## 版本自动检查整合（2026-11-09，实施中）

本项目使用 `.agents/skills/` 中的完整本地副本，来源与初始哈希见 `.agents/skills/copy-manifest.json`；不修改或运行时隐式覆盖个人全局 Skill。副本保留依赖文件的原名，不作为部门 Python 模块导入。部门业务代码仍放 `QA_*.py`。

当前已验证：源码文件删除由受限读取返回证据缺口，不再泄漏 FileNotFoundError 导致整批失败；单次 SourceCatalog 的有界缓存复用未变化文件，逐次检查路径、大小与文件元数据。缓存不替代执行前后的完整基线验证，不代表已经减少模型调用。

静态审查同轮多个搜索词合并为一次项目文件遍历；重复且完全相同的搜索结果只在模型输入中发送一次，完整请求仍保存在本地审查轨迹中。发生变化的搜索结果保留，源码引用及基线校验不变。该优化不减少模型轮次，也不解决需求、目录和已读源码在各轮重复传输；真实任务的整体提速尚未验证。正在运行的服务需任务停止后重启才能加载新代码。

项目文件盘点和搜索在开始、结束以及扫描期间约每 0.25 秒检查取消、权限和任务修订，避免每个文件都触发数据库查询；具体响应还受单文件读取和系统调度耗时影响。来源路径仍逐次检查，运行结束仍校验代码基线。此优化不改变模型调用和断言门禁。

### 本地版本编排器

`QA_release_orchestrator.QA_run_release_pipeline` 提供只读、可恢复的本地协调执行：冻结 profile 后运行 SDK/server 静态检查和 GagaSort 项目盘点，分别保存阶段状态、尝试次数和原始证据，并生成统一 `report.json`。重复运行必须显式传 `resume=True`，且会校验 profile 哈希；不会执行 Git、Unity、构建、真实支付、设备安装、平台入库或外部提单。报告中的支付、埋点、广告、安装四项固定为 `unverified`，不能当作版本通过。工作台要接入一键启动，仍需平台维护者提供授权后的 start/resume/run-state 公共契约，本部门不修改公共队列或 HTTP 壳。

当前可直接运行项目入口 `python3 tools/run-release-pipeline.py`；默认报告写入 `data/release-runs/<时间戳>/`，已有批次只能显式使用 `--resume`。它是工作台接入前的真实本地入口，不代表四项运行时验证已经自动化。

模块证据复用：仅对显式相同 `module` 的用例共享已读取源码片段（每模块最多120KB、最多16模块），每次复用先校验实际内容哈希；不共享模型结论，每个用例仍经独立断言和引用校验。未提供模块时不猜归属。专项测试：`python3 -m unittest tests.test_QA_shared_evidence tests.test_QA_source_cache`。

公共契约缺口及最小接口提案（待平台维护者审核）：现有测试任务只持久化单客户端 binding；四库 profile、每阶段工具许可、冻结的本地 Skill 包哈希及协调执行状态没有公开保存/排队接口。建议由平台提供授权后的 release profile 读写、freeze/start/cancel/resume 和 run-state 回调；每次推进重新验证任务修订、执行者权限、来源与基线，重启后恢复需校验原委托有效性。部门只接收快照和持久化/调度回调，不读核心数据库、不新增私有路由、不修改公共队列。报告返回结构保留原逐用例 results/assertions，新增独立跨库及运行验证结果；外部发布沿用原人工确认门禁。

生成性能缺口：当前公共分批器每 1000 字执行设计和完整重写审计，历史记录 69 块对应 138 次计划调用。需平台维护者评审模块化分块与增量审计契约，不能仅更换模型传输后宣称提速。

维护本目录的 manifest.json、skills/ 和本部门实现。公共登录、权限、数据库、队列不得在本目录绕过。

节点标识 `testing:0` 等保持稳定；调整顺序或删除节点需要迁移方案。执行器通过公共注册接口接入，未接通的自动能力保持人工模式。测试模块复用原六节点，不复制执行链路。

## 静态审查恢复与交付关联

静态执行及回归默认每个任务最多三条独立用例并发，可通过启动环境 `TESTFLOW_STATIC_WORKERS=1` 退回串行；只接受 1–3，非法值报错。`QA_review_pool.py` 只管理有限提交与上下文复制，通过兼容入口注入取消检查/作用域，不依赖平台私有模块。结果仍按输入顺序输出；失败停止派发并协作取消在途请求，已完成检查点保留。完成数是任务总进度，用例 ID 是最新更新的用例，不代表只有一个在途请求。此限制为每任务上限，并非服务器全局配额；实际速度取决于模型服务与限流，不承诺三倍加速。旧进程需在任务空闲后重启才会加载新实现。

并发专项：`python3 -m unittest tests.test_QA_review_concurrency tests.test_QA_review_checkpoints`。用 Barrier/Event 验证真实线程调度、乱序汇总、上下文与取消、失败停止派发、串并行规范结果一致和断点重用；模型传输与 Git 基线使用显式替身，不能当作真实模型吞吐验收。

`QA_review_checkpoints.py` 仅管理测试用例的可丢弃检查点，通过 `QA_checkpoint_scope(folder)` 注入目录，不读取数据库、不授予权限。公共队列按任务和重置代次提供目录，`server/static_review.py` 负责签名、取消检查、真实源码引用校验及完整报告门禁。复用以需求、单条用例、Skill、模型连接与完整代码基线一致为条件；中断后的继续需要用户重新执行。代码变化保守重新审查，不能称作已支持跨版本的精准影响分析。

旧测试页面通过 `web/workflow-insights.js` 的 `QA_*` 只读视图函数展示当前授权响应中的真实关联，不能据此读取被过滤的来源、Skill 或其他节点。通用 Skill 规则检查由平台提供，不是测试执行器，关键词命中不代表样本质量评测。

专项检查：`python3 -m unittest tests.test_QA_review_checkpoints tests.test_job_telemetry`、`node --test tests/workflow-insights.test.js` 和 `node tests/browser/workflow-insights.cjs`。浏览器脚本使用临时数据库与明确隔离样例，不连接真实模型或飞书。

交付前运行 `python3 tools/check_department_boundaries.py --department testing`、`python3 -m unittest tests.test_case_validation tests.test_generation tests.test_static_review tests.test_execution tests.test_attribution tests.test_triage tests.test_bugs tests.test_regression tests.test_node_settings tests.test_node_reset tests.test_workflow_e2e` 和 `node --test tests/*.test.js`。该静态命名/依赖检查只覆盖 `departments/testing/`，存量兼容文件依赖由业务回归和评审检查；没有把旧目录检查冒充全面架构隔离。

## 生成校验恢复接线（2026-10-22）

补充平台接口缺口：模型传输层只对已明确完成的响应解析 JSON，通过公共 `ModelOutputError` 区分输出格式问题与传输/认证失败，携带不进入公开日志的原始候选。分批器将异常类型注入测试校正助手，不让部门模块依赖平台私有实现。格式与业务校验共用每阶段最多三次的总预算；仅允许去除完整单个 Markdown JSON 围栏，不猜测补标点、不拼接截断结果、不放宽引用校验。Responses、Chat 和 CLI 使用相同解析协议；未完成响应仍拒绝保存。

同一格式协议覆盖静态审查（执行及回归）和归因：静态审查沿用八轮探索上限，格式错误作为协议反馈继续，耗尽仍是证据不足；归因格式及证据校验共用三次预算，不能自动确认根因。静态 trace 的未解析响应和归因拒绝候选只留服务器本地证据，不进入公开进度。损坏的生成缓存只重做当前阶段，新检查点使用原子 0600 写入，不更改有效缓存签名。公共 HTTP reader 收到明确终态即结束读取，不等待长连接 EOF；没有终态不能提前接受流式片段。

进度接口缺口：公共 JobTelemetry 原来只在用例 ID 切换时清除请求诊断，分批生成的 batch/phase 切换会残留另一请求的耗时、错误和字节数。最小补充为切换批次或阶段时同样清除请求局部字段，保留任务总进度、模型选择和启动时间；这是并发请求的最新更新视图，不冒充全部在途请求列表。

本机故障诊断缺口：旧队列将权限错误转成字符串、内部异常转成通用消息后丢失调用栈。平台队列对这两类故障在服务器本地日志保存任务编号和异常栈，公开响应不增加栈或请求内容；常规模型业务校验不记录原始候选。权限错误不盲目自动重试、不绕过系统权限。

公共缺口：分批生成器遇到单次 JSON 业务校验错误会终止全部批次，没有向模型反馈校验错误的机会。最小接口是由 `server/generation_batches.py` 将当前阶段的请求、原有严格校验、取消检查和诊断回调传给纯测试业务助手 `QA_generation_recovery.py`。助手只对已收到的候选结果做最多两次校正请求；传输/认证失败仍由模型连接器处理，不能混作业务校验重试。检查点签名和有效缓存格式不变，既有有效阶段可继续复用；失败候选仅保存到服务器本地 0600 诊断文件，不作为产物、公开日志或成功检查点。

## 待确认与自动推进契约缺口（2026-11-10）

用户希望范围风险默认仅展示、无需逐项确认即可继续。现有公共全自动服务只有在批次明确启用全自动时才自动保留范围风险并推进；手动模式仍由平台决策接口要求保存范围评审，默认新批次未启用全自动。建议平台维护者提供项目/批次级默认自动决策配置与可审计的授权契约，在创建批次时应用且可关闭，并保留权限、证据、飞书人工发布和用户已有明确要求补充资料的决策；不要由前端绕过服务端审核或静默改写历史批次。当前界面明确提示两种模式的实际行为。

## 公共接口提案：选择执行仓库目录

测试执行节点需要选择运行静态检测的机器上的 Git 仓库目录并填入 `execution-path`。浏览器文件/文件夹选择器不会提供本机绝对路径，现有部门契约和 Codex 桥接也没有目录选择能力，不能用文件名冒充绝对路径。

建议由平台维护者提供受控目录选择契约：针对本机部署，通过本机桥接打开系统目录选择器，用户确认后返回所选绝对路径；远程访问时明确选择的是执行机器可访问的仓库，不能把浏览器所在机器的路径当作服务端路径。请求应绑定当前用户、项目和测试节点权限，取消选择不改变当前输入；路径须经平台现有项目仓库授权与绑定检查，选择本身不读取、上传或修改仓库，也不自动启动检测。平台审核并提供接口后，测试部门再接入按钮和取消、错误、权限及跨机器场景测试。

取消后恢复契约缺口：现有取消将整个批次设为 `cancelled`，只能通过节点重置重新开放；重置会归档当前及后续产物并更换检查点代次，不能复用取消前的逐条检查点。建议平台提供显式恢复已取消批次的接口：检查项目和当前节点权限、任务修订、后台任务已停止及前置产物，保留产物与检查点代次，记录审计事件并仅将状态恢复为待操作；不自动运行或修改飞书。并发请求与重置必须互斥，后续执行仍校验完整基线及检查点签名。

补充用户需求：取消运行应终止当前后台 job，而不取消测试批次；工作线程确认停止前继续禁止重复排队，停止后保持节点、用例、绑定与有效检查点，并允许重新执行。确认节点仍须满足该节点原有的产物和证据门禁，不能因取消而直接放行。平台需提供按 job ID 和修订检查的取消接口、可观察的取消中/已停止状态及审计，并确保在途结果不能提交；对于旧版已标记 cancelled 的批次，通过上述显式恢复接口处理。保留已有批次取消语义，不能直接重定义持久化状态。需覆盖并发取消、排队任务、线程停止、旧批次恢复和检查点签名变化。

## 公共接口提案：全工作台统一运行进度抽屉

现有用例生成抽屉由 `web/focus-workspace.js` 直接实现，限定 `testing:0` 和 `generate`；它不是部门可扩展契约。其他测试节点、部门节点和自定义流程分别使用测试任务、部门任务与工作流运行记录，状态和进度字段不同，不能把生成用例的阶段与百分比套用到其他任务。

建议平台维护者提供共享进度抽屉组件及受权限保护的统一只读运行快照：以项目、运行 ID、节点 ID 与执行类型定位，提供排队/运行/完成/失败/中断状态、已知时间、真实阶段、可用的计数、错误和可观察事件；缺少计数时显示“处理中”，不编造百分比。部门通过公共接口提交/订阅快照，用户主动启动成功后自动打开，自动推进的任务提供查看入口；刷新或切换节点可重新打开，关闭不停止任务。终止能力需按现有权限和各执行器实际取消语义分别实现，不能把“终止整个测试批次”伪装为仅取消当前节点。抽屉需支持关闭动画、遮罩/ESC、焦点恢复和移动端。

验收应覆盖测试静态执行、归因、回归、各部门执行器和自定义流程：开始/排队/成功/失败/中断、无进度字段、不同节点切换、刷新恢复、授权撤回和真实取消边界。部门在契约落地后接入本部门节点，不修改 `web/studio.js`、公共工作流或队列私有实现。
