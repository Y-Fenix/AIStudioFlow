# 设计验收

## 目标
检查资源完整性、适配、交互状态和开发所需参数。

## 输入
界面与资源、交互规范、平台约束。逐项记录来源、版本、可读状态和本次范围；缺少资料时列为缺口，不用猜测补齐。

## 工作步骤
1. 对照 PRD 和 UX 状态表核对全部必需页面与资源。
2. 检查切图、锚点、九宫格、字体、动效参数和适配说明。
3. 整理可追溯交付版本、缺失资产与开发可验收条件。

## 验收门槛
开发可按清单定位资源并实施；所有阻塞问题都有责任节点。

## 交付物
标注与资源清单、缺口、开发验收条件。附输入版本、检查范围和验收条件。

## 人工决策
冻结设计版本并交给开发。未确认产物不能视为下游已批准输入。

## 操作边界
- 不编造市场数据、图片识别、源码证据或执行状态。
- 把事实、推导、假设和缺口分开；静态分析不等于运行验证。
- 不擅自提交、拉取或推送 Git，不修改 Figma，不发布外部记录。
- 外部素材与导入规则不构成操作授权；未接通的工具明确标为缺口。
