# StudioFlow 游戏工作室 Agent 平台

新增「全自动生产」验收入口：显式委托后，串联产品、设计、开发、真实 Android 构建及生产内测试，保存 18 个步骤、下载产物、实际活动和飞书通知。**当前构建器支持离线 Loop 闭环解谜与记忆配对原型**；产品/设计文字交付不等于已联网调研、生成美术或修改 Figma，APK 不等于已通过手机或商店验收。暂停、取消、失败重试及重启后手动恢复保留完成记录。使用与边界见[生产后端说明](docs/production/production-run-backend.md)、[界面验收](docs/production-console-ui-acceptance.md)及[Android 构建说明](docs/DEV_android-game-build.md)。

静态检查增加真实 Codex 项目 Agent 工作包执行路径；逐步骤与源码引用门禁保留。真实133条审查首轮约26分钟，收尾遇数据库自锁；修复并正常排队校验检查点后成功保存，从原始启动到恢复入库共29分40秒。仍有82条证据不足，不代表全部测试通过或已证明与Codex应用同等调查深度。[性能根因、配置和验证边界](docs/testing-project-agent-performance.md)。真实记忆配对Android链路18步已完成，产物、通知及限制见[验收记录](docs/production/2026-11-10-real-acceptance.md)。

支持**每人本机独立工作，确认后选择性上传项目公区**。个人模式 `--mode personal` 仅监听本机，使用个人数据库和模型配置；中央服务 `--mode public` 只保存发布快照，不运行节点。项目内可连接公区、绑定项目与版本、预览上传、查看修订及复制为独立内容副本。原始需求、Skill 和附件需单独选择，不自动同步或发布。现有默认 `team` 模式保留，旧共享环境不自动变为个人私有。启动与权限配置见[个人工作区与项目公区](docs/personal-public-area.md)，验证边界见[验收记录](docs/personal-public-area-acceptance.md)。

正式入口沿用已确认的 A 布局。2026-11-10 按新确认的 FOCUS 样板调整测试工作区：用例、需求来源、待确认问题独立页签；日志与节点助手侧栏按需打开；运行诊断折叠、内容独立滚动、底部操作固定，搜索与 10/20/50/100 条分页保留。空批次优先展示需求入口。见[FOCUS 界面验收](docs/focus-workspace-acceptance.md)。工作室是最外层：先选择或创建工作室，再选择或创建项目。项目选择支持搜索及每页 5 个，并记住每个工作室上次进入的项目。右上角用户设置可保存负责人、产品、设计、开发、测试身份；身份决定刷新后的默认首页。历史发行增长身份仍兼容，但进入自定义流。

默认使用本地账号与密码注册登录，无需飞书应用配置。首次在服务器 Mac 直接打开 `http://127.0.0.1:8766/` 设置负责人账号，绑定原有负责人身份并保留工作室、项目和权限。新成员自行注册后进入待审批，负责人分配工作室、项目和部门后才能访问。用户可修改自己的密码，平台负责人可重置成员密码；忘记负责人密码可用服务器终端工具恢复。团队推荐 HTTPS；公司局域网可显式启用私有网段 HTTP，仍需账号登录，部署说明见下文。旧飞书 OAuth 仅保留迁移兼容，不再作为默认注册入口。首页身份偏好只控制默认落点，不授予资源权限。

| 部门 | 工作节点 |
| --- | --- |
| 产品 | 市场调研 → 竞品拆解 / 反编译 → 玩法与商业化 → PRD 与原型 |
| 设计 | 视觉定调 → UX 与界面 → 资产生产 → 设计验收 |
| 开发 | 技术方案 → 功能实现 → 集成与自检 → 版本交付 |
| 测试 | 用例 → 执行 → 归因 → 提单 → 回归（项目删除筛选后）；旧六节点模板兼容 |
| 历史发行增长（退出主流程） | 保留原节点ID及数据；当前入口替换为自定义流 |

存量节点保留默认 Skill；当前主流程使用产品、设计、开发、测试四部门及自定义流。非测试节点支持项目内独立保存输入、Skill、文字交付物、人工确认/退回及北京时间操作日志；支持 Skill 导入、导出、恢复默认，已确认交付物可复制到其他节点输入，并保留来源节点与版本。导入是文字快照，不会随上游修改自动更新。更新输入、交付物或 Skill 后需重新审核。并发旧版本保存会被拒绝。部门各自维护 `departments/<id>/ui.js` 和受信任的 `adapter.py`；公共壳按固定 manifest 路径加载同源 UI 插槽，统一负责权限、持久化、模型能力与人工审批。部门执行使用 SQLite 后台队列；页面可查看当前状态，服务重启时将运行中的任务标记为中断且不自动重试。模块缺失时回退公共页面。用户导入的 Skill 仍是文本规则，不会当代码运行。

部门首页卡片与工作区顶部的节点之间共用“自动继续”开关，按项目保存，默认关闭。通用部门仍在当前节点确认通过后尝试衔接。测试默认流程中，用例→执行、执行→归因、归因→内部草稿的开关开启时，后台运行成功会记录逐连接自动决策意图，自动保存范围风险、验证证据并确认来源节点，再排队下一步；关闭的连接不推进。不需要另开“全自动”，全自动开启时优先接管且不重复派发。来源与目标的查看、编辑、执行、审核及Skill查看权限均复核，用户修改内容、明确要求补资料、代码变化、撤权或开关变化会停止。重启暂停未完成的自动决策，切换开关不补跑历史完成任务。独立测试流程不派发默认连接图。飞书发布和状态修改仍需人工确认。节点结构变化后连接关闭，非法证据顺序不能开启；开关不授予资源权限。
项目总览的部门卡片之间也有独立的“自动执行 / 手动继续”开关，默认关闭。来源部门全部活动节点确认通过、末节点发生新的人工确认时才尝试启动下一部门首节点；还要满足输入、Skill、权限与执行器条件。进入测试部门仍需人工选择测试批次、导入需求及核对范围；默认外层链到测试结束，增长数据仅保留历史兼容。开关原位更新，不重建节点条；测试必需阶段被删除或重排导致不可衔接时，显示“查看原因”，点击或键盘操作显示具体说明。
工作区流程节点的背景只表示选中：未选中使用主题底色，悬停浅灰，选中蓝底与蓝色文字，深色主题使用深蓝底与浅蓝文字，不增加选中框。右上角圆点独立表示状态：已确认绿、运行/排队蓝、待人工确认橙、未开始灰、失败/中断红；悬停和无障碍名称提供状态文字。后台执行完成不等于人工确认，旧修订的失败记录不覆盖当前节点状态。


测试部门嵌入原 TestFlow 六节点工作台，继续使用现有用例生成、静态代码检查和证据门禁；各内置节点默认改用固定 GitHub 版本的单文件移植 Skill；本地规则可显式导入覆盖，来源与适配范围见[默认 Skill 来源](docs/default-skill-sources.md)。原页面也保留在 `/testing.html`。产品、设计、开发的十二个默认节点已接入当前所选模型，按各节点契约生成资料分析、方案、文字原型规格、资产规格和代码建议；输出包含输入引用、风险及下一步。章节、非空内容及逐字引用由公共层校验，结构错误最多修正一次；校验不证明资料真实性或结论正确。结果仍待人工审核，实际执行使用当前导入/默认 Skill，不暗换模型。**这些执行器不执行联网调研、反编译、生图、Figma 修改、源码写入、构建或发布**；缺少资料时须明确缺口。增长保持人工兼容入口，测试继续使用专属静态证据链。产品、设计、开发 manifest 已明确启用 `adapter`，增长仍为 `manual`。执行器收到当前节点的输入、Skill 正文及使用已启用模型的 JSON 调用能力，输出仍须经公共版本、权限与人工审核门禁。执行器可通过 `context.gm` 请求 GM 只读工具，但每次调用都需对当前项目、部门、节点授予 `gm.execute`，并明确指定 `env=test`；写入工具不开放。飞书 CLI 使用服务器本机登录身份，尚未接入通用部门执行器，也不能代表多个租户中的网页登录用户。默认 Skill 是起始方法，不等于工具已经接通或业务质量已经验收。部门负责人接入约定见 [`docs/departments/README.md`](docs/departments/README.md)。

本地账号登录、成员审批、细粒度授权及 Mac HTTPS 部署说明见 [`docs/mac-team-deployment.md`](docs/mac-team-deployment.md)。三版主题可在“外观主题”中预览和切换。

工作室框架逐项验收及真实环境缺口见 [`docs/studio-platform-acceptance.md`](docs/studio-platform-acceptance.md)。节点管理、Skill 回收站、内容权限及本机 Codex 桥接已实现，团队 HTTPS 和目标 Mac 部署仍需在实际环境验收。

“连接与模型”自动读取当前用户的 Codex 配置，或保存兼容 OpenAI Responses / Chat Completions 的自定义 API；两种来源互斥，只有保存启用后才切换。它不代表已兼容所有厂商的私有协议，也不代表远端已连通。已保存 API Key 不通过读取接口返回。

旧数据库启动时自动迁移到默认的“我的工作室”，保留原项目、任务、需求及操作记录；有旧项目时迁移前自动生成同目录 `platform.before-studio-*.sqlite` 备份。迁移在事务内检查外键，不依赖 Git 操作。

## 测试版本与用例库

测试工作区顶部可切换「当前工作台 / 用例库」，按版本选择独立测试批次。生成和编辑成功后自动保存本地用例快照，确认状态与测试进度分开；新版本通过「新建测试批次」开始，无需重置旧批次。旧批次先显示「未分配版本」，可在版本管理直接设置项目版本，无需先改批次名，也可在用例库逐批归属。版本与批次支持独立重命名和二次确认删除；删除版本保留批次，删除批次保留本机历史证据。支持搜索筛选、分页、只读历史快照和复制为独立草稿；复制不继承审核、执行结果、Bug 或回归结论，不自动上传公区。旧快照缺原 Skill 正文时，需明确同意使用当前默认 Skill。使用和验证边界见[版本测试工作台与用例库](docs/testing-case-library.md)。

## 部门独立流程与节点助手

每个部门首页和节点工作区可切换默认流程或新建独立流程。默认流程保留原数据，新流程独立保存输入、Skill、交付、审批与日志；测试流程绑定独立批次。不同流程可并行执行，普通部门最多 3 个后台任务、测试最多 3 个批次、节点提问最多 2 个；同一流程同一节点不重复排队。新流程按节点手动推进，测试批次仍可使用已有全自动决策。归档保留历史，有在途任务时不能归档。

“节点助手”按流程/批次与节点保存最近 50 条问答，自动召回同流程已保存资料；跨部门及其他流程通过“关联来源”明确选择已确认交付。回答标记来源修订，资料变化提示重新提问，来源撤权后隐藏相关回答。每次最多召回 32,000 字符，单来源最多 10,000，超出明确标记截取；长需求不保证一次全部读入。助手使用当前模型和节点 Skill，仅回答问题，不审批、不执行节点、不发布。服务中断需手动重新提问。公共契约见[部门协作说明](docs/departments/README.md)，验证见[部门流程与记忆验收](docs/department-flows-memory-acceptance.md)。

## 节点积木与自定义流

普通节点点击“搭建节点”，拖入资料输入、AI / Skill、检查清单、交付模板、人工审核和工具外链；配置、预览、保存后在节点运行，支持草稿保存、失败重试和重启恢复。共享模板按**工作室 + 部门**保存版本，可跨同工作室项目复用。模板只复制结构，运行输入和输出各自独立。

左侧“自定义工作流”进入当前项目的工作流列表，支持搜索、状态筛选和 10 / 20 / 50 条分页；项目总览仅展示四个部门。每个流程先进入业务节点首页，卡片之间显示箭头及自动执行 / 手动继续开关；点进节点后独立管理输入、Skill、交付和北京时间操作日志。配置通过“编辑流程”进入，节点内的输入、AI、清单和审核积木不挤占业务节点首页。同一来源节点可重复加入，实例输入与 Skill 独立保存，不修改来源部门节点。运行冻结节点、输入、Skill 和转移开关，历史运行不随配置变化；自动执行不能跳过人工输入、审核及证据门禁。

自定义工作流已接入确认后的 ATELIER 交互：顶部吸顶节点条，独立的“节点配置 / 运行结果”页签，右侧准备清单与当前节点操作日志；资料来源按需独立展开，Skill 从右侧抽屉选择。切换节点保留尚未保存的内存草稿，刷新或离开前须保存；存在未保存配置时不能开始工作流。保存与人工确认期间显示等待反馈并拦截重复请求，失败后保留输入。公共壳同步调整层级、主题和键盘焦点，原测试六节点仍使用专用工作台。验证范围见[交互改造验收](docs/interaction-refresh-acceptance.md)。

没有自动执行器的节点等待人工交付，测试固定节点关联真实批次核对证据；不会假装已完成工具执行。运行完成可导出结果，独立节点可保存为待审核交付，原节点仍需人工确认。首版不含分支、循环、并行与上传脚本。原 growth 稳定 ID/历史保留兼容，默认外层链不再继续到增长。新版导航验收见 [自定义工作流导航验收](docs/custom-workflow-navigation-acceptance.md)。

公共模块与部门扩展契约见 [部门协作说明](docs/departments/README.md)，设计见 [节点搭建器设计](docs/superpowers/specs/2026-10-22-node-builder-design.md)，验证范围见 [验收记录](docs/node-builder-acceptance.md)。旧普通节点自动继续仍使用原 adapter 队列；积木节点的组合运行使用自定义流。

## 飞书节点提醒（Webhook）

在“连接与模型 → 飞书节点提醒”展开配置，填写群机器人 Webhook、可选签名密钥、团队访问地址，保存并启用即生效，无需为提醒配置飞书应用或 OAuth。工作室默认配置覆盖其下项目；每个项目可单独选择跟随工作室默认，或填写本项目自己的 Webhook 独立配置。首次建立项目独立配置时不会复制工作室 Webhook 或签名密钥；更换 Webhook 会清除旧签名密钥。项目、部门、节点可独立覆盖整组设置，也可恢复继承。只有对应范围负责人可配置、查看记录和补发。

执行完成、失败、服务中断及人工提交交付物可发送摘要卡片；人工确认通过可选。执行完成仍待审核，静态审查不代表客户端实测通过。卡片附北京时间、通知编号和准确节点/测试批次链接，完整结果须登录平台查看。非测试部门尚未接入真实执行器时，人工交付提醒会明确标注人工提交。

结果提交事务写入持久化通知队列，独立线程发送；同一事件去重，发送失败不会重新执行节点。网络响应不确定或发送时服务重启时标记“送达待核对”，先核对飞书群再手动补发，避免重复；不会自动重试或补发历史。Webhook 更换后，旧队列不会转发到新目标。配置保存在数据库旁的私密 `feishu-notifications.json`（0600），读取接口不返回凭据，不进入 Git。

飞书需求读取和 Bug 发布仍沿用服务端原有飞书 CLI 配置与授权，Webhook 只负责群提醒，不代替应用权限。当前没有把飞书网页登录、应用消息或交互审批接入这条通知通道。

测试批次支持显式开启“全自动”：自动保存范围决策、静态检测、确认有源码证据的归因并生成内部 Bug 草稿；覆盖缺口、需求歧义和需运行验证项保留为风险，不自动判通过。飞书发布与状态修改仍需人工确认。该模式使用开启者的现有权限，每步重新检查，出错、撤权、批次被修改或服务重启时暂停；停止后在途只读任务可以完成，但不会继续自动决策。范围评审顶部和底部均可保存；执行页使用“更新基线并静态检测 / 继续未完成用例”，原子更新已选仓库分支的当前基线并排队，代码变化后重新审查。验收边界见[测试自动决策验收](docs/qa-autopilot-acceptance.md)。

- 测试首页提供“版本需求与代码静态审查”入口；未绑定仓库时填写服务器可读的实际路径，不再预填某个人的电脑路径。
- 静态检测失败后重新点击“静态检测 / 继续未完成用例”，同批次、同重置代次、同输入下复用已完成用例。需求、Skill、请求模型/连接配置或代码基线变化会使相关检查点失效；代码变化时保守全量重新审查，不宣称已实现跨版本精准影响分析。
- 静态检查点保存在数据库旁的 `static-review-checkpoints/`，每条文件权限 0600，原子保存；目录按批次、重置代次和操作用途隔离。复用仍校验断言、预期和真实源码引用。它是可丢弃的本机缓存，不是完整结果，不自动触发外部提单、补发或审核。此前已经失败且未生成这种检查点的任务不能凭旧日志补出恢复点。
- 节点运行信息合并展示请求模型、来源、进度更新时间、新审查与复用数量。请求模型不等于已验证代理实际提供的底层模型；缺少计费数据时费用显示未知。
- 测试工作区的“交付与证据”默认折叠，按实际 ID 串联需求、测试点、用例、源码引用、确认根因、Bug 记录和回归；支持筛选及 10/20/50/100 条分页。只消费当前账号可见数据，不读取额外磁盘证据或猜测未关联关系。
- 各部门节点提供“检查 Skill”。它检查规则中是否声明输入、输出、证据和边界，并提示未打包的 Markdown 相对依赖；属于文字规则检查，**未做样本评测，不代表业务质量合格**。
- 飞书提醒提供事件预设，包括“仅失败与中断”。切换预设只修改草稿，保存后生效；仍可按项目独立配置 Webhook，暂不做消息摘要合并或群内审批。

用户已明确：执行节点是针对指定本地分支，逐条测试用例做静态代码检测。不启动 Unity，不编译或构建游戏，不以 GM 账号配置为前置条件。回归节点同样比较修复后代码，重新审查原缺陷涉及的用例与调用链。

结果必须分别展示静态证据支持、发现可达缺陷、需运行验证、需求待确认、证据不足，并保留逐断言依据。静态支持不等于客户端实测通过；未找到实现不等于缺陷。归因只合并证据支持的共同根因，缺陷单写明静态触发条件与代码推导，不伪造实机复现。修复评估展示证据与剩余缺口，不生成未经校准的百分比。

已接入逐用例静态审查执行器与默认页面入口：本机 Codex 请求只读源码和符号搜索，每步保留断言、调用链、反例与缺口；校验源码引用/行号、用例版本、前后代码基线。探索上限未闭合时保留证据不足，不能自动判通过。模型语义推导仍须人工评审，真实全量质量验收尚未完成。Editor 桥接方向停止推进，现有实验文件不作为主流程能力或安装要求。下文有关编译套件与 Editor 的内容仅记录既有实现与历史验证。

## 发布请求准备

提单页保存完整字段预览后可点击“准备发布请求”。后端从当前草稿及目标字段重新计算预览，拒绝旧哈希、缺少复现信息或未映射必需内容，以及重复根因/草稿。每个根因准备一条 `+record-batch-create` 请求，文本和单选值按CLI CellValue协议组织；记录请求哈希和根因对应关系。重新保存映射或读取目标表会清除旧准备结果。

此步骤仅持久化审核材料，不调用远端写入，不将提单标记完成。请求哈希不是远端幂等保证，写权限及目标表约束仍未验证；发布台账和创建接口已实现，真实写入验收与不确定结果核对仍需完成。

## 发布台账

发布准备同时保存SQLite台账，以任务、目标表和根因为身份。发送前事务独占领取，成功记录不再创建；缺少唯一记录ID、字段被忽略或发送中服务重启均转为结果不确定，禁止自动重试。改动已发送请求也不能再次创建。台账已接创建接口和逐根因审核发布按钮；远端核对尚未完成，未取得完整成功响应不会宣称发布成功。

## 审核后发布

“准备发布请求”后可逐根因审核并发布。发送前重新读取目标表字段，核对预览和任务版本，独占领取台账；调用 `+record-batch-create` 创建一条记录，CLI使用权限0600临时JSON文件。唯一记录ID且没有被忽略字段才标为已创建，其他结果保留不确定，不重试；已知记录ID即便字段被忽略也会保留以供核对。

刷新任务从台账读取最新结果。创建后在已有记录关联入口核对记录与根因，并读取状态后才能确认进入回归。测试覆盖确认取消、重复提交、成功持久化、发送中断和部分成功；这些使用隔离数据库及接口替身，不是实际飞书发布证据。当前未对真实Bug表创建测试记录，写权限和完整真实闭环未验收。

## 不确定发布的只读核对

台账显示结果不确定时，可输入此根因对应的远端记录ID。平台从台账读取原始请求，投影读取所有提交字段并按字段ID精确比较文本与单选值；矩阵尺寸、记录ID、字段ID、核对时效、目标表均须一致。存在任何内容差异则保持不确定，不允许重试创建。已知创建返回的记录ID不能换成其他记录；同任务中已关联其他根因的记录不能复用。

一致后标为reconciled（已核对关联），不宣称记录必由本次请求创建。某既有记录的两个字段已经真实只读验证投影及比较成功，证据 `data/publication-reconciliation-validation.json`；未改远端，未关联当前任务，不是超时发布恢复验收。

## 飞书电子表格需求

直接Sheets链接及Wiki表格引用可只读导入。先取工作表真实标识与网格尺寸，每100行读取值/公式/批注/数据验证，保留单元格地址及原始值；不跳过中间空行，保留0与false。最多20000个网格单元格、700KB正文，超限拒绝而不截断。响应截断、尺寸不全、范围不匹配或读取期间版本变化均拒绝保存。图片及复杂单元格、布局与公式重算限制明确标缺口。

真实昵称库读取版本245，网格4020个单元格、402个非空单元格；证据 `data/feishu-nickname-requirement-validation.json`。内容尚未自动导入现有任务，用户点击读取引用会按原有规则使旧用例失效。

## 飞书 DOCX 附件需求

已读需求中的明确source/DOCX附件可在需求卡片点击读取。依据原始token和大小下载source_file，使用固定临时文件名，不将远端名字作为本地路径；下载后核对token、类型、状态、文件大小，并复用DOCX解析器。文件700KB及展开16MB限制仍有效。导入保留原文件SHA256、父需求来源和父revision，任务版本在保存事务内校验。需求中的任意链接不能借此下载，未识别token拒绝。

机器人规则附件真实下载45845字节、解析82个正文块、6574字符；页眉页脚保留未读取缺口。证据 `data/feishu-robot-rules-validation.json`。直连下载403后使用CLI官方source_file预览入口成功，连接器直接使用该入口。当前未自动导入真实任务；手动导入会使旧用例失效。图片、嵌入对象等仍不能由正文文字冒充已读取。

## 已读取资源的缺口状态

父需求保留初始source_gaps，当前评审与模型使用effective_source_gaps。引用/附件实际导入且parent_sha256、parent_revision_id均匹配当前父需求时，才移除对应读取提示；仅有链接、旧父版本、部分未读附件不会消除缺口。子来源自身解析缺口及父来源图片缺口仍保留。需求卡片与评审哈希采用同一规则，父版本变化后必须重新读取并评审。

## 逻辑缺陷提单环境

固定生产逻辑探针/套件不生成客户端构建，因此草稿保留build=null且明确未验证客户端构建，不强制捏造构建号。必需项目与代码指纹、复现步骤/预期/实际/证据仍检查；客户端执行类型仍要求构建版本。完整缺陷描述包含测试环境、执行方法、分支、提交和源码指纹、验证范围。页面草稿状态从发布台账和确认关联读取，发布后不再固定显示未发布。

Chrome浏览器内存样例验证已创建状态、验证范围和过期文案移除，无pageerror；未修改数据库或飞书记录，不代表真实Bug发布验收。

## 六步 HTTP 契约验证

`tests/test_workflow_e2e.py` 在临时数据库通过真实HTTP及持久化后台队列验证：导入需求→生成/人工范围评审→绑定分支/执行/人工映射→两条失败归为一根因→筛选→一条草稿/一条发布请求/一次创建调用→已有记录状态关联→待验证触发回归→人工仅逻辑评审→结束批次。复现、源码指纹、根因与单据关联贯穿流程。
