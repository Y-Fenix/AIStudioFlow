# StudioFlow 游戏工作室 Agent 平台

正式入口沿用已确认的 A 布局。工作室是最外层：先选择或创建工作室，再选择或创建项目。项目选择支持搜索及每页 5 个，并记住每个工作室上次进入的项目。右上角用户设置可保存负责人、产品、设计、开发、测试、发行增长身份；身份决定刷新后的默认首页，其他部门仍可访问。

默认使用本地账号与密码注册登录，无需飞书应用配置。首次在服务器 Mac 直接打开 `http://127.0.0.1:8766/` 设置负责人账号，绑定原有负责人身份并保留工作室、项目和权限。新成员自行注册后进入待审批，负责人分配工作室、项目和部门后才能访问。用户可修改自己的密码，平台负责人可重置成员密码；忘记负责人密码可用服务器终端工具恢复。团队访问仍需 HTTPS，部署说明见下文。旧飞书 OAuth 仅保留迁移兼容，不再作为默认注册入口。首页身份偏好只控制默认落点，不授予资源权限。

| 部门 | 工作节点 |
| --- | --- |
| 产品 | 市场调研 → 竞品拆解 / 反编译 → 玩法与商业化 → PRD 与原型 |
| 设计 | 视觉定调 → UX 与界面 → 资产生产 → 设计验收 |
| 开发 | 技术方案 → 功能实现 → 集成与自检 → 版本交付 |
| 测试 | 用例 → 执行 → 归因 → 筛选 → 提单 → 回归 |
| 发行增长 | 上线准备 → 素材与投放 → 数据与运营 → 迭代决策 |

22 个节点都有默认 Skill。非测试节点支持项目内独立保存输入、Skill、文字交付物、人工确认/退回及北京时间操作日志；支持 Skill 导入、导出、恢复默认，已确认交付物可复制到其他节点输入，并保留来源节点与版本。导入是文字快照，不会随上游修改自动更新。更新输入、交付物或 Skill 后需重新审核。并发旧版本保存会被拒绝。部门各自维护 `departments/<id>/ui.js` 和受信任的 `adapter.py`；公共壳按固定 manifest 路径加载同源 UI 插槽，统一负责权限、持久化、模型能力与人工审批。部门执行使用 SQLite 后台队列；页面可查看当前状态，服务重启时将运行中的任务标记为中断且不自动重试。模块缺失时回退公共页面。用户导入的 Skill 仍是文本规则，不会当代码运行。

部门首页卡片与工作区顶部的节点之间共用“自动继续”开关，按项目保存，默认关闭。开启后仅在当前节点人工确认通过时尝试衔接：服务端重新检查权限、修订、Skill、输入和真实执行器，再排队一次。缺少条件会停止并在当前节点操作日志说明，不补跑历史、不自动审核或重试。测试仅自动衔接到静态执行和归因；筛选、提单及回归条件仍需人工处理，不自动发布 Bug 或修改飞书状态。节点结构变化后连接关闭，非法测试证据顺序不能开启。配置修改复用来源节点编辑权限，开关本身不授予执行权限。

测试部门嵌入原 TestFlow 六节点工作台，继续使用现有用例生成、静态代码检查和证据门禁；默认用例/执行 Skill 优先读取用户本地文件。原页面也保留在 `/testing.html`。非测试部门目前是持久化的人工工作区，**尚未接通自动调研、反编译、生图、代码修改或发行执行**；不把人工交付记录显示为 Agent 执行成功。各部门有独立 manifest、默认 Skill 和受信任 `adapter.py` 接口；产品、设计、开发、增长目录中的 adapter.py 目前是未接通骨架，manifest 的 `execution.adapter` 保持 `manual`，公共注册器不会误加载。部门负责人完成实现并将 manifest 明确改为 `adapter` 后，执行器才会接入。执行器收到当前节点的输入、Skill 正文及使用已启用模型的 JSON 调用能力，输出仍须经公共版本、权限与人工审核门禁。执行器可通过 `context.gm` 请求 GM 只读工具，但每次调用都需对当前项目、部门、节点授予 `gm.execute`，并明确指定 `env=test`；写入工具不开放。飞书 CLI 使用服务器本机登录身份，尚未接入通用部门执行器，也不能代表多个租户中的网页登录用户。默认 Skill 是起始方法，不等于工具已经接通或业务质量已经验收。部门负责人接入约定见 [`docs/departments/README.md`](docs/departments/README.md)。

本地账号登录、成员审批、细粒度授权及 Mac HTTPS 部署说明见 [`docs/mac-team-deployment.md`](docs/mac-team-deployment.md)。三版主题可在“外观主题”中预览和切换。

工作室框架逐项验收及真实环境缺口见 [`docs/studio-platform-acceptance.md`](docs/studio-platform-acceptance.md)。节点管理、Skill 回收站、内容权限及本机 Codex 桥接已实现，团队 HTTPS 和目标 Mac 部署仍需在实际环境验收。

“连接与模型”自动读取当前用户的 Codex 配置，或保存兼容 OpenAI Responses / Chat Completions 的自定义 API；两种来源互斥，只有保存启用后才切换。它不代表已兼容所有厂商的私有协议，也不代表远端已连通。已保存 API Key 不通过读取接口返回。

旧数据库启动时自动迁移到默认的“我的工作室”，保留原项目、任务、需求及操作记录；有旧项目时迁移前自动生成同目录 `platform.before-studio-*.sqlite` 备份。迁移在事务内检查外键，不依赖 Git 操作。

## 当前执行定位（以此为准）

用户已明确：执行节点是针对指定本地分支，逐条测试用例做静态代码检测。不启动 Unity，不编译或构建游戏，不以 GM 账号配置为前置条件。回归节点同样比较修复后代码，重新审查原缺陷涉及的用例与调用链。

结果必须分别展示静态证据支持、发现可达缺陷、需运行验证、需求待确认、证据不足，并保留逐断言依据。静态支持不等于客户端实测通过；未找到实现不等于缺陷。归因只合并证据支持的共同根因，缺陷单写明静态触发条件与代码推导，不伪造实机复现。修复评估展示证据与剩余缺口，不生成未经校准的百分比。

已接入逐用例静态审查执行器与默认页面入口：本机 Codex 请求只读源码和符号搜索，每步保留断言、调用链、反例与缺口；校验源码引用/行号、用例版本、前后代码基线。探索上限未闭合时保留证据不足，不能自动判通过。模型语义推导仍须人工评审，真实全量质量验收尚未完成。Editor 桥接方向停止推进，现有实验文件不作为主流程能力或安装要求。下文有关编译套件与 Editor 的内容仅记录既有实现与历史验证。

```sh
python3 -m server.app --port 8766
python3 -m unittest discover -s tests
node --check web/app.js
node --check web/studio.js
```

平台地址：http://127.0.0.1:8766/ 。工作室、个人首页偏好、项目、节点工作区及原测试记录保存在 `data/platform.sqlite`。原型 `prototype/index.html` 的470条重复用例只用于分页演示；`prototype/studio/` 是独立的内存界面原型，两者均不进入真实任务。

## 已实现

- 六步节点界面、吸顶流程、折叠侧栏、项目搜索与每页5项、用例分页及编辑。
- 文本、TXT/Markdown、DOCX、XLSX需求导入；文件700KB、解压16MB限制。记录真实来源和读取缺口，不执行公式或访问外部链接。
- 飞书需求只读导入及直接Wiki/Docx/Sheets引用读取；Wiki指向电子表格时自动使用表格读取入口，未读资源显示缺口。
- 复用本机Codex CLI登录生成用例；校验来源引用、重复项和已识别测试点。人工确认拆解范围、覆盖缺口和歧义后才能进入执行。
- 持久化生成、执行、归因、回归队列；过时结果拒绝保存，取消或超时清理操作进程组，服务重启不自动重试中断任务。可选HTTP模型请求只能等待超时后丢弃结果。
- GagaSort只读分支、提交和源码/文本配置指纹绑定；执行前后核对指纹。二进制资源和构建不在此指纹范围。
- 固定生产逻辑探针及连胜分组定向套件。用例需人工关联执行结果并填写依据，未关联用例不继承通过。
- 原业务探针的源码证据归因建议、人工确认根因、筛选、一因一单内部草稿、复现补充。
- 真实飞书Bug表字段读取、文本组合及单选字段映射、CSV/JSON预览导出、已有记录关联与只读状态检查。
- 手动检查关联Bug待验证状态并排队代码回归；逐根因人工评审。保存评审本身不改远端；另有明确确认后的单条状态更新入口。

## 连胜分组执行套件

首次需要独立.NET9 SDK：

```sh
python3 tools/install-dotnet9.py
```

SDK保存在本平台 `.runtimes/dotnet`，安装器校验官方来源与SHA512，不修改游戏项目。执行页可选择连胜分组套件，复用 GagaSort 已有 `tools/test-streakgroup-event.py` 和 `tools/test-streakgroup-rank-animation.py`。编译使用临时目录，平台保存日志与代码指纹。

真实验证取得领域逻辑614项断言、排名动画时序2019项断言通过。Web按2个套件统计结果，内部断言数单列；它们依赖Unity等替身，不代表2633条需求用例或客户端验证通过。非零退出且带明确Program.Check断言栈时标为断言失败，仍需人工归因；其余异常、超时或缺少通过摘要标为运行异常。连胜分组候选归因读取对应生产源码及运行器内的断言/替身，源码引用校验通过也不代表因果已确认。独立.NET故障样例验证记录见 `data/suite-classification-validation.json`，不是游戏Bug证据。

## 静态审查验证

`server/static_review.py` 为当前默认执行器，按原用例 ID 和步骤审查，不编译或启动 Unity。执行队列保存已审查数量及当前用例；报告保留模型原始输出、只读搜索/行范围、源码引用和五类结论。唯一原文匹配时由平台修正模型误报行号，并保留原报行号；原文缺失或位置有歧义时不接受确定结论。

106 项自动测试通过，其中静态六步 HTTP 契约使用明确模型/飞书替身，不能当作真实发布验收。真实 C14“冠军次数统计及重复查看”通过本机 Codex 完成单用例只读联调，仍为证据不足，不是通过或产品 Bug。初次报告见 `data/static-review-real-validation.json`；分段读取联调见 `data/static-review-windowed-validation.json`。后者模型唯一引用行号 126 被平台定位为真实 123，重校验保留两项断言、十处源码引用，见 `data/static-review-citation-revalidation.json`；这是对原输出重校验，未再次调用模型或改动原报告。

浏览器验证默认静态入口、五类统计、逐步骤证据展开及长源码不溢出面板，无页面脚本错误；报告渲染使用浏览器内存注入，未改真实任务。证据 `data/static-review-browser-validation.json`、`data/static-review-ui.png`。真实任务仍停在用例人工评审，未自动确认覆盖范围或绑定分支。CodeGraph gate: fallback - 当前没有暴露该工具。

## 真实联调证据

GagaSort“连胜分组排行”任务基于18286字符需求，通过本机Codex生成37个测试点、17条用例、9个覆盖缺口、19项待确认问题，尚未由用户确认范围。结构校验不证明业务覆盖完整。

飞书只读授权已完成，真实Bug表读取23个字段。表中没有独立标题/步骤字段，使用完整缺陷描述组合模板。真实状态选项包括 `⚠️待验证`、`✅验证通过`；记录矩阵格式已经真实联调。验证记录的状态读取只证明接口连接，不代表它关联当前任务根因。

原业务逻辑探针真实运行64项：62通过、2项断言失败；尚不能直接认定产品Bug。连胜分组验证证据见 `data/streakgroup-execution-validation.json`，飞书状态证据见 `data/feishu-status-validation.json`。部分界面在隔离数据库经过Chrome验证，不代表六步闭环验收完成。

## 发布请求准备

提单页保存完整字段预览后可点击“准备发布请求”。后端从当前草稿及目标字段重新计算预览，拒绝旧哈希、缺少复现信息或未映射必需内容，以及重复根因/草稿。每个根因准备一条 `+record-batch-create` 请求，文本和单选值按CLI CellValue协议组织；记录请求哈希和根因对应关系。重新保存映射或读取目标表会清除旧准备结果。

此步骤仅持久化审核材料，不调用远端写入，不将提单标记完成。请求哈希不是远端幂等保证，写权限及目标表约束仍未验证；发布台账和创建接口已实现，真实写入验收与不确定结果核对仍需完成。

## 发布台账

发布准备同时保存SQLite台账，以任务、目标表和根因为身份。发送前事务独占领取，成功记录不再创建；缺少唯一记录ID、字段被忽略或发送中服务重启均转为结果不确定，禁止自动重试。改动已发送请求也不能再次创建。台账已接创建接口和逐根因审核发布按钮；远端核对尚未完成，未取得完整成功响应不会宣称发布成功。

## 审核后发布

“准备发布请求”后可逐根因审核并发布。发送前重新读取目标表字段，核对预览和任务版本，独占领取台账；调用 `+record-batch-create` 创建一条记录，CLI使用权限0600临时JSON文件。唯一记录ID且没有被忽略字段才标为已创建，其他结果保留不确定，不重试；已知记录ID即便字段被忽略也会保留以供核对。

刷新任务从台账读取最新结果。创建后在已有记录关联入口核对记录与根因，并读取状态后才能确认进入回归。测试覆盖确认取消、重复提交、成功持久化、发送中断和部分成功；这些使用隔离数据库及接口替身，不是实际飞书发布证据。当前未对真实Bug表创建测试记录，写权限和完整真实闭环未验收。

## 不确定发布的只读核对

台账显示结果不确定时，可输入此根因对应的远端记录ID。平台从台账读取原始请求，投影读取所有提交字段并按字段ID精确比较文本与单选值；矩阵尺寸、记录ID、字段ID、核对时效、目标表均须一致。存在任何内容差异则保持不确定，不允许重试创建。已知创建返回的记录ID不能换成其他记录；同任务中已关联其他根因的记录不能复用。

一致后标为reconciled（已核对关联），不宣称记录必由本次请求创建。某既有记录的两个字段已经真实只读验证投影及比较成功，证据 `data/publication-reconciliation-validation.json`；未改远端，未关联当前任务，不是超时发布恢复验收。

## 飞书电子表格需求

直接Sheets链接及Wiki表格引用可只读导入。先取工作表真实标识与网格尺寸，每100行读取值/公式/批注/数据验证，保留单元格地址及原始值；不跳过中间空行，保留0与false。最多20000个网格单元格、700KB正文，超限拒绝而不截断。响应截断、尺寸不全、范围不匹配或读取期间版本变化均拒绝保存。图片及复杂单元格、布局与公式重算限制明确标缺口。

真实昵称库读取版本245，网格4020个单元格、402个非空单元格；证据 `data/feishu-nickname-requirement-validation.json`。内容尚未自动导入现有任务，用户点击读取引用会按原有规则使旧用例失效。

## 飞书 DOCX 附件需求

已读需求中的明确source/DOCX附件可在需求卡片点击读取。依据原始token和大小下载source_file，使用固定临时文件名，不将远端名字作为本地路径；下载后核对token、类型、状态、文件大小，并复用DOCX解析器。文件700KB及展开16MB限制仍有效。导入保留原文件SHA256、父需求来源和父revision，任务版本在保存事务内校验。需求中的任意链接不能借此下载，未识别token拒绝。
