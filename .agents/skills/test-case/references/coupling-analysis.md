# 代码与历史需求耦合反查

有项目代码时在覆盖模型定稿前读取。目标是发现真实影响，不是给所有模块套回归模板。

提供 SDK/服务器源码且命中支付、埋点、广告、安装链路时，追加[跨库契约](cross-repo-release.md)。共享逻辑与项目条件分支、原生回调与奖励/存档消费者一起追；只读客户端不能宣称跨库闭合。共用 profile/快照，拆清静态可证、候选本地测试和真实平台事实，断言映射进入原覆盖账本及 sidecar。

## 检索边界与基线

1. 优先复用本次会话中明确的仓库、当前需求及历史资料路径。先读项目 AGENTS.md、文档索引、已有测试入口；用 `rg --files` 枚举有关目录，再做符号/引用检索。
2. 有用户指定的本地比较基线时，可只读查看对应 diff、log、show；没有基线则按需求定位影响入口，不能自行猜“上一个提交就是本次变更”。不 fetch、pull、切换分支或修改 Git 内容。
3. 记录检查的本地 HEAD、工作区相关改动、资料版本和实际已查范围。若项目禁止 Git 读取，遵守限制，以相关文件哈希/快照记录基线，明确分支/提交未核实。未找到历史资料是检索限制，不证明没有历史规则。
4. 从已定位模块按行为传播扩展，直到契约隔离、无可达消费路径或受影响输出已承接；不固定只查一层，也不无边界遍历整个仓库。检索有未完成部分时写明确切边界，不能宣称闭合。

## 从需求名映射到真实影响

先记录需求规定的规则和不变量，再搜索同义词、入口、类型、配置键、事件和资源标识。对候选记录：

| 关系 | 必查内容 |
| --- | --- |
| 调用/公共契约 | 谁调用变更入口，返回值、异常和默认值如何被消费；调用未变化不代表行为未变化 |
| 配置/全局常量 | 哪些读者共享字段、默认值、单位、优先级、导表及缓存；一个阈值是否误作用到别的入口 |
| 状态/存档 | 谁写谁读，保存与恢复顺序、迁移、账号/活动隔离、重复操作和中断恢复 |
| 事件/回调 | 发布者、订阅者、重复/乱序/同步重入、取消和清理；追到奖励、任务、红点等实际消费 |
| 奖励/交易 | 资格、发放、核销、存档和表现边界；重复发放、部分成功及可证实的回滚要求 |
| UI/资源 | 显隐与导航状态、弹窗队列、资源绑定；逻辑条件与真实渲染分开验证 |

例如活动结束时间变更：从 eligibility 追到入口和红点、领奖资格、存档恢复、回调和埋点；只有实际存在的消费者才纳入，不凭“活动通常有排行榜”虚构模块。

## 历史资料与证据

在已知项目资料目录查旧需求、旧用例、缺陷、配置说明、相关代码注释及本地 Git 历史。能访问的本地资料自行读取；仅在关键策略确实缺失时提出精准问题。远端飞书/缺陷平台依会话授权和可用工具读取，不自动下载全知识库。

证据分开标识，可多选：

- **需求/历史契约**：带来源位置、适用版本及未被替代依据，可支持期望。
- **代码依赖**：带调用/读写链及触发条件，只证明影响关系；若检验“保持实现基线不变”，明确为特征回归，不冒充需求正确性。
- **历史缺陷**：带记录、复现条件与仍适用依据，优先承接高价值回归。
- **结构推断**：只有命名或架构猜测，先继续定位；无可达关系时排除或保留探索性风险，不自动升级必测/待确认。

## 候选准入、合并与覆盖

纳入候选要能回答：当前变更通过哪条路径影响旧功能？什么前置可达？新增哪个可观察断言？预期依据是什么？

- 规则已明确且路径可达：生成回归用例或白盒测试点。历史资料缺失不否定已证明的影响。
- 影响可达但产品策略未定义：保留已知不变量，单列具体策略问题及不同答案的影响，不用代码现状拍板。
- 同一行为已被当前用例覆盖：复用同一用例，保留所有覆盖项和历史来源映射，不复制一条“回归版”。
- 没有行为传播或被稳定契约隔离：记录排除依据。共享数据的只读消费方可能受写入方影响，不能机械排除。
- 同一根因涉及不同真实入口或状态迁移：保留独立实例，可共享步骤/夹具；不能只因 Bug 根因相同删路径。

交付时说明已查目录/基线、纳入及排除理由、尚未查到的消费链、历史资料限制。未读取的历史不能写成“无历史影响”。
