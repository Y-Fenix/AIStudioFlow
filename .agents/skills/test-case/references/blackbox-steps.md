# 可直接照做的黑盒步骤

本文件用于把用例设计转成测试人员可操作的说明，不改变需求预期或用例主表六列。以下例子是写法示例，不声明目标项目已有对应GM或保证当前存在缺陷；使用时查证实际入口、配置和对象版本，再代入本项目值。

## 六列中的写法

| 字段 | 应写内容 |
| --- | --- |
| 测试内容 | 一个可定位的自然场景名，不加用例编号 |
| 测试目的 | 本条独立验证的规则或风险，避免重复标题 |
| 前置条件 | 可执行方式、平台/包、账号和历史状态、配置、是否新号/清档、依赖工具及其是否已核实 |
| 操作步骤 | 入口、具体操作/输入、顺序、关键检查点、页面/进程是否保留、必要的复位或独立账号 |
| 期望结果 | 操作后可观察的正常结果；内部状态另标日志确认及已核实的观察入口 |
| 需求模块 | 主要需求文件，详细出处沿用覆盖核对 |

细到能完成操作即可，不机械规定步骤数量。简单点击不补冗长说明；支付、切期、恢复或乱序则不能省略对象身份和时序。普通操作/GM辅助/受控环境是复现方式，L1～L4是验证层级，二者不能互相替代。

## 示例：同订单先失败后成功

仅当已查证测试包存在相应模拟能力时，可写成：

- 前置条件：需GM/测试包辅助；独立的无成功付款历史账号；礼包已解锁，分层开关开启且配置有效。无需为此清现有账号；日志断言需可查看支付记录。GM实际入口、模式名需按目标版本填写。
- 操作步骤：打开已核实的支付模拟入口，开启模拟，选择该包实际提供的“先失败再成功”模式。将延迟设为足够处理失败提示的值，例如测试输入30秒，单位秒；此数值不是需求阈值。进入失败页购买一次复活礼包。出现失败提示后关闭提示，不再次购买、不重启；等待同一笔订单迟到成功并完成领奖。再次进入失败页检查新打开的礼包。
- 期望结果：界面可验——奖励只出现一次，重新打开的礼包符合当前有效付费分层规则，具体档位和奖励按本例配置填写。需日志确认——同一交易的成功次数、最近成功时间及适用金额统计更新一次；无日志入口时注明这部分不能仅从界面确认。
- 判定限制：若两种身份展示完全一致，不能靠同一价签证明身份已更新；需要有区分度的合法配置或已核实的状态观察入口。禁止为测试直接修改付费判定算法。

## 示例：重启补单

- 优先使用经核实的“下次登录成功”或等价测试能力：发起一次购买，确认订单已进入等待恢复状态，再杀进程，保留同账号原存档重启，等待补单。明确“不要清档/不要新买一单”。
- 没有模拟能力时，自然路径可写“商店成功后、客户端结果处理完成前中断”，但必须标明难稳定命中；杀进程本身不证明服务端付款成功或订单尚未核销。只有确认目标前置成立才进入后续判定。
- 领奖后重新打开受影响的礼包等消费者；逐项验证奖励、资格和下游选择，不能拿“弹了奖励页”替代所有断言。需要真机商店时注明沙盒环境，不默认发起真实扣款。

## 示例：价格查询晚于页面打开

- 前置注明非美元沙盒商店、该SKU尚未查价、可用的查询延迟控制；断网或限速只作为命中尝试，不能保证只延迟目标请求。
- 先打开商品页并记录价签/商品，再恢复查询；保持同一页不关闭，以已核实的商品查询完成证据确认SDK缓存已有该SKU本地价。记录原页是否刷新，再重新打开同一商品作辅助对照。
- 正常期望来自当前需求：本地化价格、商品/奖励是否锁定分别断言。缓存有新价而原页保留旧价，与缓存始终没得到新价，不是同一结论。不得直接宣称界面美元价等于商店实际美元扣款。
- 旧价格快照、付款倍率和存档是否错误须用日志或探针观察；普通黑盒只能承接价签等界面结果。若重新打开造成选档变化，先核对SKU一致，不能直接比较两个不同商品。

## 交付前做一次“照单操作”审阅

以只拿到该行的测试人员视角检查：账号/档是否能准备？入口是否真实存在？每个输入和等待条件是否明确？目标时序是否真的命中？正常与异常能否区分？内部断言是否有观察方式？是否误用清档破坏恢复前置？

缺任一关键条件，补查后完善，或明确该断言的执行缺口；不能用详细文字掩盖无法建立的前置。设计阶段不填写“已复现”，没有实际执行结果不填写“测试通过/不通过”。
