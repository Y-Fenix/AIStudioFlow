# GagaSort QA 使用说明

面向 GagaSort 项目的自动静态检查 skill。在 Codex 中输入 `$gagasort-qa`，自动审查当前项目代码和配置，必要时运行本地测试补证，输出可以直接阅读的 HTML 报告。日常使用不需要提供需求、用例表或选择模块。

它是由 Agent 执行的项目专用工作流，需要配套的 GagaSort 仓库；单独运行某个 Python 脚本不能代替全量业务审查。

## 1. 怎么使用

首次安装见下一节。安装完成后：

1. 在 Codex 中打开要检查的 **GagaSort 游戏仓库**。
2. 输入以下内容并发送：

   ```text
   $gagasort-qa
   ```

3. 等待审查、自动补证和报告校验完成，打开回复中的 `查看报告.html`，选择本轮时间戳文件夹。

默认检查整个项目，不只检查最近改动。运行时间随代码规模、关卡数量、求解预算和依赖准备情况变化，没有固定耗时承诺。

只查指定模块时可以输入：

```text
$gagasort-qa 只检查复活礼包
```

这会检查该功能及实际关联的支付、奖励、存档、配置和升级重装影响。也支持附带需求、缺陷描述或用例表，但它们不是默认必填输入。询问用法或修改 skill 本身不会触发全量检查。

开发修复后验收：保留原始 `bugs.csv` 存档，开发在独立工作副本 `bug-progress.csv` 中把已修复项的“处理状态”改成“待验证”，然后输入：

```text
$gagasort-qa 验收这份 bug-progress.csv 中处理状态为待验证的 Bug，并回填验收状态：<文件路径>
```

Codex 核对当前代码中的修复、边界和关联回归，在“处理状态”右侧新增或更新“验收状态”：通过写“已验证”，原问题仍在或确认修复引入关联缺陷写“重新打开”。原处理状态及非本轮内容保留；证据不足不能判通过。回复固定包含验收数量、已验证数量、重新打开数量、新 Bug 情况、CSV 与逐项证据链接及实际验证方式。有未完成项时单列说明，不默认转人工。完整规则见[Bug 定向验收与回填](references/bug-acceptance.md)。这不会启动全量巡检或改写原报告。

## 2. 首次安装

**需要完整目录，不能只复制 `SKILL.md`。** 脚本、references、埋点契约、HTML 模板和版本文件都要保留。

选择一种安装方式即可，避免多个同名旧副本：

| 使用范围 | 完整 skill 的安装位置 |
| --- | --- |
| 只在该游戏项目使用 | `<GagaSort仓库>/.agents/skills/gagasort-qa/` |
| 本机用户级使用 | `~/.agents/skills/gagasort-qa/` |

安装后应存在 `gagasort-qa/SKILL.md`，不要多套一层目录。用户级安装后仍需在 GagaSort 游戏项目中运行。

本机先维护独立全局目录 `/Users/yf/.agents/skills/gagasort-qa`，再同步 GagaSort 项目，最后同步 `RuneSkills/test/gagasort/`。同事使用自己的安装路径；明确调用项目内 skill 时按指定目录加载。被测游戏仓库与 skill 所在目录分别定位，报告生成在游戏仓库。

全局、项目、RuneSkills 保留独立目录。用户已授权按此顺序同步完整有效文件并校验一致性，项目位置为 `/Users/yf/Documents/Unity/gagasort/文档/测试文档/gagasort-qa/`；具体见[本机同步规则](references/repeatable-delivery.md#本机同步规则)。保留无关改动，排除缓存、认证与运行产物，不自动暂存、提交、拉取或推送 Git。

本 skill 仅在输入 `$gagasort-qa`、手动选择技能或明确要求使用它时运行，普通问答与机制检查不自动触发。分发和同步时必须保留 `agents/openai.yaml` 中的 `policy.allow_implicit_invocation: false`。

如果 `$` 列表找不到：检查安装目录、`SKILL.md` 是否存在、软链接目标是否有效，并在安装后的新会话中重试。不要通过再复制一个同名旧版本解决。

## 3. 必备环境

以下按当前完整管线的真实依赖整理。版本建议不代表已验证所有旧版本兼容。

| 环境 | 要求与用途 |
| --- | --- |
| 操作系统 | 当前完整流程以 **macOS** 为基准。离线 Unity 工具和中文字体使用 macOS 默认路径；Windows/Linux 需要适配，不能直接保证开箱即用。 |
| Codex | 支持 skill、本地命令与文件读写；可使用子 Agent，按领域分工审查，最多同时运行 4 个子 Agent。不可用时须明确记录代行范围，不能冒称独立审查。 |
| 游戏仓库 | 完整的对应版本 GagaSort 源码、关卡与资源、开发文档、项目工具及相关子模块内容；可读取源码，并可在 `QA/results/` 和临时目录写入证据。 |
| Git 与 Shell | 用于读取版本基线、工作区和子模块状态，以及执行项目工具。skill 不会自动拉取缺失仓库或子模块。 |
| Python 3 与 pip | 建议 Python 3.11 或更新。用于扫描、证据校验、报告生成和打包。关卡解析、绘图依赖 `msgpack`、`Pillow`。 |
| 项目版本的 Unity 安装 | 从游戏的 `GagaSort/ProjectSettings/ProjectVersion.txt` 读取版本。当前项目为 `2022.3.62f2c1`，默认在 `/Applications/Unity/Hub/Editor/<版本>/Unity.app/Contents` 查找内置 .NET 6 运行时和 Roslyn 编译器。用于离线复用生产逻辑，**无需打开 Editor，不依赖 Library 缓存，不构建 Player**。 |
| Node.js | 建议维护中的 LTS 版本，用于 HTML 自动交互校验。 |
| Playwright 与浏览器 | Node 能加载 `playwright` 或 `playwright-core`，并有可用的 Google Chrome、Chromium 或 Playwright Chromium；用于校验页签、跳转、筛选、图片和报告交互。 |
| `lark-cli`（仅飞书提单需要） | 已安装并完成可用的飞书 Base CLI；报告通过 `scripts/feishu_bridge.py` 调用，不把 app secret 或 access token 放进 HTML。只看报告、导出 CSV 或不使用飞书时不需要。 |
| 中文字体 | 关卡图需要可用中文字体。脚本会查找 macOS 的 PingFang、STHeiti、Songti；缺字体会报错，不用乱码图交付。 |
| 网络 | Codex 正常运行所需连接；首次缺 Python 包或离线编译所需 Unity 包时，需能访问相应包源。缓存完备后，部分本地步骤可以离线执行。 |

Python 缺少 `msgpack`、`Pillow` 时，关卡脚本会尝试通过 pip 安装固定版本到临时目录，不要求用户日常手动安装。Node、Playwright、浏览器优先复用宿主已有依赖；路径不在默认位置时，由执行 Agent 查找并传入实际路径。环境准备好后，同事日常只需输入 skill 名。

本地查看和导出无需飞书；需要更新表头或提单时使用本机桥接，复用会话已有授权：

```bash
cd <gagasort-qa skill目录>
python3 scripts/ensure_feishu_auth.py --start-bridge
```

本次提单授权不能由本机登录态代替。仅在本次已明确授权提单后运行 `python3 scripts/ensure_feishu_auth.py --start-bridge`。已有 `base:block:read`、`base:field:read`、`base:view:read`、`base:record:create` 的有效或可刷新用户会话直接复用；不申请不存在的 `base:record:write` 权限。若脚本退出 3，立即向用户展示本次返回的授权 URL 和二维码并结束该轮；用户完成授权后才用本次设备码继续 `ensure_feishu_auth.py --device-code <本次设备码> --start-bridge`，不阻塞等待、不把设备码或 token 写入报告/分发包。未授权或连接失败只暂停飞书，不影响静态检查和 CSV。用户在 HTML 点击“更新表格”或“提单”打开“新建 Bug 单”，粘贴飞书 Base/Wiki URL → 读取表头 → 检查全部内容预览 → 手动点击“直接更新并提单”。打开、读取和预览不创建记录。桥接只监听 `127.0.0.1:17321`，HTML 只接收状态、真实字段及提单结果，不接收 token。

CodeGraph 可用于源码定位，未提供时按项目协议回退到定向源码检查。Unity MCP、Figma、后台账号、真实支付账号、设备安装包和需求链接均不是默认静态检查的必备条件。

## 4. 检查哪些内容

检查范围已固化为 **90 项：玩法28、关卡5、系统47、配置6、埋点4**。完整目录见[固定测试范围](references/audit-scope.md)，机器清单为 [audit-scope.json](assets/audit-scope.json)。同事仍只输入 skill；总控先锁定完整清单再执行，少项不能标“全量完成”。新增功能按代码证据更新清单版本，不能每次随意合并或缩减。这里是功能分组数，具体关卡、配置键、语言和埋点逐条展开检查。

| 类别 | 检查内容示例 |
| --- | --- |
| 玩法 | 关内机制、道具、状态转换、异步回调、失败与恢复、奖励和存档消费者。 |
| 关卡 | 实际打包清单、配置合法性、布局异常、正式无道具求解与独立回放、岸壁和水面几何风险；异常与风险输出真实位置图。 |
| 系统 | 礼包、支付、活动、排行榜、头像、设置、多语言等非关卡功能，逐项追查业务链和边界。 |
| 配置 | 客户端对后台参数的解析、缺省、覆盖、缓存、更新通知和最终生效逻辑，以及边界值和组合。 |
| 埋点 | 对照本地固化埋点契约检查事件、属性、触发时序、重复与漏报路径、统一出口和身份恢复；新表需另行更新契约。 |

每个功能还分析三种数据条件：**保留旧本地数据覆盖升级、清本地数据后同身份恢复、清本地数据后新身份初始化**。这是代码与隔离数据检查，不实际覆盖安装或卸载应用。

先完成逐分支源码审查，有歧义再自动使用可控时间、回调、配置、旧档或已有测试补证。默认不修改生产逻辑、正式资产、线上配置或真实账号，不提交和拉取 Git，不把正常功能交给同事人工验收。

## 5. 报告怎么看

每轮内部证据保存在 `QA/results/full-audit-<时间>/`；同事日常只需要以下交付：

```text
文档/测试文档/质量报告/
├── 查看报告.html
└── YYYYMMDD-HHMMSS/
    ├── report.md
    ├── bugs.csv
    └── images/
```

固定查看器只放一份，每轮新增时间戳文件夹，不覆盖历史。打开 `查看报告.html`，点“选择报告文件夹”，选择所需时间戳目录。系统选择窗口可能记住上次位置，页面提供当前目录复制；Mac 可在窗口按 `⌘⇧G` 粘贴定位。

- **总览**：本次范围、已盘点和已深审情况、问题数与执行结论。
- **Bug 列表**：完整保留23列和空列，直接展开条件、步骤、实际表现、归因及影响；支持导出完整 CSV。“更新表格”支持读取飞书表头并自动映射内容，预览后手动提单；飞书功能需要本机连接和有效登录。
- **玩法 / 关卡 / 系统 / 配置 / 埋点**：先看该类问题和风险，再看具体检查内容与结果。
- **问题详情**：影响、触发条件、预期与实际、复现步骤、归因及证据。有准确玩家路径就写黑盒步骤，否则给可复核的白盒步骤。
- **关卡图片**：相关入口直接跳到标位图及解释，原始日志和数据收在开发核对内容中。

颜色固定：

| 颜色 | 含义 |
| --- | --- |
| 绿色 | 在列明的静态检查范围内未发现问题。 |
| 棕色 | 风险、求解预算内未定或检查未完成，不能当成通过。 |
| 红色 | 有证据确认的问题。 |

必要源码和日志摘录保存在 MD，图片以原文件保存在 images/ 并按内容去重；完整日志、源码快照和校验回执只留在内部 QA/results。转交他人时分享**固定查看器及所需时间戳文件夹**即可离线阅读，不需要作者电脑上的原工程或 QA/results。Codex 可以直接读取 MD、CSV、图片。

Bug 单“版本号”统一固定为 `Codex`，HTML、CSV 和飞书提单一致；游戏真实版本与检查基线另行保留。

`bugs.csv` 与页面默认下载内容一致，保留完整表头、中文、多行步骤和真正空字段。风险和未完成项不混入 Bug 清单，零问题仍保留23列。CSV 不等于已在飞书提单，不自动上传附件。MD 绑定 CSV 和图片的哈希，避免选错批次；不要只修改一个文件后混用，修改内容应重新导出整轮。

上述哈希约束适用于原始报告批次。独立的 `bug-progress.csv` 是开发与测试协作的工作副本，可以单独更新处理状态和验收状态，不需要重导原始报告；验收不会修改原始 `bugs.csv`、`report.md` 或查看器。

“报告生成成功”不等于“没有 Bug”。静态检查不能保证找出全部缺陷；求解超时不能证明无解，几何风险不能直接认定为真机画面 Bug。真实平台、服务端和设备事实只记录范围限制，不伪造已验证结论，也不默认生成同事人工待办。

每轮还会生成 `quality-gate.json`。它用本轮数据固定计算盘点数、深审数、完成数、已证问题数、风险数和待续查数，并纳入便携报告数据。未完成时页面明确显示“本轮确认问题”，不会把部分结果冒充全项目 Bug 总数；同一输入和版本的排序、计数应保持一致。

## 6. 怎么分享给同事

报告读取、发布命令和数据契约见[便携报告协议](references/portable-report.md)。旧 HTML/CSV 保留；仅用户明确要求旧联机格式时启用旧方式，不是默认流程。

可直接分享完整 skill 目录，或使用现有打包脚本：

```sh
python3 -B <实际skill目录>/scripts/package_skill.py \
  --output <skill目录之外的全新zip路径>
```

同事解压后将 `gagasort-qa/` 放到第 2 节的一个安装位置。分发包带文件哈希；不要附带本机认证、缓存和历轮 `QA/results/`。同事仍需准备自己的游戏仓库和上述环境。

固定的是执行流程、深审门禁和 HTML 格式；当前代码、配置、机器预算不同，Bug 数和关卡结论会变化，不能承诺每次复制出历史结果。

## 7. README 会影响 skill 吗

**单独增加本 README 不改变 skill 的执行入口、名称、检查逻辑或 HTML 样式。** Agent 的执行入口仍是 [SKILL.md](SKILL.md)，详细规则见其引用文档；README 面向安装和阅读的人，不替代执行协议。

README 不会因为放在目录中就变成另一个 skill；Agent 显式读取它时，内容才会进入相应上下文。现有打包脚本会自动把它放进分发包，因此包内文件数和哈希会变化，这是正常的文档变更，无需调整报告模板指纹。
