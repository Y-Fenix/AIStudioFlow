# 代码报告生成与交付

按当前阶段读取对应小节，不默认全文加载。下文 `scripts/` 路径相对于本 Skill 安装目录；§ 编号保留原流程含义。

### 外部提单授权门禁

本节与“启动授权门禁（第一步）”是同一条硬门禁，不得在后续阶段补问后倒推已授权。只有收到明确的“授权提单”或等价肯定答复，才允许在 HTML 生成命令中加入 `--write-authorized`；未收到明确授权、用户拒绝或授权范围不清时，省略该参数，生成只读页面并在最终摘要说明未授权。

授权只代表用户同意本次外部写入，不等于登录凭据或服务端权限。不得索取、写入或嵌入 Cookie、Token、账号密码；实际表格服务/桥接服务仍必须自行校验当前浏览器会话和写入权限。HTML 页面加载、读取表头和筛选永远不写入，必须由用户手动点击“直接更新并提单”触发一次 POST。授权不可跨运行、跨报告继承；新运行必须重新询问。

## 可运行的报告门禁

先按 [四维覆盖契约](coverage-contract.md) 运行 `scripts/validate_design_coverage.py`，核对同一来源账本与实际主表回读的 `input-manifest.json`，保存 `validated-coverage.json`、实际命令和退出码。联用 `test-case` 复用同一账本，不重复分析；输入/来源/覆盖项发生变化时重跑。来源和四维缺口均闭合后才能宣称覆盖完整；阶段结果的四维分母和缺口必须在 Excel 同页摘要、HTML 顶部与对话可见。覆盖门禁不能代替下面的逐断言结果门禁。

生成报告前必须读取 [references/report-contract.md](report-contract.md)，按契约生成独立输入清单与审查账本，并运行本 Skill 的 `scripts/validate_report.py`。生成器只消费其逐行结果和统计，不能重新按模块、关键词或行号套状态。

来源完整性同时受 [references/media-coverage.md](media-coverage.md) 约束：输入清单与审查账本必须绑定同一 `source-coverage.json` 及 SHA256。正式结果默认 `report_stage=final`，必须对账所选来源、原始媒体引用、实际读取回执及规则到用例的映射；不能用正文摘要或旧表代替图片/视频需求。确实缺失资料时继续判定已可证明断言，阶段交付显式使用 `report_stage=partial`，并在 Excel 摘要、HTML 顶部及对话中列出缺口。不得因来源缺口把所有已闭合本地结论改为黑盒，也不得把“现有用例已审完”说成“需求已覆盖完整”。

校验失败时继续补查或修复，不能交付标称完成的正式报告，不能删条目、改期望或改绿绕过。确有外部阻塞时只能交付明确标记的阶段结果及具体限制。校验通过只证明清单完整、证据文件/哈希、归并和残留字段符合契约，不能证明代码推理必然正确。

生成 Excel 后回读核对原六列指纹、逐行 key/结果、全部状态计数与残留，和校验输出一致；JSON 校验不代替 Excel 回读。再次运行校验并保存实际命令/退出码/摘要。Skill 不会自动安装到 CI，不擅自安装 Git hook。

### 功能模块写入规则

功能模块统一使用 `【Codex-{功能模块名称}】`，去除名称开头的 ✅ 等装饰；不匹配原业务选项。前后端归一化必须一致且幂等。读取表头和预览不得创建选项；仅在用户手动点击提单后，桥接先读取完整字段定义，保留原选项、颜色、说明、默认值和单多选类型，追加缺少的 Codex 选项并读回确认，再创建记录。同名 Codex 选项已存在时复用。动态选项不得改成静态选项。模块为空、不可写、权限不足或创建未确认时必须阻断提单，不能省略模块或使用默认模块。授权预检除读取表头和创建记录权限外，必须检查 `base:field:update`；缺权限先补授权，不得伪报已具备提单权限。已提交记录不自动修改或重提。

### Bug 文案与字段映射

- 只为失败断言生成缺陷文案。同一行的通过项不得写入错误表现或期望描述；多个失败项必须逐项对应前置、步骤、实际和预期。
- 标题直接说明“在什么条件下，出现什么错误”。缺陷描述必须完整包含四段：前置条件、操作步骤、当前错误表现、预期正确表现。前置写明已知账号/活动状态、时间与配置值、是否保留旧档；需要清档、隔离账号或内部探针时明确说明，不凭空指定。
- 操作步骤使用真实换行和 `1、2、3、` 编号，写明入口、对象、具体输入、动作顺序及观察位置。代码注入、模拟回包或暂停 SDK 回调必须标明受控方式，不伪装成玩家操作。不得只写“执行用例、开始并记录旧配置、查看结果”。
- 当前错误表现写代码推导或实际记录支持的具体结果，预期正确表现独立写正确结果。不用“测试不通过”、归因、内部字段名称、`a1/e104` 等编号代替表现。代码路径、行号、需求位置放独立“日志信息/检测依据”栏，不能把证据编号直接塞给开发。
- 静态证明注明“代码推导，未真机复现”；本地自动化注明测试范围；有实际观察才按记录写已观察。不得默认填写“必现”、操作平台、服务器、优先级或严重程度，未知留空。
- 生成器从失败断言的 `bug` 对象取文案；无该对象时仅可使用该失败断言自身的输入、步骤、实际和预期，不回退到整行混合结果。标题及四段任一缺失，或没有可定位依据，必须阻止提单并显示缺项；不得补造内容绕过。
- 提单预览与写入消费同一份文案。保留 `【静态检测】` 前缀、版本 `Codex`、模块 `【Codex-{功能模块名称}】` 及原授权门禁。修正文案不自动修改或重提历史飞书记录。

### HTML 并行报告与提单

Excel 是机器/复制交付，HTML 是人工浏览交付；两者必须消费同一份 `input-manifest.json`、`review.json` 和 `validated-results.json`，不得另行按关键词重算状态。每次正式报告默认同时生成同目录、同基线的 `原文件名_{分支}_代码检测结果.html`，保持单页签语义：全部用例在同一张表中展示，原六列、测试结果、检测依据、自动化执行情况、真实环境残留和操作列均可筛选。

HTML 生成器会重新校验当前输入、来源/媒体证据及审查账本，并与 `validated-results.json` 完整比对；文件变更后必须重跑门禁，不能复用旧摘要。Excel 生成与回读也必须使用本次门禁输出，并展示相同来源完整性及阶段限制。

使用随 Skill 分发的标准库脚本生成页面，禁止复制旧 HTML 或手写一份缺行页面：

```sh
python3 scripts/generate_report_html.py \
  --input /绝对路径/input-manifest.json \
  --review /绝对路径/review.json \
  --validated /绝对路径/validated-results.json \
  --output /绝对路径/原文件名_master_代码检测结果.html \
  --title "代码初步质量报告"
```

获得本次明确授权后，在上述命令末尾追加 `--write-authorized`；未授权时不要追加。该参数只解锁页面按钮，不绕过桥接/表格服务的鉴权。

页面必须具备搜索、测试结果筛选、需求模块筛选、仅看未决/外部残留、当前筛选 JSON 导出和每行“提单”按钮。已授权时提单流程固定为：点击按钮 -> 用户粘贴 `http(s)` 表格 URL -> 读取并展示目标表头 -> 按表头映射当前用例字段 -> 用户点击“直接更新并提单” -> 发送导入请求；不再弹出第二次 `confirm`。未授权页面仍可读取和预览表头，但写入按钮必须禁用并明确提示“未发生任何写入”。读取失败、取消、跨域、非表格响应、非 2xx 或返回格式错误都必须显示错误且声明“未发生任何写入”，不得写成功。

表格 URL 的直接适配只允许两种可验证响应：JSON `{headers: [...], columns?: [...]}`，或包含首行 `<thead><th>` 的 HTML table。Feishu/企业内部表格页面通常需要本地桥接服务，生成时可用 `--bridge http://127.0.0.1:<port>`；桥接服务必须提供 `GET /schema?url=... -> {headers:[...]}` 和 `POST /import`，导入 body 至少包含 `url`、`headers`、`row`、`caseKey`。桥接不可用时保留页面筛选和映射预览，不能把人工复制或本地 JSON 视为远端导入成功；不在 HTML 中保存 token、Cookie 或账号数据。

使用飞书 Wiki/多维表格页面 URL 时，必须先启动随 Skill 分发的本地桥接服务，再生成 HTML；浏览器不能直接把 Wiki 页面当作可写 API：

```sh
python3 scripts/feishu_bridge.py --port 8765
```

生成报告时追加 `--bridge http://127.0.0.1:8765`。桥接服务只监听本机回环地址，凭据留在本机 `lark-cli` 用户登录态中；HTML 通过桥接读取表头和提交数据，不保存 Token/Cookie。启动后可先执行以下只读检查：

```sh
curl http://127.0.0.1:8765/health
curl --get --data-urlencode 'url=<用户粘贴的飞书 Wiki/Base URL>' http://127.0.0.1:8765/schema
```

桥接不可用、`lark-cli` 未授权、URL 解析失败或字段类型不支持时，页面必须显示具体错误并声明“未发生任何写入”；不得退化成伪造成功。只有用户在已授权 HTML 中点击“直接更新并提单”后，桥接才调用 `+record-batch-create`。

提单是外部写入，必须同时满足“本次 Skill 已获用户授权”和“用户在 HTML 中点击直接更新并提单”；技能运行、页面加载、读取表头和筛选均不得自动创建 Bug 单。导入响应只在真实收到 2xx 且记录响应摘要后标记成功；HTML 只能展示成功/失败，不能修改 Excel、review 账本或原始用例。

## 交付核对

- 已记录并复核实际基线，未用其他分支、旧报告或记忆代替当前证据。
- 所有范围内用例与参数实例有断言级审查记录；输入实例总数和已审数核对一致，公共模板、参数实例、回归场景的计数口径明确且不重复。
- 每条失败有可达反例，每条通过覆盖声明范围内全部断言；code 通过不包装为完整用例验收通过。
- 需求待确认、证据不足、缺接缝、需自动化验证、需黑盒验证分别统计；每项均通过必要性检查，附影响断言、解除动作及责任来源，说明静态追踪和可控验证已做什么。
- 已核对耦合传播到真实消费点，白盒测试覆盖与输入实例逐一关联；报告通过但找不到本次执行证据的不算自动化通过。发现输入漏测另列建议，不能用“输入表都审过了”声称需求全覆盖。
- 默认静态检查逐项有输入、调用路径、中间状态、推导输出及独立需求预期；四维覆盖分别计数。可选黑盒复测步骤不计人工待办；真正的黑盒残留逐项说明外部独有变量，不能用缺动态环境或账号代替理由。
- 可在当前权限和资料内补齐的缺口继续处理；外部依赖或未完成分析如实保留，不为了清空待验证强行下结论。
- 未修改原用例期望、未自动继承旧结论、未重复添加结果列、未擅自覆盖输入；输出字段和统计核对一致。
- Excel 与 HTML 使用同一基线和逐行结果；HTML 用例数、测试结果计数、残留数与 `validated-results.json` 一致，生成脚本拒绝覆盖已有 HTML。
- 提单流程有 Skill 级一次授权、表头映射、用户点击和远端响应；未配置桥接或跨域失败时不得伪造导入成功，不把“导出 JSON”冒充已提单。未授权页面必须只读。
- 最终分别报告代码结论、实际运行数、根因数和真实外部残留；残留断言数不等于人工用例数。对比旧结果时说明代码、需求、测试或口径的变化，不能只换标签。格式检查通过不等于业务通过，静态检查不等于自动化执行或真机验收。

### 当前对话简报（必须）

每次运行结束，必须在当前对话的最终回复中简短汇总，不能只提供文件链接或让用户自行打开报告。说明实际检查基线、输入用例总数及各结果数量、主要 Bug 根因和真实外部残留，并附结果文件。明确是代码初步质量还是完整验收结论；自动化实际运行数与审查用例数分开统计。

来源与覆盖另列：已选来源数、全部来源已读/总数、各类媒体已读/发现数、未覆盖/待确认规则数。来源未闭合时明确“阶段结果”，不能仅给通过率；校验通过只证明清单和证据映射符合契约，不能证明模型视觉理解或需求语义绝对无遗漏。

数字必须来自本次实际产物，缺少可靠统计时如实说明。仅回顾历史结果时标注结果日期/基线及“本次未重跑”，不得按新口径擅改旧统计。联用其他测试 Skill 时合并为一份短简报，关键失败和未完成项不能因压缩篇幅被隐藏。
