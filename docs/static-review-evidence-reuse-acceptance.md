# 静态审查证据复用验证（2026-11-10）

## 已实现

- 显式模块/精确测试点关联的临时证据种子；同主关联串行、不同关联保持最多3路并发，结果原顺序。
- 本用例搜索命中已有源码位置时，取回本次执行内重新校验的原文片段；不自动复制其他用例结论。
- 种子与单轮取回各最多120KB，单轮取回最多4文件，单用例仍最多700KB。组池32键、全局片段池128文件/4MB，执行实例互相隔离。
- 搜索文本在已读源码中逐字存在时，模型请求使用引用标记；证据文件保留原始搜索文本。检查点包含新策略版本；无效缓存重算且不计入复用数量。

## 实际检查

- 先运行新增失败测试，分别复现无 module 时无法按测试点复用、旧调度没有关联隔离、搜索后不能取回已读片段、无效缓存误计复用。修改后回归通过。
- Python 业务回归及静态检测专项：128项通过。
- `node --test tests/*.test.js`：105项通过。
- 部门静态依赖/命名检查与 `git diff --check` 通过。
- 完整执行器入口的受控模型替身：4条用例、2个精确关联组，总模型请求从无共享时需要的8次降为6次；每条仍有独立断言校验，产物顺序保持。此结果不能外推为真实模型耗时。
- 使用原有真实执行前37条记录、实际源码，只读回放证据池：20条存在关联种子，36条在自己的搜索结果中命中此前已读片段。回放按完成顺序近似，不代表三路线程运行时一定得到相同命中。
- 相同记录的请求历史压缩从8,372,517字符降为8,244,191字符，仅减少1.5%；因此此次主要收益假设来自减少源码发现/读取的模型往返，不能宣传上下文压缩带来大幅提速。
