# 商业工作台本轮验收

日期：2026-10-22 开始，2026-10-23 持续验收。对应[需求设计](superpowers/specs/2026-10-22-commercial-workbench-design.md)与[实施计划](superpowers/plans/2026-10-22-commercial-workbench.md)。

## 已落地

- 产品、设计、开发共十二个默认节点，由原人工占位改为调用当前启用模型和当前节点实际 Skill。每节点有独立交付章节与能力边界，公共层检查非空章节、精确段落 ID、引用格式及引用是否逐字来自输入；结构错误最多定向修正一次。空交付不能成功。
- 普通节点和自定义流程保留证据、缺口及执行器实际返回的检查报告。报告明确未做事实核验，不生成虚假的质量分数。保留版本冲突、撤权、历史快照及人工审核门禁。
- 部门工作区提供紧凑 Skill 菜单、Markdown 阅读预览、运行准备提示、常驻保存/运行操作栏和失败恢复指引。模型完成、保存失败及晚响应不应覆盖当前输入草稿或跳到其他节点；上游交付先预览，追加为独立草稿，不自动保存。
- 测试六节点采用常驻操作栏，保存评审与确认不再依赖滚过全部条目；Skill 工具及次要操作收进菜单。原逐用例静态证据链和全自动到内部草稿的边界保留，不启动 Unity。
- 首页使用真实可见记录和当前权限展示进度、执行能力及下一步；不插入演示成功数据。四部门卡片遵循统一最小尺寸与主题规范，保留已确认的首页高度。
- 部门队列及自定义流程新增持久化进度：请求模型、推理强度、重试次数、已收字符和有效响应间隔。只存白名单诊断字段；进度更新不改变输入/运行修订，不触发重复执行。进度中断提示与任务失败分开，刷新页面可继续查看。
- 提供[游戏版本示例和入门](commercial-workbench-onboarding.md)，说明部门交接、能力限制和业务试点指标。

### 完整响应的 JSON 格式恢复

10月23日代码追踪发现：章节和引用错误已有一次修正，但模型完整响应无法解析为 JSON 时，`ModelOutputError` 会直接退出，未进入修正。新增四项回归先确认失败，再将 JSON 解析、章节和引用错误统一使用一次修正预算。修正时保留原输入、Skill 和契约，仍执行严格引用校验；过大原响应不重发，二次失败不继续循环，也不把原响应正文写入最终错误。传输失败不走此格式恢复。

实际通过 41 项交付/执行器/解析专项、全量 589 项 Python、89 项 JavaScript、四部门边界检查及 `commercial-workbench.cjs` 隔离浏览器回归。格式恢复由明确的畸形响应与真实解析器测试验证，不宣称真实服务必定返回可修复格式。

## 真实模型试跑

使用隔离临时数据库、实际部门注册表和后台队列，输入为入门文档中的虚构游戏规则，节点为产品 PRD（`product:3`）。只读复用原团队模型选择：本机中转配置、请求模型 `gpt-6.1-sol`、推理强度 `high`、Responses HTTP；不读取或输出密钥，不修改用户项目与当前模型设置。此处模型名称为请求选择，不能独立证明中转站实际路由到的底层模型版本。

第一次试跑失败：模型引用了契约中的文字，引用未出现在用户输入中，被校验拒绝；一次修正请求还发生连续 600 秒无新有效响应的真实空闲超时，底层有限传输重试后仍未通过引用校验，总耗时 976.9 秒，未保存成功交付。

已针对失败补回归测试并修正提示：引用只允许来自 `inputs`，错误指出具体 `claims[index].quote`，规范和建议不能冒充资料事实。保持严格校验，不以放宽引用规则换取成功。修正后的第二次真实试跑中，第一轮请求产生 3,074 个正文字符后停止，连续 600 秒无新有效响应，约 861.57 秒触发空闲超时；未收到完成事件，未保存片段为结果。已核对原始 SSE 事件及未启用工具的请求元数据，此处是响应流停滞，不能称为正常持续生成。

随后第 2/3 次请求在 183.77 秒完成并通过校验；本次试跑总等待 1045.4 秒，结果状态为 `waiting_user`。实际报告为 `product.prd.v1`、6 个章节、8 处逐字来源引用、0 次结构修正、`fact_checked=false`，正文 5,816 字符。已阅读[完整试跑样本](examples/commercial-workbench-prd-smoke.md)：包括范围与规则、状态/页面、六条代表性验收、事实/推导/假设及具体缺口，未宣称工程已实现或测试通过。个别正文事实索引仍需人工逐项核对；结构检查不做语义关联正确性判定。

随后用该 PRD 合成样本，经过实际自定义流程、默认 Skill 和执行器，完成 `design:1` UX → `development:0` 技术方案的自动交接。UX 耗时约 310.19 秒、正文 12,238 字符；技术方案约 326.56 秒、正文 14,938 字符；整链 636.9 秒、最终状态 `completed`，不代表人工批准。两个节点均检查 6 章节、8 处原文引用、0 次修正、`fact_checked=false`。完整样本见 [UX 交付](examples/commercial-workbench-ux-smoke.md)与[技术方案](examples/commercial-workbench-technical-smoke.md)。正文覆盖页面/异常/广告竞态和工程状态/接口/迁移/验证计划，明确箱体机制、SDK 契约和源码等缺口；引用匹配不校验语义关联。此次真实链启动于新增持久化进度代码之前，不用于宣称新进度功能已完成真实模型验收；进度功能由隔离队列/浏览器测试验证。

测试部门已有此前归档的真实模型证据，见[静态链路验收](qa-static-pipeline-acceptance.md)：六行 Reward 合成源码、三条用例完成生成→静态检测→共同归因→显式模拟批准后一张内部草稿→修复后静态回归。该链模型传输真实，Git 基线用样例 SHA256 替代，不能描述为实际游戏全链验收。另外 `data/qa-acceptance/2026-10-22-autopilot/real-static-smoke.json` 记录实际 GagaSort 需求、首条用例及真实源码基线的只读静态试跑，203.86 秒；原始报告计数为 `needs_runtime=1`，不是通过，也未写回原任务或启动 Unity。

完成交付逐份阅读全文后的发现：

- 市场调研将 TAM/SAM/SOM 写为带假设的计算框架，没有捏造市场规模和收益。竞品节点保留虚构标签，未将“没有商业化记录”推断成竞品 B 没有广告。
- 视觉和验收均识别了 24×24 与至少 44×44 触控尺寸冲突；验收因缺少实际图稿和设备证据，不建议批准设计。视觉方向及尺寸调整仍为提案。
- 实现和集成都识别失败仍奖励、重复回调重复加时；将线程、切局和 SDK 未知项保留为待验证，未宣称整工程存在已复现问题。实现提供未应用伪代码，集成提供未执行测试计划。
- 玩法商业化区分有效操作时间与现实经过时间，使用资源守恒推导分数上限；探索实验每组 20 人明确不能证明五个百分点的非劣性。最小存档、最好成绩和埋点是新增建议，需重新检查两周 MVP 范围，不能自动采用。
- 资产生产明确只交文字规格，未冒充真实图片或声音；逐资产许可仍未知。数量、尺寸、包体和内存预算均为建议，理论 RGBA 计算不等于设备测量；十类资产与四批排产需按单美术实际工时裁剪。
