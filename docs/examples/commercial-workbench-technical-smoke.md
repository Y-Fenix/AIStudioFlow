## 模块边界与依赖方案

【事实F03｜玩法资料】输入描述同色物品拖入同色箱，每箱容量3，满箱移走并加1分。来源：inputs“依据与判断”F03。
【事实F04｜规模与拒绝规则资料】输入描述错色、满箱时返回原位且不扣分；首版10关，每关最多30个物品。来源：inputs“依据与判断”F04。
【推导D03｜职责与依赖提案】建议依赖方向为：页面及输入适配器→SessionCoordinator→规则、计时、暂停及奖励策略；SessionCoordinator通过接口使用配置仓库、资源提供器和广告网关；具体平台适配器实现这些接口。规则模块不引用页面、SDK或场景对象。建议职责如下：LevelConfig负责配置结构及校验；CollectionRules负责落箱、满箱及分数计算；SessionCoordinator负责局标识、命令串行化和终局提交；PauseController维护暂停原因集合；AdCoordinator维护广告请求和奖励收据；页面Presenter将只读快照转换成P01—P04与L01显示。表现动画完成不能驱动得分、奖励或胜负提交。箱体补充算法与布局策略在业务规则确定后单独接入，不预设箱体数量或生成机制。
【推导D04｜生命周期与资源加载】建议应用生命周期持有配置、资源及广告服务入口；每局生命周期持有局状态、命令记录、拖拽与奖励上下文；页面生命周期持有视图订阅和表现资源。开局顺序为加载配置→校验→准备必需资源→创建局状态→发布可玩快照，任一步失败均不进入可玩页。用加载代次隔离取消与重试；迟到资源到达后释放该次持有的句柄。页面退出时解除订阅并停止动画，局结束时使局命令与回调资格失效；广告SDK对象按其实际生命周期释放，不能假定页面销毁即可关闭广告。共享资源由资源提供器维护所有权，禁止页面直接释放其他页面仍在使用的资源。默认配置包、字体、物品与箱体资源拟随包提供；该加载来源仅为假设A02，不构成离线可用结论。
【假设A02｜资源来源】候选首版采用随包关卡配置与基础资源，以减少开局对网络的依赖；资源格式、压缩、图集及加载框架待工程基线确认。验证办法：检查全部目标关卡的资源引用完整性，在断网冷启动和缺失资源条件下验证开局与错误恢复。
【推导D05｜ADR-TECH-001提案】状态为Proposed。背景为拖放、计时、后台及广告回调可能同时改变同一局状态；建议采用单一局状态写入口和接口化外部服务。候选一是在现有架构内增加协调器，收益是便于审查原子提交及旧局隔离，成本是增加命令和快照适配；候选二是沿用现有组件事件组织并补齐防重和终局锁，新增结构较少，但跨组件顺序更依赖集成验证；候选三是采用完整事件溯源，便于回放，但增加事件版本、重建和迁移成本，当前不优先选择。初步推荐候选一，须先核对现有架构，不能据此推动全局重构。引擎兼容、既有ADR依赖、决策人、决定日期和最后核验日期均待确认；上游依赖状态为未知，不登记为无依赖。关联R01—R06；验证重点为同帧竞争、重复回调、销毁与重开。若已有架构无法低成本适配，则退回候选二并保留相同接口和验收断言；性能影响须测量后判断。该ADR未批准前，不解除依赖其决策的实现任务阻塞。

## 接口、状态与异常契约

【事实F05｜计时与后台资料】输入描述每关90秒，所有物品收纳完成即胜利，计时归零失败，切后台暂停。来源：inputs“依据与判断”F05。
【事实F06｜广告资料】输入描述每关可完成一次激励广告加30秒，失败或取消不奖励，网络失败可继续游戏。来源：inputs“依据与判断”F06。
【事实F07｜范围资料】输入范围包含开始、暂停恢复、胜负结算和加时，不含IAP、社交或云存档。来源：inputs“依据与判断”F07。
【推导D06｜公共接口草案】接口名称与类型均为新方案。StartLevel(levelId, configVersion, operationId, cancelToken)异步返回Started(sessionId, snapshot)或ConfigMissing、ConfigInvalid、ResourceMissing、LoadFailed、Cancelled、Busy；相同operationId复用同次结果，失败重试使用新operationId，取消后不得因迟到结果开局。DropItem(sessionId, actionId, itemId, boxId, expectedRevision)返回Accepted(snapshot, events)或WrongColor、BoxFull、InvalidTarget、ItemUnavailable、Paused、Terminal、StaleSession、RevisionConflict；拒绝不修改已提交局面。相同局内actionId及相同参数返回原结果，参数不同则报IdempotencyConflict。接受时在同一事务中处理物品归属、箱体占用、满箱移走、加分及终局候选，表现层随后消费结果；箱体补充尚无规则时不能宣称该事务完整可实现。SetPause(sessionId, reason, active)返回原因集合和快照；同一reason重复添加或移除均幂等。AdvanceTime(sessionId, activeDelta)仅由局调度器调用，校验非负有限增量，仅在可玩状态扣时，不由HUD自行减秒。SubscribeSnapshot(sessionId)返回可释放订阅；快照携带revision与终局状态，页面只读。
【推导D07｜状态、线程与取消】建议应用状态为Idle→Loading→Active→Settled，Loading失败或取消回Idle；Active内由暂停原因集合决定Playable或Paused。拖拽仅在Playable存在，暂停、终局或触点取消时回到最后已提交状态。所有局写操作经同一执行队列处理；SDK或后台线程仅投递带sessionId、requestId的消息，不直接改页面或局数据。终局提交是单向操作，提交后拒绝落箱、扣时和新广告请求。每个逻辑步先收集命令，再按已批准顺序处理落箱、计时和终局；不能将线程偶然到达顺序当成胜负规则。销毁页面只取消其视图任务；撤销开局使加载代次失效；已提交落箱不能因动画取消而回滚。计时使用可注入时钟，广告等待超时使用独立于暂停游戏时间的时钟。
【假设A03｜竞争与恢复规则】候选规则沿用输入中的待确认方向：最后有效落箱与归零同时发生时优先胜利；全部物品入箱即可胜利，尾箱无需装满；暂停冻结计时和拖放，回前台保持暂停并由玩家主动恢复。这些规则须由策划分别批准。验证办法：用可注入时钟构造同一步落箱与归零、尾箱未满、拖拽中后台、手动暂停叠加后台场景，按批准预期逐项判定。
【推导D08｜广告与权限边界】建议RequestReward(sessionId, requestId)返回请求受理或NotEligible、Busy、ServiceUnavailable、ConsentRequired、NetworkUnavailable；异步事件区分Loaded、Shown、Closed、Failed及RewardReceipt，不能把Closed或播放完成直接等同于奖励。ApplyReward(sessionId, requestId, receiptId)只在会话有效、请求匹配、收据有效且未应用时提交加时，成功返回Applied(snapshot)，重复返回AlreadyApplied。优先使用SDK稳定奖励标识；若SDK不提供，拟用局标识和请求标识进行本局去重，其可靠性须结合回调契约评估。网络或广告失败不写奖励，不阻断已有基础局面。广告服务回调先转换为内部结果，再由局写队列处理；关闭、奖励、后台事件允许乱序到达。等待达到产品批准阈值时进入明确的超时/待核对状态，但超时不能伪装成SDK已经关闭；恢复游玩和释放广告暂停原因的条件必须由真实SDK契约确定，未确认关闭前不发起重叠展示。权限及隐私选择由平台适配器处理，拒绝后重新评估广告资格，不默认禁止基础玩法。IAP不新增接口或页面。
【假设A04｜广告资格与迟到结果】候选为剩余时间大于0且当前奖励作用域尚未领奖时可申请；失败不消耗资格，广告期间冻结游戏时间，单次有效奖励加30秒。奖励作用域究竟按关卡编号还是单局计算、重开是否重置、超时后有效收据能否补发、终局与奖励并发优先级、进程重启后是否承认收据均待确认。旧局回调不得修改新局；对旧局是否记录待补偿奖励应另行决策。验证办法：先取得广告SDK的回调、关闭、线程、超时及奖励标识说明，再分别覆盖重复、乱序、迟到、取消、断网、后台和重开。

## 存档、配置与兼容迁移

【推导D09｜配置结构与校验】建议LevelConfig包含schemaVersion、configVersion、levelId、durationSeconds、boxCapacity、rewardSeconds、items[]、initialBoxes[]以及boxSupplyRule。物品字段建议为itemId、colorId、auxiliaryCode、resourceId、placement；箱体字段建议为boxId、colorId、resourceId、placement。durationSeconds=90、boxCapacity=3、rewardSeconds=30及物品数量上限30仅映射资料F03—F06中的样本规则，须随正式规则批准后写入配置；不生成10关的物品、颜色或箱体配置。玩法字段缺失不以零或隐式默认值补齐，返回ConfigInvalid；重复ID、未知颜色/资源、非正计时、容量非法、超出批准物品数均阻断开局。零物品、缺失箱体及补充规则不完整先列待确认，不自动胜利。配置校验分结构校验、引用校验和可完成性验证；没有箱体补充及布局规则时，不能仅靠结构合法判定可完成。设计token和动效参数放入独立表现配置，输入中的建议数值须经设计批准后才形成默认值。
【推导D10｜局内数据与持久化】建议SessionSnapshot包含sessionId、levelId、configVersion、revision、phase、remainingTime、score、itemsState、boxesState、pauseReasons、appliedActionIds及rewardState。所有容器建立受局生命周期约束的容量和清理策略；新局分配新sessionId，不能只把旧对象数值清零。局内状态首先作为内存数据；是否落盘采用假设A05。若批准持久化，另设SaveEnvelope：schemaVersion、gameBuildId、configVersion、payload和完整性校验字段，广告待核对收据与局面一并定义提交顺序。校验和只用于发现损坏，不等同于防作弊或签名。SDK密钥、广告原始身份信息及不必要个人标识不得进入通用局快照或普通日志；持久化和日志字段由工程与隐私负责人按实际SDK逐项核对。
【假设A05｜进程终止边界】候选首版仅保证当前进程内的局面和奖励去重，不承诺杀进程恢复；若批准此范围，冷启动不显示继续游戏，相关提示及奖励作用域须由产品明确。验证办法：策划确认是否需要恢复局面、保留加时资格或补发奖励；若需要，增加持久化设计、崩溃一致性及恢复任务。资料F07不含云存档，不能据此推断不需要本地存档。
【推导D11｜兼容、迁移与回滚】当前旧存档与配置格式未知，不能声明已有字段或迁移已兼容。若新增持久化，建议按已发现的版本逐级迁移，保留迁移前副本，使用目标平台支持的安全替换方式提交；迁移失败保留原数据并给出恢复选择，不静默清空。高于客户端支持版本的数据不覆盖，旧客户端降级的支持矩阵需明确；迁移前备份不能直接等同于旧客户端可读。配置版本与存档绑定，升级途中不在活动局内替换规则；新版加载失败时仅回退到经确认与该存档兼容的配置。既有稳定字段不得借同名字段改变单位或语义，新增语义采用新字段或显式迁移。没有旧样本前，迁移实现与回滚可用性保持待评估。
【推导D12｜预算与数据采集】性能预算待补：目标帧率、拖拽反馈延迟、最低设备、内存峰值、包体、冷启动/开局耗时、加载超时和广告等待上限。每项登记设备、构建类型、场景、统计口径、阈值及负责人，不以缺失数据填零。建议测量最大配置、反复重开、广告往返和后台恢复，检查逐帧分配、资源峰值和订阅增长。埋点若获批准，采用level_start、drop_result、pause_change、ad_request、ad_result、reward_apply、level_end与ux_error；记录配置版本、局/动作标识、相对时间和原因，奖励实际提交后记录reward_apply，终局事件按局去重。采集范围、保留期限、上传条件和指标分母均待产品及隐私评审，不能将埋点提案写成已接入事实。

## 风险、缺口与能力边界

- 【推导D01、D02】虚构样本及静态方案被误当成真实项目批准基线，会使未确认规则进入开发或验收。
- 【推导D03、D09、D16】箱体数量、布局和补充机制未定，无法证明关卡始终有合法落点，也不能完整实现收纳事务或验证可完成性。
- 【假设A03、A04】落箱、归零与广告奖励的竞争顺序可能改变胜负，必须先形成批准预期。
- 【推导D08、D19】缺少真实SDK的关闭、收据、线程及超时契约，可能导致重复加时、卡等待、错误恢复或旧局污染。
- 【假设A04、A05、推导D22】奖励作用域和进程恢复未定，当前方案不能承诺跨进程奖励一致性或补偿。
- 【推导D04、D07】资源所有权、订阅及异步取消若未落到代码审查，可能产生迟到开局、跨场景引用或反复重开后的资源增长。
- 【推导D11】缺少历史存档和配置样本，不能确认迁移成本、稳定字段兼容或客户端降级可行性。
- 【推导D12、D21、D26】未知箱体数量与最大物品布局、真实资源及设备约束尚未共同验证，触控、可读性和性能均无达标证据。
- 【推导D13、D27】缺少工程、SDK、实际命令和设备条件，人日、交测时间及验证结果均不能确定。
- 未修改源码、读取本地工程、拉取/提交/推送 Git 或调用开发工具；仅基于输入文本提出技术方案。
- 未编译、构建、启动 Unity、运行测试或测量性能；架构和基线必须由工程负责人核对。
