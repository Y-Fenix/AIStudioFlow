# UX 与界面交互规范

## 目标用户路径与需求追溯

【推导D01｜交付定位与资料登记】本稿按所给 studioflow-design-2 业务材料形成 UX 静态设计建议。项目、版本与平台引用事实F01；资料来源为本轮 inputs 中的《PRD 与文本原型》及其“依据与判断”。事实F09中的日期仅登记为样本生成日期，不作为项目资料批准日期。工作室、正式资料日期、审批人及批准版本待补。下述页面、状态、参数和验收断言均为待审核方案；不将输入中的推导或假设升级为已确认业务规则。
【事实F01】项目为虚构示例《星屿收纳》，版本0.1，平台Android。
【事实F03、F04、F05】玩法依据为同色入箱、容量3、满箱移走加1分；错色或满箱返回原位且不扣分；首版10关、每关最多30件；每关90秒，全部收纳胜利、归零失败，切后台暂停。
【事实F06、F07】商业化路径为每关一次激励广告加30秒，失败或取消不奖励、网络失败可继续；范围不含IAP、社交或云存档。因此本方案不设置商店、购买、支付或购买恢复页面。
【假设A01｜用户】以偏好短时整理玩法的休闲玩家为候选用户，首局目标为理解匹配与满箱反馈，重复游玩目标为快速开始并识别局内状态；需访谈验证，不能据此声称用户需求成立。
【推导D02｜需求追溯与路径】沿用输入中的R01—R06作为追溯标识，不代表需求已批准。R01：P01开始页→配置加载→P02游玩页；前置为经确认的有效关卡配置。点击开始后锁定按钮，仅建立一个开局请求；配置失败留在P01，显示错误与重试；加载期间返回则使该次请求失效，迟到结果不得自动开局。零物品配置按待确认项处理，不直接显示胜利。
R02：P02选择物品→拖动→释放→逻辑判定；同色且有容量时提交收纳，达到容量时显示移箱与加分；错色、已满、无效落点或取消拖拽时回原位。落点反馈必须对应同一次判定，不能先播成功再回滚。箱体数量、补充位置与补充时机须先补齐。
R03：P02持续显示剩余时间→全部收纳或归零→P04结算。最后落箱与归零并发按假设A02待确认；尾箱未满按假设A05待确认。终局锁定后，残余拖动、广告点击与旧反馈均不能改写结果。
R04：P02暂停按钮或系统返回→P03暂停层→明确点击恢复→P02；切后台后的恢复行为采用假设A03。暂停中取消拖拽并恢复原位置。返回开始页和放弃当前局不是已确认功能，本稿不在暂停层直接增加可执行的放弃入口。
R05：P02广告入口→L01广告等待层或广告服务界面→奖励、失败或取消反馈→P02；若存在其他暂停原因则返回P03。奖励资格、冻结计时与重复回调处理采用假设A04；广告展示期间的关闭和系统返回服从经确认的服务能力，不承诺自定义关闭按钮。归零后不默认出现广告入口。
R06：P04显示胜负及得分；建议提供“重开”“返回开始”，但在重开清零、奖励资格与关卡入口规则确认前，仅作为文本线框中的待批准导航。重开拟创建新局并隔离旧局回调；返回开始拟进入P01。下一关、选关和教程不自动加入此路径。
【假设A02】最后一次有效落箱与归零同时发生时优先判胜利，须策划批准。
【假设A03】暂停冻结计时并禁止拖放；中断拖拽回原位；回前台保留暂停层，主动恢复才继续。仅讨论内存局面，进程终止恢复另行决策。
【假设A04】时间大于0且本关尚未领奖才允许请求广告；失败不消耗资格，广告期间冻结计时；成功回调只生效一次。超时、迟到回调、重开奖励资格及持久化去重待确认。
【假设A05】全部物品已入箱即可胜利，最后箱子不必装满；箱体补充与尾箱表现须共同确认。

## 页面结构与文本线框

【推导D03｜布局基准】建议以360×800dp竖屏内容区描述文本线框，尺寸均为建议值；不将dp视为截图像素或Unity坐标。外边距16dp，常规间距8/16/24dp，按钮最小触控区48×48dp、相邻触控区净距至少8dp；正文16sp、辅助文字14sp、标题24sp，行高建议约1.4—1.5倍。Unity中的缩放、字体单位和安全区换算由开发确定后核对真机。所有页面先扣除系统安全区，再进行布局。
【推导D03｜P01开始页，R01】信息层级：游戏名→主动作→状态说明。文字线框：顶部安全区；中部[星屿收纳／版本信息]；下部[开始，宽度填满内容区、高56dp]；按钮下方[加载或配置错误说明][重试，仅失败时出现]；底部安全区。开始后按钮文案变为“准备关卡…”，附加载指示；错误文案建议“关卡暂时无法开始，请重试”，开发日志另记录具体配置原因。页面不增加未经确认的关卡选择和继续存档按钮。
【推导D03｜P02游玩页，R02/R03/R05】信息层级：时间与操作状态→物品和箱体→得分与商业化入口。文字线框：顶部[关卡{编号}][剩余{秒}][暂停]，HUD建议最小高64dp；其下[得分{值}]；中部[物品区，按配置排布，物品触控区建议至少48×48dp]；下部[箱区：颜色名＋形状标记＋已装{数量}/3]；底部[看广告加30秒][资格或处理状态]；所有区域避开安全区。箱体数量不预设。先为HUD、箱区和广告按钮预留空间，再计算物品布局；最小目标设备无法容纳时阻断该布局验收，不通过缩小触控区或让拖拽区域滚动来掩盖问题。
物品被选中时加轮廓及抬起反馈；候选箱显示可放或不可放标记；得分只在逻辑提交后更新。反馈层预留不遮挡物品及箱体的位置，显示“颜色不匹配”“箱子已满”“未获得加时”等明确短句；不得只用颜色或震动表达结果。广告按钮显示“看广告加30秒”“处理中…”或“本关加时已领取”，资格未确认时不把假设包装成正式可用规则。
【推导D03｜P03暂停层，R04】文字线框：[遮罩下保留局面，但不可操作]→[居中卡片，建议宽度为内容区宽度、最大320dp]→[已暂停]→[恢复，最小高48dp]。后台返回可显示“已暂停，点击恢复继续”。遮罩点击不恢复；焦点限制在暂停层；恢复后回到暂停前有意义的控件或游戏区。放弃和返回开始待业务确认后另补确认流程。
【推导D03｜L01广告等待层，R05】文字线框：[不可操作的局面]→[广告处理中]→[请按广告页面提示操作]→[结果反馈区]。请求准备阶段与广告实际展示阶段分别记录；不以持续旋转图标暗示服务一定会返回。发生明确失败、取消或网络失败时显示“未获得加时，可继续游戏”；成功仅在有效奖励提交后显示“已加30秒”。关闭按钮、等待上限及恢复入口待广告服务确定，不绘制虚构的可用退出控件。
【推导D03｜P04结算页，R06】文字线框：[胜利／时间到]→[本局得分{值}]→[重开，待规则批准]→[返回开始，待规则批准]。结果和得分为首要信息，不用自动跳转截断阅读。重开和返回均采用点击后锁定并切换的建议；切换失败保留结果与重试入口。无需购买入口，失败页也不默认提供归零后广告复活。
【推导D11｜交付形态】以上仅为文本线框和交互规范；设计图、Figma文件、可点击原型、资源图和客户端预览均不作为本次已产出物。

## 页面与组件状态矩阵

【推导D04｜状态矩阵使用规则】以下每行按“进入条件｜显示｜允许动作｜退出条件”描述。共享状态由对应页面继承，再按页面特例覆盖。状态标签与数据校验应分离：显示“成功”不能自行授予奖励或推进关卡。暂停和广告相关状态受假设A03/A04约束。
S01默认：P01待开始、P02可玩、P03已暂停或P04结果已确定｜分别显示开始、局面、恢复、结果导航｜仅接受当前页面动作｜有效动作进入下一状态。
S02加载：P01正在准备配置或P04正在切换新局｜原布局保留，主按钮显示处理中并禁用｜允许P01取消尚未生效的加载，其他操作按页面限制｜有效结果进入目标页，失败进入S05，取消回原页；迟到结果丢弃。
S03空：P01没有可用配置，或P02收到零物品、缺失箱体等未获批准的配置｜显示“关卡暂时无法开始”，不展示可操作空局｜重试或返回P01｜配置通过批准的校验才开局。P04得分为0是有效数值，不作为空态。
S04禁用：请求未结束、已终局、广告已领奖或处于暂停｜控件保留标签，并用文字说明原因；游戏区禁用时有遮罩或状态提示｜允许查看说明及可用恢复动作｜阻塞原因解除或离开本局；颜色变灰不能作为唯一说明。
S05失败：配置读取失败、页面切换失败、拖放被拒绝或广告明确失败｜配置/切换显示就地错误与重试；错放回原位并显示原因；广告提示未获加时｜执行对应重试、继续或返回动作｜操作完成且状态重新校验。重试不重复提交已成功的收纳或奖励。
S06成功：有效落箱、满箱、广告有效奖励、终局结果提交或页面切换完成｜分别显示收纳确认、得分变化、加时、结果或目标页｜反馈不拦截下一次合法操作，终局除外｜反馈结束或被更高优先级状态替代；成功动画不决定数据提交时间。
S07离线：检测到网络不可用或广告请求网络失败｜局内保留当前局面，广告入口显示网络状态；是否可用配置由本地资源方案决定｜资源齐备时继续本局，广告重试仅在服务与资格均允许时开放｜网络恢复并重新检查服务状态；不自动申请广告。网络断开本身不额外扣分或清空局面。
S08权限：如选定广告服务出现系统权限或隐私选择界面｜说明用途、可选择项及返回后的状态；不预设具体权限种类｜允许系统支持的允许、拒绝或取消｜回到局面或暂停层并重新评估广告可用性；不得默认把拒绝权限当成禁止基础游玩的理由。实际权限需求待服务方材料确认。
S09长文本：字体放大、本地化扩展或系统服务文案较长｜按钮允许换行并增高，错误和暂停说明在各自容器内滚动，HUD必要时拆成两行｜读屏、滚动及当前合法动作｜内容恢复可容纳后回常规布局。时间、得分及关键动作不得截断。
S10重复点击/重复回调：同一开始、恢复、广告、重开被连续触发，或同一奖励结果重复到达｜保持同一处理中状态，不叠加弹层或奖励提示｜只允许首个有效请求推进；可继续使用不冲突的控件｜该请求结束或失效。旧局回调不得退出新局页面。
S11恢复：系统回前台、广告关闭或短暂中断结束｜按暂停原因集合显示P03或恢复可玩；进程重启不显示未经证实的“已恢复”｜由玩家执行已批准的恢复动作｜所有暂停原因解除后才进入游玩。恢复失败需说明可保留与不可恢复的内容，具体策略待定。
S12焦点/悬停：控件获得键盘、手柄焦点，或存在指针设备悬停｜显示清晰轮廓和文字标签，悬停不触发动作｜确认键激活；移开或导航切换焦点｜失焦回到原状态。触屏功能不得依赖悬停。
S13选中/拖拽：物品被合法按下且开始移动｜选中轮廓、原位占位及候选箱提示｜移动、释放、取消；不接受第二个并发拖拽｜有效提交、回滚、暂停或终局时清除选中。
【推导D04｜页面覆盖】P01覆盖S01—S05、S07、S09、S10、S12；P02覆盖S01、S03—S13，其中空态为配置阻断；P03覆盖S01、S04、S09—S12，背景继承被暂停的P02状态；L01覆盖S02、S04—S11，交互能力以服务确认结果为准；P04覆盖S01、S02、S04—S07、S09、S10、S12。各页面无适用业务的状态不强造入口，例如P04离线仅作环境提示，不阻止阅读本地结算。

## 交互、动效与输入反馈

【推导D05｜输入与返回优先级】P02建议仅允许单指单物品拖拽；第二触点不建立新拖拽，暂停按钮和系统生命周期事件仍可中断。点击物品仅选中，长按不新增业务功能；拖拽识别建议移动阈值8dp，待触控实测调整。释放时按实际命中区域提交一次；不扩大到相邻箱造成歧义。拖出游戏区、触点取消或暂停均回原位。箱体接收区及相邻箱间距由批准布局标注。
返回处理顺序建议为：系统/广告服务界面按其能力处理→顶层模态层→取消当前拖拽→P02进入P03→其他页面按已批准导航处理。取消拖拽后不继续穿透触发暂停。P03返回键保持暂停并聚焦“恢复”，不静默开始计时；P01返回遵循确认后的Android退出行为；P04返回去向待R06批准，不能由开发自行推定为下一关。广告界面能否关闭、能否响应返回键须单独验证。
【推导D05｜层级与焦点】建议视觉层级为基础页0、局部反馈10、暂停模态20、广告等待模态30、系统/服务界面由平台管理。全局状态控制避免同时打开相互冲突的模态；局部提示不抢占焦点。打开暂停层记录原焦点并限制焦点范围，关闭后恢复到原可用控件，原控件失效时移至游戏区或主动作。模态遮罩阻断底层触控，暂停遮罩点击不关闭。
【推导D05｜键盘、手柄与读屏】Android触控为本方案主要输入；键盘/手柄是否正式支持待定。若纳入，方向键或摇杆移动焦点、确认键选择物品再选择目标箱，取消键撤销当前选择；焦点次序按HUD→物品→箱体→广告入口。读屏标签建议包含“物品，颜色名，形状名”“箱子，颜色名，已装数量，容量”；为拖拽提供可评估的“选择物品→选择箱体→确认放入”替代操作，须评审其范围和实现能力。时间不逐秒抢占播报，可建议在30秒、10秒及终局时播报；阈值须批准。本期无文本输入需求，不主动唤起软键盘；系统界面若唤起键盘，先关闭键盘，再处理应用层返回。
【推导D06｜建议反馈时序】按下态目标在100ms内出现；拖动物品随手指逐帧更新；错放回原位动画建议120—180ms；满箱移走建议160—240ms；暂停层过渡建议120—180ms；局部文字反馈建议停留约2秒，可由新同类反馈替换。上述均为建议参数，不是已测响应或性能承诺。时间、分数和奖励在逻辑确认时更新，不等待表现动画完成。等待型操作在进入等待状态时即显示原因，不能以无反馈按钮代替加载状态。
终局、暂停、切后台及页面销毁应取消拖拽和未完成的表现动画，并立即对齐到最后一次已提交的逻辑状态；已提交的收纳不因动画取消而回滚。不同反馈重叠时优先展示终局，其次暂停/广告状态，再展示得分或错误；被替换的关键结果保留在当前状态文本中。
减少动态效果方案建议关闭抬升、粒子、缩放及位移动画，改用静态轮廓、文本与数值更新；不得因关闭动画延迟游戏逻辑。声音和震动只作补充，沿用系统能力或经批准的设置，不以它们作为唯一反馈。
