# 玩法与商业化方案

## 玩家动机与核心循环

【事实 F01、F02】本方案对象为虚构练习项目“星屿收纳”0.1，平台为Android；资源约束为1策划、1美术、2Unity开发、1测试，MVP两周。资料不能作为真实市场或玩家观测。
【事实 F03、F04】输入规则：同色物品拖入同色箱，每箱容量3；满箱移走加1分；错色或满箱投放返回原位且不扣分。首版10关，每关最多30物品、90秒；全部收纳胜利，计时归零失败，切后台暂停。
【假设 A01：目标玩家与体验提案】暂以偏好短局分类整理的玩家作为招募方向，验证“辨认物品—匹配箱子—拖放—清空”的理解成本，不据此确定年龄、地区或市场规模。核心决策为选择下一个物品及其目标箱；正确投放显示入箱与容量变化，满箱显示移走和加分，错误投放回弹并提示正确匹配依据。颜色之外增加图形标记，先验证可辨识性。
【假设 A02：状态与边界提案】状态设为开始页→进行中↔暂停→胜利或失败结算；广告请求和播放是进行中的暂停子状态。拖放提交时原子检查物品未结算、目标颜色匹配、容量未满；同一物品只允许成功入箱一次。输入处理前先更新有效游戏时间：剩余时间为0时进入失败并拒绝新投放；时间仍大于0且最后一件成功入箱时进入胜利。同帧多次操作、拖拽途中切后台及结算后的迟到输入均不得重复改变结果。
【推导 I01：规则缺口】满箱移走后的补箱方式、尾箱未满时的表现、最后一次拖放与计时归零的优先级均未明确，不能当成已批准规则。建议每种颜色使用一个有效箱，满箱后若该颜色仍有待收纳物品则补同色空箱；首版关卡按每种颜色物品数为3的倍数制作，避免尾箱争议。
【事实 F10、F11；推导 I02】合成摘录提示颜色辨识和自愿看广告值得验证，但不能证明真实需求。首局理解和加时干扰应作为本轮验证重点。奖励回路建议仅保留满箱得分、过关反馈和进入下一关，不新增货币与长期养成。单局有效操作时间以90秒为基线；若成功获得一次加时则最多增加30秒，广告观看和暂停使现实经过时间可能更长。

## 关卡、成长与难度

【假设 A03：关卡与引导建议参数】保留10关框架，建议物品总数依次为6、9、12、15、18、21、24、27、30、30；全部属于待测配置，每种颜色的物品数须为3的倍数。第1关使用2种易区分颜色及对应图形；第2—3关验证连续操作；第4—6关逐步增加可见物品和布局分散程度；第7—10关在已验证的颜色集合内调整数量和位置。相邻关先只改变一个难度变量，不同时增加颜色数、数量和遮挡。颜色数量及色值在素材确认后补齐，不预设色差数值。
【假设 A04：新手引导与机制解锁】首局以一次手势提示引导拖放，首个正确操作后收起；错误操作显示目标标记，再次成功后收起。引导不自动代操作，玩家可跳过。首版只逐步开放布局复杂度，不加入新失败条件；暂停、重试和自愿加时入口不设置付费或进度门槛。
【假设 A05：失败恢复与结算】失败结算提供直接重试和返回开始页，重试重置本局物品、箱子、分数与90秒计时；成功结算提供下一关，第10关提供完成提示及重玩。建议先不在计时归零后提供复活，以保持“归零失败”的明确边界；广告加时在归零前触发，具体见monetization。重玩是否重新获得广告额度仍须确认。
【推导 I03：可检查的关卡约束】关卡配置须满足0<N≤30、各颜色数量之和等于N、每种颜色数量可被3整除、每种颜色均有对应箱；这些是所提关卡方案的校验条件。空关、超量、缺失颜色箱或非法物品应在进入计时前阻断并显示可返回入口，不能把空关当自动胜利。
【假设 A06：难度调节与异常处理】首轮采用固定关卡，不启用动态难度。根据首次尝试的无加时胜率、错误投放率和剩余物品数定位问题：错误集中于某颜色时先改辨识提示，正确操作仍普遍超时时再减少数量或缩短移动距离。不得以增加广告需求为调难目标。来电、切后台和主动暂停均冻结有效计时；恢复后重置拖拽到合法位置，避免物品悬空或重复入箱。上述行为需进入验收用例，目前不视为已实现。

## 经济与数值约束

【事实 F03、F05、F06】输入给出的数值资源包括满箱加1分、单箱容量3及广告加时30秒；范围排除IAP、社交和云存档。输入没有给出货币、商店、消耗道具或离线收益规则。
【假设 A07：最小经济范围】建议将分数定义为单局表现记录，消耗为无、单局结束后只保存关卡最好成绩，不跨局累加成可消费余额；不新增金币、体力、付费道具或离线产出。广告加时直接记入当前局剩余时间，不形成背包道具。以上是范围提案，不代表已有经济系统。
【推导 I04：守恒与上限】令N为初始物品数，W为尚未入箱数，B为当前箱中物品数，C为已经随满箱移走的物品数，任一合法状态应满足N=W+B+C；设已结算满箱数为F，则C=3F，单局分数S=F，故S≤floor(N/3)≤10。条件是没有新增或重复生成物品、没有重复计分；采用各颜色数量可被3整除的提案时，胜利应满足W=0、B=0、S=N/3。建议样例：N=6时，一个满箱后W=3、B=0、C=3、S=1；全部完成后S=2。该样例是规则推算，不是运行结果。
【假设 A08：时间与领取账本】令P为本局有效游玩秒数，G为已成功记账的加时次数，剩余时间T=max(0,90+30G−P)，0≤G≤1；暂停及广告状态不增加P。加时只有在合法完成回调且未领取时将G由0改为1；拒绝、取消、失败和重复回调均不增加G。建议算例：完成回调前T=10秒，暂停期间完成广告后T=40秒。广告额度在重试间是否重置，需先明确“每关”的口径。
【假设 A09：离线与本地存档】建议本地保存已解锁关卡、最好分数、引导完成标记及存档版本；局内状态暂不跨进程恢复，重新启动后从开始页重新开局。断网仍可游玩已提供关卡，广告不可用时保留继续和重试路径，不补发未验证奖励。关卡解锁与最好成绩在胜利结算时原子写入；进程中断不得重复结算。损坏存档保留可诊断信息并提供明确的重置选择；版本变化保留可映射进度，不强行套用不兼容的局内状态。
【推导 I05：待测敏感项】经济校验重点为重复回调、多次拖放、广告后切后台、重试和跨版本载入；难度敏感项为物品数量、拖动距离及颜色辨识。没有收入与获客数据时，只能定义CAC=同口径获客支出/新增用户数、LTV_H=同一新增队列在H天内的累计净收入/队列人数；H、净收入扣项和归因窗口须另定，不能据此给出收益或回本结论。

## 广告与 IAP 触点

【事实 F05、F06】输入规定每关完成激励广告最多加时一次、加30秒，失败或取消不奖励，网络失败仍可继续游戏；首版不含IAP。
【推导 I06：触发冲突与待决口径】输入未明确广告在失败前还是失败后出现，也未明确“每关一次”是每次开局、每次重试还是整个存档周期。失败后复活会增加结算后恢复状态，必须单独确认；本稿优先提出失败前自愿加时方案，不把合成竞品A的失败后加时视为项目规则。
【假设 A10：唯一广告触点与建议频控】建议仅在进行中、0<T≤15秒且当前局未成功加时时，显示“自愿看广告，加30秒”按钮；15秒为建议阈值。按钮不自动弹窗、不遮挡物品，点击前展示价值和可取消路径。建议按每次开局最多成功领取一次设计，且同一时刻只允许一个广告请求；该额度口径须由策划确认后才能进入配置。无广告或未选择观看时按原规则继续，不设置插屏、横幅或额外广告入口。
【假设 A11：请求、拒绝与异常规则】主动点击后冻结计时和拖放，保存当前局标识及请求标识；取消确认直接回到原局且不奖励。请求加载建议最多等待5秒，超时或网络失败显示简短说明并恢复原局，禁止自动重试。广告播放期间游戏维持暂停；仅SDK定义的有效完成回调可尝试一次加时，关闭回调本身不代表完成。处理完成、失败与关闭事件时，先按请求标识归并，再按原子领取标记决定是否加时；乱序、重复、上一局迟到回调均不得重复入账或作用于新局。切后台后保持暂停，回到前台再完成恢复流程。
【假设 A12：权益与付费边界】首版不设置商品、价格、支付入口或付费恢复按钮，也不把广告加时宣传为永久权益。若后续新增IAP，应另立方案，明确商品类型、订单验证、重复订单幂等、退款撤权及可恢复商品的恢复机制；不能直接复用广告回调发放付费权益。
【推导 I07：价值、成本与平台核项】玩家以观看时间换取当前局30秒操作时间；可能收益是增加完成机会，体验成本是操作中断、等待和恢复后的注意力切换。实际观看时长、填充率及收益未知。目标地区和年龄范围确定后，需核对Android具体分发渠道、广告SDK的年龄适用条件、隐私同意、数据采集、个性化广告及未成年人限制；核项未完成时只验证模拟流程，不据此批准真实广告配置。

## 风险、缺口与能力边界

- 【推导 I01、I06】补箱、尾箱、同帧超时、加时触发及广告额度重置范围未定，会直接影响玩法状态、关卡可解性和验收预期。
- 【假设 A10、A11】15秒入口、每次开局一次及5秒加载上限均为建议，不能当成现行配置；SDK回调语义尚需适配核对。
- 【推导 I07、I10】目标地区、年龄、分发渠道和SDK条件缺失，真实广告配置的适用性及隐私约束尚不能确认。
- 【推导 I08、I09】缺少工程、安装包和素材授权材料，无法判断现有实现、兼容性及两周工作量；模拟广告流程不能证明真实接入成功。
- 【假设 A03、A14、A15】关卡参数、目标玩家和实验招募规模尚未验证；探索样本不能支持总体留存、广告无损害或市场需求结论。
- 【推导 I04、I05、I11】重复投放、回调乱序、跨局回调和存档中断可能破坏资源守恒；需以实际执行证据检查，文本方案不能标为通过。
- 【推导 I05；假设 A16】没有真实收入、获客和留存样本，不能承诺转化率、LTV、收益或回本时间；IAP不属于本轮范围。
- 未执行外部调研、玩家测试、经济模拟、收入测算验证或广告/IAP 接入。
- 参数与收益假设仅为文本方案，需策划确认和真实样本验证后才能用于上线决策。
