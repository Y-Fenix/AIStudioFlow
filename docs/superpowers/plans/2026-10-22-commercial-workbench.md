# 商业工作台实施计划

> 执行方式：使用 subagent-driven-development 划分独立部门实现与审查；公共契约由主代理维护。用户已授权推荐方案直接执行，禁止 Git/Figma 操作。

**目标：** 四部门及自定义流程可按诚实能力边界运行，形成有证据、可交接的专业交付。

**架构：** 公共交付契约负责结构/引用校验和 Markdown；部门执行器负责各节点职责；公共工作区负责准备检查、预览与常驻操作。沿用权限与现有存储。

**技术：** Python / SQLite 持久化队列、原生 JavaScript/CSS、Playwright、本机已配置模型。

- [x] 公共契约：先在 `tests/test_deliverable_contract.py` 验证空输入、不完整段落、错误引用、一次修正上限；实现 `server/core/deliverables.py` 并从 integrations 公开。
- [x] 部门实现：分别在 `tests/test_PRODUCT_executor.py`、`test_DESIGN_executor.py`、`test_DEV_executor.py` 补四节点调用/默认 Skill/错误输入，修改对应 adapter.py、manifest 和 README；运行各自边界与契约检查。
- [x] 平台执行链：临时数据库覆盖真实 registry、队列、十二节点、自定义引用、过期保存与撤权；扩展质量报告但不改变原字段含义。空交付不得成功。
- [x] 工作区交互：测试在先；新增独立公共工作区模块，紧凑 Skill 菜单、交付预览、准备检查、常驻动作；修复后台完成覆盖草稿、请求重入、失败缺少恢复指引。
- [x] 首页与入门：真实运行能力/进度与推荐下一步，游戏版本示例资料及人工交接指引；不插入演示数据冒充结果。
- [x] 自动回归：最新 589 项 Python、89 项 JS、四部门边界检查通过；前期六套隔离浏览器覆盖主题/窄屏/权限/冲突，格式恢复修正后复跑商业工作台浏览器；详见验收文档。
- [x] 真实模型烟测：首次失败后定向修正引用提示；第二次试跑经历一次真实空闲超时及有限重试，最终 PRD 生成并通过结构/引用校验，保留完整样本和耗时。随后隔离自定义流程真实完成 UX→技术方案自动交接，保留两份样本。其余九个文字节点首批六项完成、三项 JSON 失败，三项在修复后复测完成，其中版本交付自动修正一次。累计十二个文字节点均有真实模型完成记录，但输入均为虚构练习资料，仍不代表四部门真实游戏全链路质量或稳定性验收。
- [x] 长任务进度：部门队列与自定义流保存白名单诊断；模型/重试/接收量/有效响应间隔可见，不变更业务修订，不污染下一步骤或晚回调；隔离后端和浏览器验证通过。
- [x] 格式失败恢复：完整响应的 JSON 解析错误与章节/引用错误共享一次定向修正，仍严格校验；传输失败不误触发格式修正，二次错误不循环，超大正文不重发。
- [x] 阅读稳定性：真实浏览器先复现状态更新清除文字选区和证据展开状态，再修复相同内容重复重建；浏览器及 89 项 JavaScript 回归通过。
- [ ] 后续真实业务试点：十二节点及四部门跨部门链的业务质量、中转稳定性和外部工具，仍需实际资料/工具及负责人验收，不以替身测试或单次烟测代替。
- [x] 审查：先逐项规格核对，再代码质量审查，修复问题后复验；文档同步当前能力，建立次日审批与验收清单。

每项遵循先失败测试、再实现、后回归。外部副作用与新增授权不执行，单列次日审批；任何真实验证缺口保持未完成标记。
