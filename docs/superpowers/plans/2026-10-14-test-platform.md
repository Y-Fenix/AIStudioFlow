# 测试闭环平台实施计划

> 执行方式：当前会话顺序执行，使用 executing-plans；用户已授权逻辑开发，不再请求重复确认。禁止 Git 提交、推送、拉取；不修改 Figma。目标游戏仓库默认只读。

**Goal:** 将已确认的 A 界面接入持久化六步工作流及真实需求、代码测试、GM、飞书提单和回归证据。

**Architecture:** Web 前端负责项目选择、工作区、证据与决策；Python 服务负责 SQLite 持久化、任务队列和连接器；本机执行器通过 Codex CLI 对指定分支逐用例静态审查，不启动 Unity 或编译测试。生产工作区不包含 470 条演示数据，原型单独保留。

**Tech Stack:** Python、SQLite、HTTP API、HTML/CSS/JavaScript；文件解析库按格式引入；模型通过配置的服务调用，飞书通过 lark-cli，GM 通过已验证的 MCP 客户端连接。

## 已确认界面

A 布局、可折叠侧栏、项目搜索弹窗每页 5 个、新增/选择按钮并排、用例每页 10/20/50/100、流程箭头与选中背景、带不透明底板吸顶、弹窗锁滚动且保持页面宽度、外部遮罩关闭。项目标题不重复展示，左栏不重复六步入口。

## 文件边界

- `server/app.py`：本地 HTTP 服务与静态文件、路由分发。
- `server/store.py`：SQLite 数据模型及事务。
- `server/workflow.py`：节点门禁、决策、失效、重试与取消。
- `server/jobs.py`：持久化任务领取、状态与进程句柄。
- `server/requirements.py`：来源版本、解析、测试点与覆盖映射。
- `server/model.py`：模型调用及结构化输出验证。
- `server/execution.py`：代码指纹、执行映射、进程与报告读取。
- `server/triage.py`：根因候选、人工确认与筛选。
- `server/bugs.py`：草稿、发布意图与远端记录对应。
- `server/regression.py`：待验证监听、修复批次和用户验证决定。
- `server/connectors/lark.py`、`gm.py`：独立外部接口与凭据脱敏。
- `web/index.html`、`styles.css`、`app.js`：真实工作区界面。
- `tests/`：状态机、覆盖、幂等、报告映射及集成测试。
- `data/`：本地数据库和证据，不加入源码交付。
