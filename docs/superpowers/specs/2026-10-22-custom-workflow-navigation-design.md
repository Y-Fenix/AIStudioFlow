# 自定义工作流：首页与节点导航设计

日期：2026-10-22。状态：用户已确认并实施；实际验证范围见 [验收记录](../../custom-workflow-navigation-acceptance.md)。

## 目标与现状

用户要求：自定义流不出现在项目总览；支持创建很多个工作流，每个工作流进入后，像测试部门一样展示节点流，再进入具体节点操作。

现状检查：项目总览将自定义流作为第五张部门卡；左侧自定义流直接进入积木编辑器，多个流以横排名称按钮切换。工作流、业务节点、节点内部积木混在同一操作面。

## 方案比较

| 方案 | 优点 | 代价 / 问题 |
| --- | --- | --- |
| 工作流列表 → 工作流首页 → 节点工作区，编辑器独立进入（推荐） | 符合部门使用习惯，支持大量流程，使用和配置各有入口 | 需要新增列表页、首页和节点视图 |
| 左侧直接展开所有工作流 | 少一次进入列表的点击 | 大量工作流挤占部门导航，搜索和分页仍要另做 |
| 保留编辑器，顶部加节点预览 | 改动较小 | 日常使用仍被编辑功能占据，不能解决层级混乱 |

## 页面层级

```text
项目总览：产品部门 → 设计部门 → 开发部门 → 测试部门

左侧「自定义工作流」
  └─ 工作流列表
       ├─ 版本质量验收
       │    └─ 工作流首页：需求确认 → 用例 → 执行 → 归因 → 提单 → 回归
       │         └─ 节点工作区：输入 / Skill / 执行 / 交付 / 操作日志
       ├─ 竞品立项评审
       └─ 商店素材制作

工作流首页 → 编辑流程 → 节点排序、增删和节点内容配置
```

自定义工作流是流程集合，不是第五个部门。项目总览移除其卡片、介绍文案及下方搭建入口；四部门之间现有协作关系保留。左侧保留一个「自定义工作流」入口，不随工作流数量增加导航项。

## 工作流列表

- 仅列出当前项目中有权查看的流程，默认最近更新排序。
- 顶部提供名称搜索、最近运行状态筛选和新建工作流。
- 默认每页 10 条，支持 10 / 20 / 50 条；搜索和筛选后回到第一页，归档后夹紧有效页码。
- 每行展示名称、简短说明、节点数、最近一次运行状态、更新时间和进入入口；没有运行记录则显示「尚未运行」。
- 复制、重命名、归档放入更多菜单，按服务器权限展示和检查。复制只复制配置，不复制运行输入、结果或审批记录。
- 新建可从空白或有权使用的团队模板开始；没有工作流时显示创建入口，权限不足时说明原因。
- 返回列表保留搜索、筛选、页码和滚动位置；不再横排堆积所有工作流名称。

## 单个工作流首页

顶部用紧凑标题区展示流程名称、说明，提供返回列表、运行记录、编辑流程和开始运行 / 继续本次运行。不复刻部门首页的大幅宣传图。

主体复用部门节点卡片的视觉结构：编号、名称、来源部门、交付物、进入节点。卡片之间显示方向箭头及「自动执行 / 手动继续」开关。节点较多时横向滚动，移动端使用单列布局，明确保留执行顺序。

首页默认展示最近一次运行，也可选择具体历史运行。所有节点状态和交付来自同一条运行记录，不拼接不同批次。完成不等于已获人工批准；沿用平台状态配色，选中样式与执行状态分开表达。

手动继续在上一步成功且必要审批通过后，提供居中的「继续下一节点」。自动执行也不能跳过人工输入、审核、证据或权限门禁。失败、中断或取消均不会触发下一节点。无权限、来源失效或依赖未满足时，禁用按钮并显示具体原因。

未运行时可进入节点查看配置和准备资料；不会因点击卡片自动启动模型。新运行使用已保存配置；查看历史时展示该次运行快照。活动运行使用已冻结的节点及开关配置，编辑保存仅作用于下一次运行。

## 业务节点与内部积木

工作流首页展示业务节点，不把每一个输入框、检查清单或模板都当成业务节点。

两种节点来源：

1. 引用已有部门节点：显示来源部门和节点名称，继承来源执行能力及默认 Skill；执行仍需来源权限。
2. 新建自定义节点：设置名称、说明、交付要求，在节点内部组合输入、AI、清单、模板、审核、工具等积木，并配置本节点 Skill。

示例：「竞品分析」是一个业务节点；它内部的资料输入 → AI 分析 → 检查清单 → 人工确认不占首页四张节点卡。

每次加入节点都有独立实例 ID；同一来源节点可重复使用。流程中的输入、Skill 覆盖配置、结果和日志独立保存，不因编辑流程实例而修改原部门节点。Skill 支持选择、导入、导出及恢复来源默认；引用更新须显式确认，活动运行及历史快照不跟随变化。

测试固定节点保留现有真实批次与证据依赖。进入时提供关联批次、打开原测试工作台和返回当前流程的入口；不能用通用 AI 节点冒充已执行真实测试或绕过提单、回归审核。

## 节点工作区

- 面包屑：自定义工作流 / 流程名称 / 节点名称；提供返回流程。
- 顶部吸顶展示紧凑节点条，可切换查看节点；切换查看不改变执行游标。
- 中间展示当前节点输入、Skill、实际执行能力、结果、证据与缺口。来源执行器缺失时明确标示需人工交付。
- 右侧为当前运行、当前节点的操作日志，北京时间展示；轮询更新不重建正在编辑或滚动的区域。
- 人工提交、审核、继续、重试分别显示真实状态和权限条件。历史运行只读，不混入新配置草稿。

## 编辑器与兼容边界

现有搭建器作为「编辑流程 / 编辑节点内容」复用，日常进入工作流不默认打开搭建器。导航离开前提示未保存修改；保存后返回流程首页。

这是对现有工作流的增量设计，不另建一套运行系统。保留流程、积木、源部门节点和运行记录的稳定 ID。旧流程中的部门引用映射为业务节点；连续的顶层通用积木在新视图中归为一个自定义任务，保存原积木 ID 和顺序。旧运行仍按原快照读取，不能重新执行后伪装成迁移成功。

实施前需明确新增节点实例配置、Skill 覆盖、转移开关的持久化契约与幂等迁移，并通过历史数据兼容测试；不在本次设计阶段修改数据库。现有配置 revision 是配置修订号，不冒充项目发行版本。

权限沿用工作室 / 项目 / 部门 / 节点 / Skill 的授权原则；拥有工作流编辑权限不代表获得源节点或 Skill 的使用权限。新增节点实例资源时需补服务端授权契约，禁止仅靠前端隐藏按钮。

## 验收标准

1. 项目总览及其下方入口均不再展示自定义流，四部门顺序不变。
2. 准备 100 条工作流列表测试数据，验证搜索、筛选、分页和返回位置；侧栏不随数量增长。
3. 点入任一流程先见节点流首页；编辑器仅从明确编辑入口进入。
4. 不同流程、重复节点实例、不同运行间，输入、Skill、结果、日志均不会串用；状态来自所选运行。
5. 自动 / 手动转移有真实运行器测试，人工门禁、失败、撤权及测试证据依赖不能被绕过。
6. 旧流程、旧运行深链、模板来源和历史结果可访问；迁移重复执行不会重复创建节点或丢失积木。
7. 验证窄屏布局、长节点流、ESC 关闭弹窗、滚动位置及轮询不闪烁。
