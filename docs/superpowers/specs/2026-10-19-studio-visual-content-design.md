# 部门视觉与工作台内容管理设计（已确认）

## 部门首页标识

保留 ATELIER 浅色作为默认。用同一网格和线条体系设计五个部门专属 SVG 标识：产品为调研雷达与需求卡片；设计为画板与钢笔；开发为代码窗口与分支；测试为放大镜、勾选清单与回归环；发行增长为漏斗与趋势线。

每个部门顶部用对应标识替换当前通用文字水印，呼应其职责；侧栏/卡片使用同体系简版图标。沿用已确认的模块高度与布局，不再增设占空间的统计区。图标是界面设计，不伪装成真实业务数据。

## 两套替换主题

ATELIER 保留。原 FORGE 替换为 CONTROL：石墨灰底、清晰分隔线、克制的琥珀重点色；原 SPECTRUM 替换为 EDITORIAL：暖白与灰褐底、墨色文字、低饱和青绿重点色。两套都按完整页面设计和验证，包括首页、节点、权限后台、弹窗和表格，不仅替换配色卡。

取消漂浮装饰和夸张发光；通过排版、边框、间距和状态层级表达专业感。浅色/深色均保留清楚的输入边界与可读状态颜色，不能只靠颜色表达成功失败。

## 所有工作台内容的增删授权

推荐把“增加/删除”定义为管理工作台结构和用户维护的内容条目：工作室、项目、部门在本项目的启用状态、节点、Skill、工具入口、首页自定义信息块、用户上传的需求来源和手工交付条目。平台管理员默认可操作，其余成员不因部门身份自动获得这些管理权限；可按组织范围授权个人或部门，允许与删除独立撤回。

已有工作流程中的“保存输入、生成产物、审核、执行”继续由对应 edit/execute/approve 控制；它们不因产出一条结果就等同“新增工作台结构”。如果希望连这些产物的首次保存也要求独立 create 权限，需要明确选择更严格方案并迁移现有角色权限。

删除默认归档，历史可追溯；有活动任务或下游引用时提示影响并拒绝破坏性删除。部门停用是当前项目配置，不删除仓库模块，不修改其他项目。静态平台壳的登录区、授权校验、错误提示、操作审计和必要的确认按钮不作为可随意移除的业务内容；审计不是可由普通内容权限清空的工作区条目。

新增工具仍仅允许校验过的 HTTPS 链接；新增首页块使用纯文本/受限字段，不接受脚本或任意 HTML。部门负责人通过原有独立模块契约开发专用内容，无需修改公共权限和数据库。

## 验证

三主题与五部门标识在桌面、窄屏、节点、后台和弹窗实测；图标带可访问说明，装饰标识不影响操作。内容增删验证默认拒绝、管理员默认允许、按人/部门授权、撤回、跨项目隔离、并发版本冲突、引用保护和历史保留。现有静态测试证据门禁不得被内容删除入口绕过。
