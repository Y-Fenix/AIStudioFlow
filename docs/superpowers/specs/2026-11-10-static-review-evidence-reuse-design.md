# 静态审查证据复用

用户已授权按只读诊断确认的方向优化，完成后由用户运行测速。当前任务不取消、不自动启动新模型任务，不执行 Git 或 Figma 写入。

## 方案与边界

增加并发只增加吞吐压力；提高探索上限会增加大请求和等待。首期采用基于精确关联的源码复用，而不是将多条用例合成一个未经逐条校验的结论。

- 分组仅使用显式 module，或用例已有的精确 point_ids；没有关联信息时独立处理，不从标题猜功能模块，不修改持久化用例。
- 同一主关联组最多一个在途审查，不同组最多三路并发，结果仍按原始用例顺序返回。当前组后续用例可从前一条审查的已读源码开始，仍独立请求模型并校验所有断言。
- 每个 execute_static 实例有独立证据池，不跨批次或项目。池中只放真实源码及哈希，不放模型结论、需求判断或审核状态。每次取出重新读取并校验哈希、允许路径及原文，变化后失效。
- 每条用例最多种子120KB，证据池有限容量；同文件片段合并时保留原始行号。元数据或缓存不能作为代码结论。
- 跨关联组不自动灌入源码；本用例搜索命中此前已读的位置后，可取回已校验片段，每轮最多4个文件、120KB，仍受每条700KB限制。执行内全局源码片段池最多128个文件、4MB；关联组池最多32个键，每键120KB。
- 模型请求去除搜索命中中已在 sources 对应行逐字出现的 text，用明确标记指向 sources；其他命中和截断信息保留。完整证据文件仍保留原搜索结果。
- 保留完整需求、八轮上限、最多三并发、取消/权限检查、逐步骤及引用校验。源码定位策略变化纳入检查点签名，不复用旧策略结果冒充优化后的审查。

## 验证

先补失败测试：共享测试点但无 module 的用例确实减少模型轮次；不同关联不串证据；修改源码失效；同组串行不同组并发；原顺序、失败取消与检查点行为保持；搜索文本压缩可恢复原文。再运行部门完整检查。

使用已有真实记录做只读统计或受控回放，标明未调用真实模型；不将测试替身的轮次节省外推为真实吞吐或业务质量。
