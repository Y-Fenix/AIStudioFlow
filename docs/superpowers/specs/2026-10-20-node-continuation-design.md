# 节点间自动继续开关设计

日期：2026-10-20。状态：用户已确认，功能已实现；验证及服务更新记录见 `docs/studio-platform-acceptance.md`。

## 需求与已核实的现状

用户要求在部门首页节点卡片之间、工作区顶部节点之间增加开关，控制是否执行下一步。

- `web/studio.js` 的 `departmentHome()` 渲染首页节点卡片；`departmentPage()` 渲染普通部门节点条，测试固定节点嵌入 `testing.html`。
- `web/app.js` 渲染测试节点条，目前箭头只用于展示。
- `server/store.py` 的 `Store.decide()` 通过既有证据门禁后推进测试阶段，但不自动启动下一阶段任务。
- `server/studio_workspaces.py` 的 `Workspaces.decide()` 只确认或退回当前交付物。普通部门执行队列也是单节点执行；不能仅增加一个开关就宣称链路自动化已经实现。
- 项目迭代版本仍处于设计待确认阶段，不能假定已有版本存储和 API。

## 方案与推荐

1. 推荐：每条节点连线设置“自动继续”开关。关闭时在当前节点结束后停下，开启时在条件齐备后尝试执行下一步。手动工作仍由原权限和证据门禁控制。
2. 硬禁止下一节点：关闭后连手动操作也禁止。会把流程偏好变成新的访问门禁，不作为默认解释。
3. 全部门单一自动运行开关：不能分别控制每个相邻节点，不符合截图。

本设计采用用户已确认的方案1。

## 界面

- 两处均在节点之间展示紧凑的方向箭头和开关；不放进已有节点按钮内部，避免点击开关同时进入节点。末节点不显示向后开关。
- 标题为“自动继续”，关闭显示“手动继续”，开启显示“自动继续”；悬停和键盘聚焦说明完整行为。颜色服从当前部门和主题，不能只靠颜色表达状态。
- 首页和工作区读取同一份服务端配置，修改后刷新仍保留；保存失败还原并显示真实错误。
- 使用可键盘操作的 switch，提供开关状态和起止节点名称。窄屏保证可点击，不覆盖节点标题。
- 无配置权限时显示只读状态和说明，不能因隐藏按钮省略服务端校验。

## 行为边界

- 默认全部关闭，保持旧流程不自动执行；关闭不是删除或跳过下一节点。
- 开启表示允许自动衔接，不表示已执行、已通过或已审核。节点产物需要人工确认时，先等人工确认，不能由开关代为批准。
- 当前节点成功且已完成所需人工确认后，开关开启、下一节点真实执行器已接通、资料与授权齐全时才可排队。关闭时显示“已完成，等待手动继续”，不自动执行下一节点。
- 用户仍可查看后续节点；手动进入或运行依旧检查原有前置证据，不用此开关代替权限或业务依赖。
- 缺少分支、需求、映射、Skill、执行器或授权时停止并说明缺项，不假装运行成功。需要人工输入的节点停在待操作。
- 测试节点仍是静态代码检查，不启动 Unity。用例范围确认、归因确认、筛选决策、缺陷发布和回归结论保留原有门禁。
- 开关不授权发布 Bug、修改飞书状态、Git 或其他外部写操作；这些仍需原有明确确认。
- 运行中关闭开关不取消当前任务，只阻止尚未派发的下一任务；已经排队或运行的任务使用现有取消机制。
- 打开一个已完成节点的开关只保存配置，不补跑历史或立即执行下一步。实际衔接只由新的完成/人工确认事件触发。
- 错误、中断、取消、证据失效和结果过期不会继续；不自动重试。

## 作用范围、兼容与实现约束

- 公共平台负责配置、权限、调度和公共 UI；部门模块继续通过公共契约接入。覆盖五部门的节点连接，不让各部门自行写数据库或绕过审核。
- 按当前真实项目、部门和起止稳定节点 ID 保存；不按数组位置保存、不改已有节点 ID、权限含义或 revision 含义。旧数据无配置时解释为关闭。
- 对同项目、同部门、当前有效的相邻节点校验连接；重排产生的新连接默认关闭。节点归档后涉及连接不可执行，不能自动跨过测试必需阶段。
- 测试展示排序不是证据执行顺序。非合法证据依赖的相邻展示连接应禁用并解释原因，不能通过开关重新编排原六阶段。
- 修改配置复用来源节点 `node.edit` 检查并验证目标可见；执行每次另查真实操作者的 `view/edit/execute` 和既有门禁。审批仍查 `approve`。开关不授予任一权限。
- 配置保存使用独立修订号检查冲突，记录真实操作者、起止节点和状态；项目切换后的迟到响应不能影响新页面。
- 调度由持久化服务端完成，页面关闭也不会丢失；同一完成/确认事件和连接只能派发一次。完成事件落库与续接意图持久化须原子处理，重复回调和刷新不能重复排队。
- Worker 派发前重查开关、授权、版本/批次修订和证据；目标不可执行则记待操作原因，不无限循环尝试。
- 操作日志分别记录开关修改、自动衔接和停止原因；不把导航或开关开启记录成执行成功。
- 若随后批准项目迭代版本设计，连接配置纳入版本独立范围并按该迁移方案承接；本次不擅自实施尚未确认的版本改造。

## 验收

1. 先补失败测试，验证默认关闭、保存和重载、项目/部门隔离、越权和修订冲突，再实现。
2. 验证开启且前提满足才排队一次；关闭、失败、取消、缺资料、缺执行器、撤权、过时结果和重排非法依赖均不自动执行。
3. 人工审核仍暂停；发布 Bug 和修改远端状态不被自动触发。测试六步证据门禁保持。
4. 关闭运行中连接、重复完成事件、并发确认、服务恢复、跨项目迟到响应有真实临时数据库测试。
5. 浏览器验证两处状态同步、点击不误导航、键盘操作、刷新持久化、三主题和窄屏。
6. 使用隔离数据和执行器替身验证调度，不宣称其他部门真实工具已接通。预览服务更新前检查活动队列、备份，不打断用户任务。
