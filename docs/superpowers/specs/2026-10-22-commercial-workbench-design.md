# StudioFlow 商业工作台：四部门与自定义流程

日期：2026-10-22。状态：按用户挂机委托采用推荐方案并执行，不追加确认；外部写入与新增权限留待审批。

## 现状与产品价值

代码检查发现产品、设计、开发 manifest.execution.adapter 均为 manual，对应 adapter.py 直接抛出未接入异常。测试已有静态审查队列；自定义流可调用模型与部门执行器，但依赖部门真实接入。仅美化这些页面无法形成可用产品。

目标用户是小型游戏工作室及部门负责人。核心价值是把团队方法固定为 Skill，把需求、专业交付、证据与决策连起来，减少重复整理及上下文丢失。相对飞书/企业微信，本平台应提供有业务契约的执行、冻结版本、失败恢复和交付追溯；协作软件继续负责消息与文档。不声称已有付费转化、节省时长或效果提升数据。

## 推荐方案及取舍

采用“现有公共壳 + 部门独立执行器 + 通用交付质量契约”。保持 ATELIER 与另两套主题、稳定节点 ID、现有登录/授权/队列；不重写成新的低代码系统。纯 UI 包装不能解决执行缺口；无限制工具代理会扩大权限与失败面，均不采用。

平台维护者统一扩展公开契约，部门只维护职责模板与 adapter。用户本次授权覆盖整个平台维护，不将部门实现混入公共壳。

## 验收需求

1. **真实 AI 执行**：产品、设计、开发各四个默认节点调用当前启用的模型与实际 Skill；禁止空输入调用。保留原队列、版本与撤权检查；成功后仍待审核。
2. **部门质量契约**：每节点明确输入要求、必备输出段落、证据规则、风险与下一步。返回结构化段落，由平台生成可导出的 Markdown；空段落、未知/重复段落、错误证据引用不能保存为成功。结构错误可做至多一次定向修正，不能无限循环或暗换模型。
3. **诚实交付**：本期新增执行器做基于用户资料的分析、规格及代码建议。无联网资料时不声称完成实时市场调查；无包体工具不声称反编译；设计规格不冒充生图/Figma 成品；代码建议不冒充源码已修改或编译通过。每次交付明确限制。真实工具接入另列审批。
4. **自定义复用**：引用产品/设计/开发节点时调用同一执行器；独立 AI 积木输出保留依据及风险，空交付不能完成。冻结 Skill 和运行资料，保持审核门禁与重试隔离。
5. **专业工作区**：部门节点采用紧凑 Skill 工具菜单、输入/交付清晰分区、可读预览、常驻保存/执行栏。桌面不平铺所有工具；窄屏、三主题和键盘均可用。
6. **运行准备与结果**：展示输入、Skill、执行器、编辑/执行权限及未保存修改；失败提示下一步。结果展示实际证据、缺口和检查项，不给未经校准的质量分数或修复概率。
7. **交接效率**：从已确认上游导入时可预览来源、修订及正文，明确为副本；不得自动覆盖未保存内容。保存、运行、审核和重绘不丢草稿、不重复提交。
8. **测试专属流程**：维持逐用例静态检测、原自动决策范围、内部一因一单、人工发布；不启动 Unity。运行完整测试链回归，不以通用文本节点替换测试证据。
9. **运营与商业化基础**：首页显示当前项目真实进度/待决策/执行能力，提供推荐下一步与明确空状态；维护可复用的游戏版本示例及入门资料，不向用户数据库自动插入演示成功记录。先以工作室付费部署与方法包服务验证需求，计费/支付/订阅不在本轮接入。
10. **交付证明**：临时数据库验证十二节点、自定义串联及测试链；验证权限、冲突、空输入、畸形模型输出和浏览器操作。实际模型烟测和工具替身分开记录；无法验证的真实工具明确列为未完成，不能用绿测试替代业务证据。

## 架构及兼容

公开 `server.core.integrations.generate_document(context, contract)`，委托独立 `server/core/deliverables.py` 校验及渲染；沿用 `{deliverable,evidence,gaps}`，可附加只读 quality 检查报告，不改持久化字段含义。部门在自己的 adapter.py 选择稳定节点契约。通用工作区 UI 增强由平台维护者集中完成，部门不越界改壳。自定义运行沿用现有不可变快照，不跳过人工步骤。

新增只读报告不是事实核验：引用仅证明文本来自输入，资料真实性与结论因果仍待专业评审。Skill 中的工具调用说明不会授予工具权限。

## 权限待审与上线

不授权新成员、不修改现有权限规则，不执行 Git 拉取/提交/推送，不改 Figma，不发布飞书 Bug、不自动上传公区、不写用户游戏源码。需要上述能力时记录用途、最小权限和验收方法给用户明天审查。测试使用隔离数据，不中断现有真实队列；发布新服务版本前检查在途任务并保留回退方式。

## 追加：通用节点运行可观测性

2026-10-23：真实模型烟测出现流停滞与传输重试，现有通用部门队列/自定义运行缺少模型进度。给 `department_jobs`、`block_runs` 各增加可空 JSON `progress` 列，旧记录为空，不改变原状态、revision、结果或权限含义。查询仍走原节点/流程权限；进度更新不递增业务版本，不触发通知，不重试业务执行。只存固定枚举与有界数值，不存请求正文、错误原文、URL、密钥或用户输入。自定义运行按 claim revision 限制迟到更新，换步骤清空旧请求数据。UI 区分最近有效响应和进度采样时间，明确重试，不能把心跳或部分字符当作成功。
