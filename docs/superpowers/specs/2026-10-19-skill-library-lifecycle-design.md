# Skill 工作台、版本与回收站设计（已确认）

日期：2026-10-19。对应第 11 项；本文不代表功能已实现。

## 推荐范围

继续以“项目 → 部门 → 节点”定位 Skill。工作台是各节点实际规则的管理入口，避免另做一个与执行规则无关的文件列表。每张卡片可打开详情、导入替换、导出；详情有描述、正文、上传者、北京时间更新时间、更新说明和版本历史，可查看及导出历史版本。

默认规则标记来源为“内置”或“本机默认”，上传者显示“系统默认”；旧导入记录没有操作者信息时显示“未记录”，不根据当前用户反推。新导入记录真实登录用户和服务器时间，并要求填写更新说明。所有版本关联稳定节点 ID，重排不会串数据。

测试部门的工作台规则作为后续新批次的项目默认规则；已存在批次保留自己的 Skill 和版本，避免改一次工作台规则就改写正在检测的任务。批次中的后续导入依旧独立保存，并记录到相应批次的历史。

## 方案取舍

推荐“直接管理实际节点 Skill + 不可变版本历史”。只做上传附件库容易出现页面显示一份、执行使用另一份的问题；增加独立公共 Skill 市场会引入发布、订阅和跨项目复制语义，暂不纳入本次。

## 删除与回收站

- 删除是移入回收站，保留文件、版本、原节点、删除人、删除时间和到期时间；回收站提供恢复、导出及立即永久删除。
- 移入回收站、恢复、永久删除均要求管理员身份及对应范围权限；普通 Skill 编辑/导入权限不能删除。管理员包括平台管理员及当前工作室/项目有权限管理职责的负责人，不能越项目操作。
- 明确二次确认永久删除；活动任务引用当前 Skill 时阻止删除。已完成任务的结果、所用 Skill 哈希和审计记录保留，不声称删除 Skill 就清除了已完成测试的证据。
- 删除后节点显示“未配置 Skill”，禁止依赖该规则启动新 AI 任务；不会悄悄恢复默认规则。管理员可恢复回收站版本，或明确重新导入/恢复内置默认。已创建批次的独立快照仍保留。
- 自删除时间起满 30×24 小时自动永久删除回收站正文与版本；服务启动和定期清理均执行同一事务逻辑。服务停机时不能执行，到下次启动补清理。审计只保留动作和摘要，不保留已清除正文。
- 自动清理不依赖登录用户，手动永久删除必须服务端校验管理员权限；不能只隐藏按钮。重复删除、恢复已过期数据和并发更新明确拒绝。

## 实现边界

公共层增加 Skill 生命周期与版本服务、持久化表、管理员校验、到期清理和审计。现有工作区导入、测试批次导入与工作台操作共用记录接口；模型执行仍读取对应节点/批次的当前版本快照，不执行上传 Markdown 中的脚本。

仅支持当前单 Markdown 规则格式；脚本与附件不凭空补齐，不把这次功能称为完整 Skill 包分发。部门插件不得直写版本或回收站表。

## 验收

真实 HTTP 与临时数据库验证导入、详情、版本、导出一致，旧数据未知字段如实展示；项目隔离、普通用户删除拒绝、管理员范围、撤权、活动任务保护、软删后执行拒绝、恢复、永久删除以及 30 天清理边界均有测试。时间测试通过可控时钟推进，不实际等待 30 天。

浏览器验证卡片详情弹窗、历史版本、更新说明、导入导出、回收站、删除二次确认和 ESC。使用明确样例，不调用模型或修改飞书。
