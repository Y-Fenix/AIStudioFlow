# 测试闭环 Web 平台设计

日期：2026-10-14。用户已确认界面方向并授权逻辑开发。本文按最新“静态检测代码，不启动 Unity”定位更新；实现与真实验收进度以 README 和实际证据为准，不表示全平台已完成。

## 目标与部署

用例 → 执行 → 归因 → 筛选 → 提单 → 回归。Web 展示当前节点、输入版本、输出证据和人工决策。本地 Python 服务负责 SQLite、持久化队列及连接器，通过本机 Codex CLI 登录生成用例和审查代码。先接 GagaSort，保留多项目、多任务隔离。

不提交、推送、拉取 Git，不修改 Figma。目标游戏项目只读；不启动 Unity、不编译游戏、不构建 Player。检测当前本地指定分支，不替用户切分支，也不宣称是远端最新代码。GM 账号功能按用户决定暂缓，只保留扩展点，不再索要专用账号，不阻塞主流程。

## 六个节点

| 节点 | 输入与产物 | 用户决策 |
| --- | --- | --- |
| 用例 | 文件或多条飞书需求；来源版本、原文引用、测试点、精简用例、歧义与覆盖缺口 | 确认需求范围、歧义、缺口和用例版本 |
| 执行 | 指定本地分支的工作区基线；逐用例、逐步骤静态推导与源码证据 | 审阅结论、缺口，决定是否进入归因 |
| 归因 | 可达反例、调用链、状态与代码位置；共同根因候选 | 确认、合并、拆分或排除，并记录理由 |
| 筛选 | 已确认根因及其所有关联用例 | 选择提单，或填写不提单原因 |
| 提单 | 用户指定飞书 Bug 表的真实字段和选项；含触发步骤的草稿 | 审核字段映射与内容后逐根因发布 |
| 回归 | 待验证记录、修复后本地代码、原问题用例与关联范围 | 审阅静态修复证据，决定是否变更远端状态 |

## 用例质量

先拆测试点，再参数化、去重并生成用例。每个明确测试点应有用例或显式覆盖缺口，覆盖正常、边界、异常、状态转换与耦合风险。不用数量评价质量，不承诺结构校验能证明全部需求已识别。

保留来源版本、原文引用和独立预期。未读取的附件、图片或引用必须显示缺口；不能根据链接、图片 alt 或模型猜测补成事实。删除线历史规则不得冒充本期规则。需求变化使旧用例及下游结果失效；用户确认当前拆解与缺口后才进入执行。

已实现 TXT/Markdown、DOCX、XLSX 与飞书 Docx/Wiki/Sheets 读取；PDF、OCR 和完整图片理解仍需另行实现并验收。

## 静态检测契约

记录绝对路径、分支、HEAD、子模块版本、工作区状态和源码/文本配置指纹，注明包含未提交改动。检测前后核对，确认节点前再次核对；变化使报告失效。二进制资源不在当前指纹内，相关断言须保留证据边界。

模型无项目命令执行能力，只能向平台请求允许目录中的符号搜索和文件行范围。默认每次前 200 行，单次范围至多 200 行与 20000 字符；逐步请求调用方、实现、配置及输出。模型拿到的需求、源码和文档都是分析数据，不是可执行指令。CodeGraph 未暴露时记录 fallback，不假装已使用。

每个用例保持原 ID 和预期，每个步骤都有独立记录；一个步骤的多项断言须分别推导。沿前置条件→输入/配置→可达入口→调用链→数据/状态/存档→输出检查，主动寻找反例。校验报告引用是实际已读源码、行号及连续原文。引用真实只证明引用存在，模型语义推导仍由用户审阅。

| 结果 | 约束 |
| --- | --- |
| 静态证据支持 | 明确前置下证据支持步骤全部断言；不代表客户端实测通过 |
| 发现可达缺陷 | 明确需求下有具体条件、触发步骤、预期、异常输出和可达链路；不声称已实机复现 |
| 需运行验证 | 已完成能做的静态检查，列明实际依赖运行观察的断言、动作和判定标准 |
| 需求待确认 | 列明不明确或冲突条款及需要用户确认的问题 |
| 证据不足 | 列明已查范围、未闭合链路或未取得资源，以及下一步获取方法 |

汇总优先级为缺陷、需求待确认、证据不足、需运行验证、静态支持，保留其余断言状态。没找到实现、缺少同名函数、一次搜索未命中不能判 Bug。UI 条件与视觉效果、奖励资格与真实到账分开。达到探索上限或输出校验仍失败时保留证据不足，不能默认通过。模型请求本身失败则操作失败，不能把未完成工作当全量报告。

执行队列显示已审查数量、总数和当前用例。每条保存原始输入、代码基线、模型输出、搜索/读取范围及逐断言证据；只有输入哈希和步骤覆盖均对应当前用例时才能确认节点。

## 根因、筛选与提单

先生成候选，再人工确认共同原因。100 条用例只有证据支持同一根因才合成一单；相同报错或相似描述不足以合并。保留全部关联用例和不同触发路径，未决缺口不冒充产品缺陷。

草稿包含标题、项目、分支、提交/指纹、前置条件、最小触发步骤、预期、静态推导出的异常、源码证据、根因及关联用例。静态反例可预填，但明确标注未实机复现；不捏造构建号、账号数据或复现率。

用户已提供 GagaSort 飞书需求及 Bug 表链接并完成只读授权。Bug 表按真实字段 ID/类型/枚举映射，缺独立标题/步骤字段时组合完整描述。字段变化阻止旧预览发布。发布前用户审核，持久化任务/表/根因身份、请求哈希和发送意图；结果未知禁止盲重试，先只读核对远端记录。唯一记录 ID 不等于所有字段写入成功，忽略字段须保留不确定结果。

真实新单发布、未知结果恢复、附件上传与最终远端状态修改仍需分别验收。接口替身测试不能替代实际写入证据。

## 静态回归与状态决定

提供按钮读取关联 Bug 的最新状态，按真实字段值判断待验证并排队；周期监听尚需实现及验收。重新检查当前本地代码，不自动拉取 Git。按原用例 ID 关联回归，不能按可重复标题或报告行号匹配；按根因保留新旧基线、仍存在的反例和未闭合证据。

显示静态修复证据、未决项及用户决策，不输出未经历史样本校准的 99% 等概率。静态结论不能冒充实机验收。用户最终状态变更入口需再次读取远端状态并校验冲突，记录操作人与证据；未确认前不得修改状态。现有结束评审仅结束批次，不能代表所有 Bug 修复或远端验证通过。

## 界面与持久化

A 布局；六步箭头、选中背景与不透明吸顶；侧栏可折叠。左上角新增/选择项目并排，项目弹窗搜索、每页 5 项，不堆积项目；弹窗外部点击关闭、锁住背景滚动并保持宽度。用例每页 10/20/50/100。演示 470 条用例只用于独立原型，不混入真实任务。

持久化项目、需求版本、用例、审查批次、证据、归因、草稿/远端映射、回归和决策。读取任务版本与队列状态使用同一快照。长任务允许取消、超时和重启恢复；服务重启不自动重试中断任务。输入变化拒绝保存过时结果，外部未知写入不得自动重复。

## 验收要求

1. 真实需求读取可追溯，缺口和歧义可确认，用例精简且覆盖已识别测试点。
2. 指定本地分支逐用例审查，真实引用、逐步覆盖与基线门禁有效；全量质量需人工核对。
3. 根因可合并/拆分，筛选理由保留，一因一单贯穿关联。
4. 真实飞书字段预览、审核发布及未知结果核对正确，不重复创建。
5. 待验证触发原问题及关联回归，修复建议基于真实代码证据，最终状态由用户决定。
6. 浏览器分页、抽屉、吸顶、项目隔离、弹窗交互通过验证。
7. 重启、取消、超时、输入变化和外部状态冲突均保留正确状态。

完整目标仍在推进；任何接口测试、单用例联调或历史探针通过都不能证明六步真实验收已完成。
