# 项目节点管理设计（待用户确认）

日期：2026-10-19。对应新增第 10 项需求；本文是方案，不代表功能已实现。

## 目标与当前缺口

五个部门都支持在当前项目新增、删除和调整节点顺序；管理员可以分别向个人或部门下发、撤回这些操作权限。

当前节点从部门 manifest 静态加载，节点键使用 `department:index`。界面、授权、Skill、执行队列均依赖这些键。直接删除数组元素或重排 manifest 会导致旧节点关联错误，不能这样实现。测试六节点还包含固定阶段和提单、回归门禁，不能把卡片排序直接当成执行链重排。

## 方案比较

| 方案 | 结果与代价 |
| --- | --- |
| 只修改 manifest 数组 | 开发量小，但会改变旧节点含义，且无法支持按项目授权，不采用。 |
| 项目节点注册表 + 稳定 ID + 工作流版本 | 推荐。项目独立配置，保留存量 ID；顺序、删除状态和内容分开保存，需要迁移现有消费者。 |
| 直接做通用可视化编排引擎 | 支持任意分支与依赖，但超出本次增删排序范围，暂不采用。 |

## 推荐行为

1. 部门首页节点标题右侧增加“管理节点”。没有任何节点管理权限时不展示；按钮显隐之外，所有写请求均由服务器检查权限。
2. 管理面板展示有序节点列表，支持新增、上移、下移和删除；可补拖拽，但上移/下移必须可用。修改集中保存，包含当前配置版本；多用户冲突要求重新加载，不覆盖他人修改。
3. 新增填写名称、用途、输入、交付物和人工验收条件，提供可导入、导出的默认 Skill。新增节点默认人工处理；没有已注册执行器时不显示为可自动执行。
4. 删除采用归档：从当前项目活动节点列表移除，保留历史产物、Skill、审计及原权限坐标。确认时显示受影响内容；运行中或排队任务涉及该节点时拒绝删除。新增同名节点获得新 ID，绝不复用已删除 ID。
5. 顺序按项目、部门保存，只影响该项目的节点展示、下一节点导航及新建流程的计划顺序。不得变更已有记录所属节点。
6. 原批次保留创建时的节点定义快照，不能因管理员后来修改配置而变成另一个流程。新配置只用于后续批次。

## 测试部门兼容规则（需特别确认）

测试部门也提供增删排序入口，但原有六个业务节点的证据门禁必须保留：用例确认之后才能做逐用例静态检测，有检测依据才能归因、筛选、提单及回归。新增节点默认走公共人工工作区，不凭空生成专用执行器。

推荐允许自由调整展示和导航顺序，实际执行业务操作仍检查原有依赖。删除必需节点不会自动跳过证据校验；新建测试批次时提示缺失依赖并阻止启动对应自动链路。已有测试批次使用原六节点快照继续完成。

如果希望“调整顺序”同时任意改变测试业务依赖，必须另做执行引擎与门禁迁移；不能仅靠界面卡片移动实现。这是本方案需要用户明确确认的主要行为。

## 数据与代码边界

- 公共平台新增项目节点注册服务，维护稳定 ID、部门、排序、归档状态、定义版本及默认 Skill；持久化使用增量迁移。部门 manifest 是初始模板，不在网页操作中改写仓库文件。
- 存量 `product:0`、`testing:0` 等 ID 原样保留；新增节点使用不可复用的随机 ID。所有授权、工作区、执行任务和 Skill 引用稳定 ID，不能根据当前数组位置推算。
- 对旧工作区、任务、队列和权限保持兼容；迁移可重复执行。历史记录不因归档节点而被丢弃或页面报错。
- 新 API 位于当前工作室/项目范围下，读取返回配置版本；保存使用事务与版本比较。对无效部门、重复 ID、非法顺序、跨项目节点、超长输入和活动任务进行拒绝。
- 部门插件通过公共上下文获得节点定义，不能直接写节点表；公共服务继续负责权限、版本和操作日志。

## 权限

分别定义 `node.create`、`node.delete`、`node.reorder`。第三项需要在现有动作枚举中增加 `reorder`，不能借用普通编辑权。Skill 导入/导出继续独立授权。

平台管理员默认可管理；其他角色包括部门负责人不因已有 `node.edit` 自动获得这三项权限。后台可指定工作室、项目、部门范围，授权给某个人或该部门所有成员；删除还可缩小到单个节点，新增/整组排序要求部门范围。明确拒绝优先，撤权后下一次请求立即生效。

保存混合变更逐项检查所需权限：只有排序权的人不能夹带新增或删除。授权管理者不得超出自己的组织范围下发权限。

审计保存操作者、北京时间展示所需时间、项目/部门、配置前后版本及新增、归档、排序信息；不把 Skill 正文或账号凭据写入操作日志。

## 验收条件

- 五部门新增、归档、排序及刷新后持久化；两个项目配置独立。
- 已有 Skill、授权、产物和日志在排序后仍对应原节点；新旧批次使用各自定义版本。
- 单独授权、部门授权、拒绝、撤权、越权、混合变更和并发版本冲突均有服务端测试。
- 普通编辑权无法增删排序；无权用户直接调用 API 仍被拒绝。
- 活动任务阻止删除；归档节点历史可追溯；新节点无执行器时明确为人工模式。
- 测试六节点原有静态检测、合并提单和回归证据门禁回归通过，不因重排/删除绕过。
- 浏览器实测新增、上移下移、删除确认、ESC、窄屏及权限撤回后的行为。
