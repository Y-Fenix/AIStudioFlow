# 测试工作区操作布局精简

日期：2026-10-22
状态：用户已确认，已实现并完成隔离回归验证；见 [验收记录](../../qa-workspace-actions-acceptance.md)。

## 问题与范围

测试节点的 `.footeraction` 位于全部节点内容之后，长评审列表导致主要操作难以到达。工作区标题栏同时平铺五个 Skill 操作，长 Skill 名称挤压按钮并引起换行。六个测试节点采用同一布局调整，不修改稳定节点 ID、业务门禁、任务数据或权限含义。

## 方案比较

1. 推荐：主内容列底部常驻操作栏，顶部 Skill 次要操作折叠菜单。主要操作始终可达，列表仍可完整查看。
2. 仅在顶部复制底部按钮：改动较小，但重复按钮继续增加拥挤程度，长内容中途仍不便操作。
3. 全部确认项改成逐页向导：缩短单页，但增加审核步骤，改变现有评审方式，本次不采用。

## 底部常驻操作栏

在当前工作区进入视口后，操作栏保持在可见工作区底部；仅覆盖主内容列宽度，不覆盖操作日志或左侧导航。独立测试页面与嵌入测试页面都使用各自正确的滚动视口定位，避免外层页面与 iframe 双滚动造成错位。

排列：左侧显示当前节点与任务版本；右侧显示「更多操作」「保存评审」（仅范围评审存在可保存内容时）和主按钮「确认当前节点」。回归节点主按钮沿用「结束本次回归评审」。保存复用现有保存逻辑和权限，不新增虚假保存能力。

「更多操作」中放置「发布到项目公区」（仅已有发布入口的嵌入环境）、「重置当前节点」和「取消任务」。危险操作与其他条目分隔，保留原有确认与权限检查。运行中、已结束和非当前节点沿用实际业务限制；不满足条件时提供具体原因，不允许按钮绕过服务端审核。

操作栏采用当前主题的不透明表面色、细分隔线和轻微阴影。内容预留足够底部空间；最后一条确认项、文本输入及键盘焦点不能被遮挡。短页面不产生多余悬浮条或重复按钮。保存和提交期间拦截重复点击，失败保留编辑内容。

## 精简 Skill 标题栏

桌面排列：「节点工作区 / 状态」＋「默认或当前 Skill：简短名称」＋「选择 Skill」＋「Skill 工具 ▾」。长名称单行省略，悬停可查看完整名称，点击沿用 Skill 详情。

「Skill 工具」依次包含「在 Codex 使用」「检查 Skill」「导入 Skill」「导出 Skill」。根据现有权限与连接条件隐藏或禁用，并显示原因。禁止简单移动 DOM 后遗漏原有权限控制。

常规桌面宽度下保持单行，不再让某个按钮单独掉到下一行。窄屏允许明确的两层布局：第一层标题与状态，第二层 Skill 名称与两个入口；不靠随机换行布局。

菜单支持点击外部关闭、Escape 关闭、键盘操作和关闭后焦点恢复；打开方向根据可用空间调整，不能被面板边界裁剪。后台轮询不能持续关闭菜单、重置滚动或吞掉未保存编辑。

## 实现边界与验收

主要修改测试兼容前端 `web/app.js`、`web/styles.css` 和必要的 `web/testing-themes.css`，不改业务 API 和执行链路，不重启正在运行真实任务的服务。

先补预期行为失败测试，再实现。浏览器使用隔离样例，至少包含 1,200 条评审项和长 Skill 名称；验证列表顶部、中部、底部主要操作可达，最后一条内容可见，长名称无按钮意外换行，菜单的点击外部与 Escape 关闭有效，禁用状态及权限保持，后台更新不丢输入。覆盖嵌入/独立页面、三种主题和窄屏，运行测试部门规定的检查。测试不调用真实模型、Webhook 或公区上传。
