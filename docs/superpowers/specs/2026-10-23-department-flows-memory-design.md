# 部门并行流程与节点记忆

沿用已确认的部门工作台。每个项目/部门提供流程选择器和新建入口，旧工作区显示为“默认流程”，数据不搬移。新流程使用独立 ID，节点 ID 和权限资源保持不变；输入、Skill 快照、交付、审批、日志和执行队列按流程隔离。测试流程绑定独立测试批次，复用现有静态证据链。归档保留历史，有在途任务时拒绝归档。

采用独立流程工作区表的兼容扩展，避免把固定部门节点变为自定义流的人工证据链接。旧自定义流继续使用现有运行引擎。本轮不添加流程内分支/循环。

节点提问按项目/流程/节点（测试按批次/节点）持久化。自动读取本流程已保存的同部门资料；跨部门/其他流程由用户明确关联已确认交付。每次提问和执行重新读取允许访问的来源，记录来源 ID、修订、摘要哈希与截断标记。历史回答提示来源变化，撤权后隐藏涉及来源的回答。只保留有依据的回答，不虚构模型记忆或真实客户端执行。

提问使用持久化后台队列，展示等待、运行、失败状态；服务器重启将运行中的任务标记中断，不自动重放。通用节点执行同时注入有来源的记忆。测试提问可召回同批次需求、相关用例和节点结果；静态检查沿用原需求/用例输入和检查点，不用对话改写测试结论。回答不能审批、发布 Bug 或修改飞书。

后台以有界线程池允许不同流程并行；同流程同节点仅一个在途任务，测试同批次仅一个。进程清理失败不得覆盖模型原始错误，模型可按原重试策略继续。

验证：隔离、真实并发、乐观锁、跨项目拒绝、权限收回、来源更新、重启恢复、测试批次召回、浏览器切换/提问/草稿及既有工作台回归。模型替身与真实服务验证分别记录。
