# 个人工作区与项目公区设计草案

日期：2026-10-22。状态：用户已确认，已实现；部署及验证边界见 [使用说明](../../personal-public-area.md) 与 [验收记录](../../personal-public-area-acceptance.md)。

## 目标与现状

日常在个人工作区导入资料、调试 Skill、运行节点及修改结果。用户自行核对后，显式选择内容发布到项目公区，供获得授权的项目成员查阅和复用。自我确认不是专业质量认证，也不等于负责人审核。

设计前及保留的团队兼容模式并非严格的个人私有工作区：普通节点以 `(project_id,node)` 保存一份工作区；测试批次按项目归属，后台任务的 actor 记录不等于私有内容所有者；自定义流按项目保存。模型配置使用服务端统一配置，而非每个浏览器用户的本机配置。实施后以每人独立安装的个人服务作为隔离边界，未将旧共享数据库改成多账号私有存储。

## 已确认的部署方式

用户已选择：每人本机独立运行，确认后上传到统一的项目公区服务器。

- 本机端：个人数据库、代码仓库访问、资料、Skill、模型配置、任务、检查点和日志都在自己的电脑。读取本机 Codex 登录/中转站配置，或使用自己的 API 配置。日常工作不依赖公区在线；新个人安装默认仅监听回环地址。
- 公区端：统一部署在工作室的 Mac 服务器，负责账号、成员审批、工作室、项目、项目版本、发布内容、附件、权限和操作审计。不读取个人代码仓库，不保存个人模型密钥，不执行个人节点任务。
- 本机端在“项目公区”设置一次服务器地址并登录；局域网先使用同一服务器，远程部署沿用 HTTPS。HTTP 只允许管理员显式启用的受限局域网部署，不默认为任意明文地址开放认证。

这是选择性发布，不做全盘同步、自动双向同步、远程控制或分布式执行。个人电脑或服务器的系统管理员仍可能访问所在机器的磁盘，不宣称新增了操作系统级沙箱或磁盘加密。

## 账号与项目连接

个人本机身份与公区账号分开。首次连接公区注册账号，仍由负责人审批并分配工作室、项目、部门和权限；已有成员直接登录。负责人批准成员资格后，成员每次发布不再逐条送审。

公区服务端确定发布作者与权限，不接受本机传入的作者 ID 作为身份。设备会话可退出和撤销；本机只保存必要凭据，不在日志或上传清单中记录密码与会话密钥。公区账号密码继续使用现有密码哈希机制。

本机项目显式绑定公区的工作室 ID、项目 ID 和目标版本 ID，不凭同名自动匹配，不要求两端数据库 ID 相同。选择公区项目不能覆盖本机项目内容。版本必须属于该项目；没有项目访问权时不能查看其版本与发布列表。服务器管理员管理统一项目目录，个人本机负责人身份不等于公区管理员。

## 页面与使用流程

- 项目内新增“我的工作区 / 项目公区”，默认进入我的工作区；保留部门首页、节点流与自定义流。未连接时公区显示连接入口，不阻挡个人工作。
- 个人区包含自己的需求、输入、Skill 覆盖、工作流配置、执行结果及操作日志；共享的节点定义和内置默认 Skill 可复制使用，但个人调整不修改其他人的配置。
- 节点结果和批次提供“发布到项目公区”。打开预览，选取发布条目，填写标题、目标版本和说明，确认可见范围后发布。
- 默认只选当前交付结果和必要的证据摘要；原始需求、附件、源码正文及 Skill 正文必须显式勾选。私有路径和日志不直接作为公区附件链接。
- 公区按项目、目标版本、部门、节点、作者、类型筛选及分页。展示作者、发布时间、发布版本和结论边界；测试静态结果不改写为实机通过。
- 公区条目可查看、按权限下载和“复制到我的工作区”。复制记录来源条目和版本，不能直接修改作者的私有工作区。

## 发布与版本

发布是冻结快照，不是共享个人工作区的实时引用。发布后个人继续修改，公区原版本不变；“发布新版本”再次预览确认，保留旧版和作者。项目版本与交付物的发布修订分别记录，不能混为一个版本号。

创建预览时冻结本机来源修订和所选内容；点击确认时若来源已改变，要求刷新预览。上传由本机后端发起，浏览器不直接携带公区凭据拼装作者。每次发布绑定幂等操作 ID；超时后先查询同一操作状态，不能重新生成 ID 盲目重传。

用户对自己的内容确认后即可发布，无新增负责人逐条审批。操作仍需既有项目成员资格及明确的公区发布权限；负责人可按部门或指定人授予、撤回，个人内容的存在不自动授予发布权。全自动生成只保存个人结果，不能自动发布到公区。项目公区发布与飞书创建 Bug 是两个不同动作，飞书发布仍人工确认。

作者可在仍有权限时撤下自己的发布，项目管理员可下架公区条目；不允许其他成员原位编辑。撤下后新请求不可读取该内容，保留操作审计；不能收回已下载内容或他人合法复制的副本。被撤下条目的历史引用保留来源标识并显示不可用，不静默改成另一版本。

跨部门衔接只能引用有权访问的公区指定版本，或本人有权使用的个人条目；不自动读取其他人的未发布结果，也不随公区新版自动替换当前输入。

## 上传、离线与冲突

- 传输包为数据清单和显式选择的附件，包含格式版本、来源标识、条目类型、文件大小和 SHA256。发布内容中的证据使用已上传附件或可访问的外部来源；本机绝对路径替换为相对来源说明，不暴露用户名、磁盘目录或私有下载接口。
- 公区先暂存，校验权限、项目版本、清单、大小、文件类型与哈希，通过后一次性提交发布。上传中及失败的暂存包不能被其他成员查看；过期暂存定期清理。附件不能作为服务端脚本执行，拒绝路径穿越、压缩包绕过和超限文件。
- 发布新修订必须携带预期的公区修订；被其他设备更新或撤下时返回冲突，展示差异并由用户重新确认，不覆盖最新内容。权限在最终提交时再检查，上传中途被撤权则拒绝提交。
- 公区离线时可保存本机发布草稿，界面显示“未上传”。恢复联网后不会偷偷发布，用户明确重试。结果不确定显示“待核对”，查询操作状态确认，不能当成功也不能默认再建一条。
- 同一发布操作的网络重试最多产生一个可见修订；下载、复制或复用需用户操作，不启动个人节点任务，不执行附件中的 Skill 或脚本。

## 数据与公共契约提案

此变更由平台维护者实施，部门模块不得自行改核心表或绕过授权。

- 单人本机安装作为个人数据边界，不把所有人的私有工作区搬到中央服务器。本期不增加共享机器上多账号私有运行的承诺，也不把现有项目级存储改名成多租户私有存储。
- 本机普通节点、测试批次及来源/产物、Skill 覆盖、自定义流、运行任务、日志和检查点沿用本机存储；外部连接不能访问这些内部接口。个人模式默认只接受本机访问，现有团队服务的监听设置不自动改变。
- 公区使用独立的发布记录、不可变发布版本和附件清单。发布正文由显式选定内容生成，不提供指向私有完整对象的通用读取链接。浏览公区不授予读取全部原始输入的权限。
- 增量新增公区查看、发布、下载/复用及管理权限，支持工作室—项目—部门—节点授权；既有 node.view/edit 等资源含义不重写。Skill 发布仍检查其来源节点及 Skill 范围授权。公区在列表、详情、附件、搜索、统计、导出及提交时统一检查权限。
- 部门继续使用公共 context 和保存/执行接口。公共平台负责快照导出、选择预览、上传及导入；部门只通过公开的交付物导出契约提供数据，不自行调用上传或读公区数据库。中央公区 API 与本机内部 API 分开，客户端不能通过同步接口远程执行节点。
- 发布连接器、数据清单校验、公区存储及权限、通知分模块维护。优先复用现有账号与项目权限组件，通过独立启动模式或入口部署公区服务；公区模式不启动本机执行队列或公开模型连接配置。
- 个人模式下节点运行默认不发项目群 Webhook，避免未经确认就泄漏摘要；原团队部署通知配置保留。公区发布通知由中央服务器按项目配置发送，仅在提交成功后发送一次，失败不重做发布。个人提醒后续显式配置，不能沿用项目群设置自动启用。

## 存量迁移与验收

先备份再增量迁移，旧任务、稳定 ID、证据及历史发布台账不丢失。当前机器的数据继续留在当前机器，不复制整库到其他成员安装，也不作为公区初始化内容。既有团队部署可继续使用兼容入口，不能突然将共享数据标为个人私有。

新公区仅由负责人建立统一的组织、项目和版本元数据；现有本机项目经显式绑定后才能发布。本机目录、账号、模型配置与公区账号分别保存，不能靠数据库整库复制完成连接。现有数据没有可靠创建者字段时不能凭最后一次运行 actor 认领。旧数据不自动发布、不批量复制给所有成员。实施前后核对当前实际用例数量（本次检查为 933 条）及原始产物哈希。

验收使用两套独立本机数据目录和两个真实公区测试账号：同节点同时修改互不覆盖；未发布内容不出现在中央库、附件、日志、搜索和通知；篡改作者、项目、版本、发布 ID 及附件 ID 不能越权。验证选择性上传、哈希错误、部分上传失败、重复点击、断线后结果核对、过期会话、中途撤权、修订冲突、撤下与复用来源版本；个人修改不改变公区，自动模式不自行发布，公区停机不影响本机保存与任务。个人模式监听、凭据脱敏及旧数据迁移需要实际验证。

两套目录的协议测试不冒充两台 Mac 真机部署验收；模型替身不冒充真实模型运行。分别记录协议、浏览器、实际跨机联调及真实业务执行的验证范围。

实施顺序：先完成个人/公区启动边界和账号项目绑定，再实现最小闭环“节点结果预览 → 上传 → 公区查看 → 复制到个人区”，接着覆盖测试批次、Skill 和自定义工作流的受控导出，最后加入项目提醒、兼容迁移及实际跨机验收。不改变现有节点执行和证据门禁，不把新增公区功能称为现有执行问题已修复。
