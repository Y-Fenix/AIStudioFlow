# StudioFlow 团队框架与主题

目标：单台 Mac 部署，飞书登录登记真实用户，负责人管理授权；公共框架与部门实现分离，测试部门保留现有六节点。

## 界面

- 负责人首页为项目总览；产品、设计、开发、测试、发行增长分别有部门首页，保留顶部主视觉、当前项目待办、节点入口及真实统计。打开节点是另一步，不能用节点编辑器代替部门首页。
- 左侧工作室选择下固定一行“新增项目 / 选择项目”，选择工作室后展示项目选择，支持搜索及每页 5 个；保留顶部项目切换。
- 三种真实可切换主题：深色制作台、浅色专业工作台、紫色创作工作室。主题仅改变展示，不能重置数据或权限。

## 权限

资源层级：工作室 → 项目 → 部门 → 节点 → Skill。主体为指定用户或指定部门成员；允许/拒绝规则可撤销，明确拒绝优先。普通用户没有工作室或项目的创建/删除权；负责人默认管理自己范围，可授权给部门或个人。

服务端每次读取、修改、执行、审批、Skill 导入/导出均检查权限；旧测试 API 也必须经过同一门禁，不能靠隐藏按钮实现权限。更改“首页身份”不改变权限身份。部门成员资格必须由后台维护，不能信任浏览器自报部门。

删除使用归档，保留历史与执行台账；不删除游戏源码、飞书记录或后台进程中的任务。后台有活动任务时拒绝归档。

## 认证与部署

本机模式仅允许回环访问。团队模式要求支持多企业安装授权的飞书应用 Client ID / Secret、固定回调 URL、允许企业列表和负责人身份配置（可显式允许所有企业登记待审批）。网页授权码由服务器换取用户信息；state 单次使用并过期，浏览器绑定，Session Cookie 为 HttpOnly/SameSite，服务器仅存摘要；账号以企业标识 + 应用用户标识唯一绑定，未知用户登记待审批。

负责人由本机管理员明确指定，禁止“第一个注册的人自动成为管理员”。应用密钥仅存在服务器私有文件，API 不回传；运行器凭据属于服务器，不冒充登录用户的飞书业务授权。

## 部门模块

`departments/<id>/manifest.json`：部门、节点、首页、输入输出描述与接入点；`skills/` 保存默认规则。公共目录加载器验证唯一标识及协议版本。部门负责人可以独立修改自己的目录；公共账号/权限/队列/审计保持统一。外部工具通过明确接口适配，Skill 不等于代码插件，不自动执行导入文件。

## 验证

覆盖部门首页、项目入口与隔离；允许/拒绝/撤销/越权/旧 API 旁路；登录 state/过期/企业限制/管理员归属/会话隔离；旧库迁移；各主题桌面与窄屏；原测试全量回归。没有真实飞书应用参数时只验证协议替身，不声称真实登录已验收。

## 工作顺序

1. 界面修复、三个主题和部门首页。
2. 部门模块边界与维护说明。
3. 账号、授权后台、服务端门禁及归档。
4. 飞书 OAuth、Mac 启动配置及真实/替身分开验证。

不提交/拉取 Git，不修改 Figma。飞书应用启用、主题最终选择及真实团队权限验收由用户基于可查看结果决定。
