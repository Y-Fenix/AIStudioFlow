# StudioFlow 节点积木与自定义流

日期：2026-10-22。用户授权按推荐方案直接实施；共享范围明确为工作室 + 部门。实际验收记录见 `docs/node-builder-acceptance.md`。

## 产品行为

普通部门节点可进入“搭建节点”，将资料输入、AI / Skill、检查清单、交付模板、人工审核、工具外链拖入有序画布，编辑属性、重排、预览并保存。提供点击添加、复制、上移和下移作为键盘/触屏替代。默认组合为输入 → AI → 清单 → 模板 → 人工审核。

保存后，重新进入该节点使用已应用的运行工作区；每次运行单独保存输入、逐块结果、证据、缺口和人工操作人。输入及清单可保存填写进度。运行完成后可显式保存为原节点的待审核交付；源蓝图、工作区或 Skill 已变化时拒绝旧交付覆盖，绝不自动批准。

“自定义流”替换发行增长的主导航和项目总览卡片。可拖入当前项目任意可见部门的活动节点，也可直接使用通用积木。顺序执行、传递前序交付，可重复使用同一个节点而不覆盖来源工作区。工作流属于项目，不是新部门；保留原 growth 稳定 ID、默认 Skill 和历史数据兼容。项目默认跨部门自动链到测试结束，不再隐式运行增长。

## 运行语义

| 类型 | 行为 |
| --- | --- |
| 资料输入 | 文本、可选必填；保存草稿，提交后作为后续输入 |
| AI / Skill | 公共模型真实请求 JSON；节点内自动使用当前节点 Skill 快照，流内直接 AI 仅使用本块指令 |
| 检查清单 | 每条勾选可存草稿；全部确认后才继续，不丢失上游交付 |
| 交付模板 | 只替换 `{{input}}` 和 `{{previous}}`，不执行表达式或脚本 |
| 人工审核 | 必须填写依据并具备节点/工作流批准权限；作为运行内检查，原节点批准仍另行操作 |
| 工具入口 | 无凭据 HTTPS 外链；人工确认继续，不宣称 API 已接通 |
| 部门节点 | 有积木则展开快照；无积木但注册真实 adapter 则执行 adapter；否则等待人工交付 |
| 测试固定节点 | 打开原测试工作台，核对当前项目已完成审核的真实批次及对应证据，不冒充静态检测 |

首版是顺序状态机，不含分支、循环、并行和上传可执行脚本。固定测试六节点不可被通用蓝图替换；测试自定义节点可搭建。现有普通节点自动继续仍沿用旧 adapter 队列，不自动转为积木运行；使用自定义流串联积木节点。人工步骤可在未来扩展时升级，但不能绕过原提单及回归证据门禁。

## 数据与版本

公共目录 `server/core/node_blocks/` 按 schema、服务、运行器、注册契约、路由拆分；前端独立于公共壳的 `web/node-builder.js/css`。SQLite 幂等新增 `node_blueprints`、`block_templates`、`block_template_versions`、`custom_flows`、`block_runs`。不重写旧节点 ID 或任务数据。

积木随机稳定 ID 与数组顺序分离。每个组合最多30块、200KB；展开流程最多300步。属性仅接受登记字段和类型；拒绝未知类型、重复 ID、非法变量和凭据 URL。导入 JSON 是数据，不执行 Python/JS/shell/HTML。

保存使用预期 revision，拒绝并发覆盖。节点结构或属性更新使原工作区批准失效；该独立节点存在活动运行时禁止改蓝图。流运行保存展开后的独立快照，源节点后来变更不会漂移历史运行。运行记录固定 Skill 正文/哈希、请求模型/推理强度，以及连接配置指纹；接口不返回模型凭据或快照中的私有 Skill 正文。中转站改变地址或凭据时，下一自动步骤失败，要求新建运行，不暗中换模型。OAuth 会话刷新仍由 Codex 自身管理，平台不冻结 OAuth token。开始入队前再检查来源修订，避免准备快照期间的并发变更。

队列状态：queued → running → waiting_user / queued → completed；异常进入 failed；重启中的执行进入 interrupted，保留前序结果。失败/中断只能手动重试当前步骤；取消通过修订校验防止晚到结果复活。模型取消不保证提供商停止计费，但结果不会保存。单 Mac 工作线程串行执行，不提供多进程队列抢占租约。

## 模板共享

共享范围固定 `(studio_id, department)`，项目限定授权不能成为跨项目模板管理权限。部门在任意项目的成员可读取同工作室本部门模板，显式拒绝优先。新增、编辑、归档单独授权；工作室负责人可管理。

模板分 node / flow 两类，不可变版本保留真实作者和创建时间。节点模式不能导入含节点引用的 flow 模板。流程可选择模板所属部门。模板只复制配置，不自动包含项目输入、交付、Skill 正文、API Key 或 Webhook。手工写入指令的内容由作者自行核对，平台不声称能识别所有敏感文本。

应用时复制配置并重建块 ID，记录来源模板 ID/部门/版本；源模板升级或归档不改变应用结果。当前版本不做自动升级或差异合并；需要使用新版本时手动添加、检查并保存。JSON 导入导出只交换结构；导入后须显式保存。

## 权限

新增精确资源 `block`（工作室+部门）与 `workflow`（工作室+项目），后台可对指定人或部门授权。所有写入和执行在服务器复核，按钮禁用只是提示。

节点蓝图：view/edit，增加结构额外需 content.create，删除额外需 content.delete；同 ID 改类型视为删除+新增。流程 view/create/edit/delete/execute/approve 各自独立。引用节点运行要求所有来源节点 view/edit/execute 及 skill.view，人工审核另需 approve；运行后保存前再次检查撤权。共享模板保存前先检查读取权限，避免提交后才报越权。

## 部门扩展

部署仓库的 `<PREFIX>_blocks.py` 提供 `<PREFIX>_register_blocks(register)`；注册稳定 `department.type`、展示名、属性字段和真实处理器。支持 text/bool/list/url，使用已有公共 ExecutionContext（输入、Skill、模型、只读且逐次授权的 GM）。模块只在受信任部署目录加载；同进程重复建服务幂等，注册失败回滚本次新类型。网页导入无法登记执行器。

私有积木只用于所属部门节点和模板，跨部门自定义流通过引用节点组合。扩展程序本身是受信任服务器代码，没有运行时沙箱；必须经评审，不得绕过公共权限或自行发布外部记录。示例与 HTTP 契约见 `docs/departments/README.md`。

## 提醒兼容

各来源节点完成、失败和服务中断写入现有通知队列；项目流整体完成也可提醒。遵守工作室/项目/部门/节点原有 Webhook 配置及事件偏好，链接带具体运行 ID。测试只检查入队及链接，不向飞书发送。

## 验收

先失败测试后实现权限、模板版本、未知数据、失败恢复、撤权与过时结果；真实 HTTP/SQLite 队列使用明确模型替身；隔离浏览器完成拖放、属性配置、草稿、发布待审、跨部门流、模板复用及移动端检查。真实模型最小联调另行记录，不把它当业务评测，不向飞书发送验收消息。
