# 测试流程自动决策与执行入口修复

## 问题与范围

1. 范围评审的保存按钮和拆解确认仅在长列表底部，批量处理仍要滚动数百行。
2. 当前“自动继续”仅在人工确认后排队，不会自动评审、确认归因或准备完整内部交付。
3. 当前任务绑定的是旧代码提交及子模块，直接静态检测因此在模型调用前失败。保留基线检查，用明确的更新入口解决，不放宽证据校验。

## 界面

- 批量操作区增加“保存范围评审”与本次范围确认选项；底部入口保留，同一状态同步，保存时拦截重复提交并显示结果。
- 当前测试批次增加“全自动 / 停止全自动”按钮和运行/暂停原因。默认关闭，按批次保存；与原节点间“自动继续”分开，原手动模式行为不变。
- 执行按钮明确为“更新基线并静态检测 / 继续未完成用例”。一次点击只读检查当前指定分支，代码变化时刷新基线并使下游结果失效，再排队；同一基线保留检查点。分支不同、权限不足、并发版本变化仍拒绝。

## 全自动行为

用户开启即委托当前账号权限内的自动决策。以已识别且具备可执行断言的测试点作为本次静态范围；来源缺口、覆盖缺口及歧义按明确策略记录风险，不把缺口当作覆盖或通过、不伪造“人工已核对”。生成完成后自动保存范围决策并继续静态执行；执行完成后按原覆盖校验继续归因；自动确认有真实源码依据的候选根因、选择提单范围，并按共同根因生成内部草稿。未能归因的失败不能凭空合并或视为通过，保留并暂停说明。所有自动行为记录账号、方式和理由。

默认终点是内部 Bug 草稿。飞书真实发布及远端验证状态仍走现有明确授权；若用户另外选择自动发布，须扩展明确的外部写入范围和失败对账设计，不悄悄扩大本版本范围。回归保留真实状态和新代码条件，不能凭静态缺口生成修复百分比。

缺需求、路径、分支不符、权限撤回、Skill失效、真实执行错误会暂停并说明；不无限重试，不自动重置节点。停止全自动不删除产物；在途只读执行可完成，但不会再自动审核或续接。服务重启后停止自动委托，用户可重新开启，保留原检查点。

## 模块与平台接口

测试部门 `QA_automation.py` 只负责纯数据策略及组装，沿用严格用例、静态覆盖、归因、草稿校验。平台增加按批次持久化的自动委托及串行调度，统一负责身份、范围、修订、在途任务去重、暂停、权限和审计；不能由浏览器驱动后台循环。

新增表保存 task_id、actor、enabled/state、revision、last_task_revision、detail。旧表/节点ID/手动审批默认含义不变。自动确认产物明确标注来源，旧数据按人工路径解释；关闭模式不会回写旧快照。执行新增经授权的“重新检查基线并排队”原子接口；检查和排队均核对版本，任何冲突回滚。

## 验证

先复现：顶部不能保存、旧基线始终执行失败、现有开关不自动决策。新增行为测试覆盖：顶部/底部同步与重复提交、静态基线更新/同基线复用/分支拒绝/并发回滚、完整自动生成到内部草稿、风险未伪装通过、无归因证据暂停、权限撤回、停止、重启、重复轮询不重复排队。跑完整 Python/Node 与真实浏览器；真实模型只读小样本单独注明，不冒充933条已执行完。
