# 个人工作区与项目公区

每个人在自己的 Mac 运行 StudioFlow，使用自己的数据库、代码目录和模型配置。确认结果后，选择内容、预览并上传到统一项目公区。公区保存发布快照，不远程运行节点，不读取个人代码仓库。

## 两端分别启动

命令在各自的 StudioFlow 代码目录运行，需要 Python 3.11 或以上。每台电脑使用自己的数据目录，不复制其他成员的数据库或凭据。

个人 Mac：

```sh
python3 -m server.app --mode personal --host 127.0.0.1 --port 8766 --database data/personal/platform.sqlite
```

首次打开 `http://127.0.0.1:8766/` 设置本机账号。个人模式强制仅监听本机，保留本机节点运行能力，禁止自动排入或发送项目群提醒。隔离边界是每人独立安装，不支持共享机器上的多账号私有运行。

省略 `--database` 时，个人、团队、公区模式分别使用 `data/personal/platform.sqlite`、`data/platform.sqlite`、`data/public-area/platform.sqlite`，不会因切换模式默认共用旧库。本次机器的 8766 仍有旧任务运行，新个人实例暂用 `http://127.0.0.1:8767/`，数据目录为 `data/personal/`；这是独立新安装，需要首次设置账号，旧项目没有自动复制过来。

公区服务器 Mac：

```sh
python3 -m server.app --mode public --host 127.0.0.1 --port 8770 --database data/public-area/platform.sqlite
```

负责人在服务器直接打开 `http://127.0.0.1:8770/` 设置首个账号。公区强制账号密码认证，不开放模型、源码、个人任务或节点执行 API，不启动节点执行队列。默认公区数据库与旧团队数据库分开；仍建议明确填写数据库路径。

先建立公区的工作室、项目和版本，再批准成员。普通成员需要对应项目成员资格，以及独立的 `publication` 权限：`view` 查看，`create` 发布，`export` 下载/复制，`delete` 撤下。可按工作室、项目、部门、节点授权。撤下还要求本人是作者或该范围管理员；其他成员不能修改作者的发布。新建项目版本需要 `project.edit`。发布 Skill 还检查相应 Skill 导出权限。

推荐用 HTTPS 反向代理。认证、Caddy 和 launchd 的通用要求见[Mac 部署说明](mac-team-deployment.md)，但公区启动命令必须保留 `--mode public`、8770 端口及独立数据库。现有部署生成工具面向团队模式，不会自动切换成公区部署。

仅在受信任公司内网使用 HTTP 时：先在公区“权限后台 → 账号登录与部署”填写服务器实际私有 IP 地址（例如 `http://192.168.1.50:8770`），明确启用局域网 HTTP 并保存，再用原命令改为 `--host 0.0.0.0` 重启。个人端连接时也须勾选允许局域网 HTTP。此连接不加密，不能用于公网；示例 IP 必须替换成服务器实际 IP。

## 连接与发布

1. 个人端进入项目的“项目公区”，填写公区站点地址并登录；也可注册公区账号，等待负责人审批。个人账号和公区账号分开，个人端负责人身份不授予公区管理权。
2. 选择公区工作室、项目和版本，保存绑定。绑定使用 ID，不按同名自动合并；项目选择每页 5 个。更换服务器或公区账号后需要重新绑定。
3. 从节点的“发布到项目公区”入口，或公区页选择普通节点结果、测试批次节点、Skill 或自定义流。填写标题和说明。默认不附带原始需求、输入、Skill 正文或附件，需单独选择。
4. 查看冻结预览，核对正文和附件，勾选确认后上传。个人继续修改不会更新已经发布的快照；需要“发布新修订”并再次确认。预览后本机来源改变，必须重新预览。
5. 公区按版本、部门、节点、作者、类型筛选和分页，可查看修订历史。下载/复制要求独立权限。“复制到我的工作区”保存到独立副本列表，保留来源与修订，不覆盖当前节点，不导入运行配置或执行 Skill。需要时手动复用文字。

测试导出只选择当前节点结果字段，保留静态结论边界与相对源码定位，剔除整批任务、执行日志、原始模型输出、代码引用正文及外部 Bug 发布请求。全自动运行不会自动上传公区，飞书创建 Bug 和状态变更仍人工确认。

自定义流导出配置、任务指令及所选的有效 Skill；任务指令本身可能包含私人文本，必须检查预览。流程的部门/节点选择表示公区归属，流程中每个引用节点仍需导出权限。Skill 仅保存单 Markdown 快照，不打包依赖文件、执行器或脚本，不保证可直接迁移运行。

## 断线、会话与撤下

- 公区离线不影响个人节点保存与运行。已创建的上传预览保存在本机，最近 50 条可从草稿列表打开；创建预览前需已有项目绑定。
- 连接超时显示“待核对”，用户重试时使用同一操作 ID，先核对服务端结果，避免重复发布。不自动后台重传。暂存未提交包 24 小时后清理，可在条件仍有效时重新暂存。
- 公区会话有效期 12 小时，过期后重新登录同一账号再重试。连接器不保存账号密码；会话凭据保存在本机数据库，不返回浏览器，必须限制数据目录访问。公区只保存会话哈希。改密、禁用或撤权后按最新身份和权限判定。
- 发布新修订需匹配预期修订；其他设备已更新或条目已撤下时拒绝覆盖。上传最后提交前再检查权限，作者由公区登录身份确定。
- 撤下后详情、历史和附件均不可再通过公区读取，保留审计；已下载内容和本机副本无法追回。已复制副本不会随公区修订或权限改变自动更新或销毁。

## 内容边界与提醒

发布包上限 2 MiB（含 base64 编码与清单），正文上限 1,200,000 字节；最多 10 个附件，每个不超过 700,000 字节。支持 TXT、Markdown、JSON、CSV、PNG、JPEG、PDF、DOCX、XLSX；验证文件名、大小、哈希，不解压执行附件。

正文及 UTF-8 文本附件会隐藏常见格式的绝对路径。它不是通用密钥扫描器，不能保证发现所有目录写法、正文秘密、图片信息或二进制附件元数据。附件不会自动去除内容或元数据，上传前由用户检查。

公区负责人可在“飞书节点提醒”启用“公区发布”。只有发布提交成功才记录一次通知，默认关闭该事件；失败不会重跑节点或重做上传。个人模式不会沿用团队群配置自动发送运行摘要。

## 旧环境与备份

未指定 `--mode` 仍是 `team`，保留原团队服务、数据和通知配置。现有共享实例不会被自动变成个人私有模式。当前机器的旧数据留在原数据库，公区初始只建立组织/项目元数据，不自动上传旧需求、用例、日志或模型配置。

升级前使用 SQLite 一致性备份，或停止服务后备份数据库及同目录私密配置，限制备份访问。不要在两个服务之间共用同一个数据库，也不要将数据库、会话、密钥或用户文件加入 Git。实际验证范围见[验收记录](personal-public-area-acceptance.md)。
