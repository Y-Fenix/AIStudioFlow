# StudioFlow 界面原型

评审问题：工作室作为最外层后，游戏开发全链路如何呈现；项目价值门槛、身份首页和可替换 Skill 是否清楚。

启动：`python3 -m http.server 8767 --bind 127.0.0.1 --directory prototype/studio`

入口：<http://127.0.0.1:8767/?variant=A>

- A：工作室总览；B：全链路；C：决策优先。底部切换或左右方向键切换。
- 五个部门、22 个节点：产品、设计、开发、测试、发行增长。测试六节点沿用当前流程。
- 工作室切换与项目分页选择（每页 5 个）；项目只列在其所属工作室。
- 个人身份决定默认首页，负责人默认进入总览；部门身份默认进入该部门。
- 各节点可查看、导入、导出和恢复 Skill；测试用例与静态检测读取本地用户 Skill 的只读快照，未改写它们；其他节点提供本轮编写的起步规则。
- 数据只保存在浏览器内存；刷新恢复，不连接后端、AI、飞书、GM、Figma、Unity 或本地工程，不执行 Git 操作。
- 各部门工作区和 AI 接入只供评审信息结构。模型检测、竞品包体分析、生图、代码修改、投放和发布未接通，不代表已有执行或商业结果。
- 商业验证区不展示虚构的收入或 ROI；输出重点是预算、证据、成功阈值、停止条件和人工决策。

该原型只用于界面评审。确定信息结构后再讨论持久化、工具权限、模型接入和真实节点能力。
